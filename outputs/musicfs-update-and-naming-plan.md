# 自动更新与命名模板：决策与交付

2026-10-23，dev.23源码实现完成。当前模块与流程以[架构](../docs/architecture/updates-and-naming.md)为准，证据见[离线核对](../docs/verification/updates-and-naming.md)，产物状态见[发行页](../docs/release.md)。本页只保留范围、取舍和实施前估算，不复制当前接口。

## 已确认并实现的范围

- 自动更新支持每天固定时间、每周指定日、自定义间隔和时区；目标明确区分单目录、完整子树和整个来源实例。
- 用户自由编辑文件名模板，自动填充插件可选提供的字段；支持字段插入、条件块、格式选项和预览。
- 来源默认与单目录覆盖独立保存；旧实例继续使用原名，旧周期保留原范围及首次触发点。
- DAV、App挂载和管理页消费同一命名结果；改名不改变来源配置、快照或实际音频身份。

## 关键取舍

| 比较 | 采用方案及理由 |
|---|---|
| 每目录弹出简单周期 / 统一规则 | 上下文打开共用编辑器，规则在现有设置页集中管理；不新增顶层导航 |
| 自制日历 / 现成时间库 | Croner只计算日历时间，持久执行继续归现有刷新队列 |
| 插件配置中拼接 / 核心展示策略 | 插件提供可选事实，Mustache在共享展示层渲染；保留旧插件与音频缓存合同 |
| 仅预设 / 自由模板 | 预设只填入编辑框，用户可继续任意修改；高级格式按需展开 |
| 扫描全来源预览 / 复用已加载目录 | 实例自动选一个继承默认设置的已加载文件目录，显示有限行；避免仅为编辑模板请求平台 |
| 保留位置后缀 / 稳定媒体后缀 | 使用媒体/音质和同曲出现身份，减少无关插入导致的改名；不建立永久别名库 |

完整范围会增加实际清单更新量；通过复用覆盖工作和原冷却机制控制重复请求。首次应用模板仍可能让按路径索引的播放器或rclone重新识别；不含序号的模板可减少后续无关改名。现行边界与消费者差异集中在架构页维护。

## 工作量与ROI

以下为实施前的单人有效开发日估算，已完成的工作不再作为剩余待办。

| 工作包 | 原估算 | ROI |
|---|---:|---|
| 调度、完整范围与持久任务关联 | 1.25—2日 | 高，解决固定时间和整来源更新 |
| 调度编辑与集中管理 | 0.75—1日 | 中高，减少逐目录维护 |
| 命名合同、插件事实、渲染与缓存关联 | 1.25—2日 | 高，支持模板及稳定路径 |
| 模板编辑、预览与简单目录覆盖 | 0.75—1日 | 核心预览高，覆盖与格式选项增量中等 |
| 迁移、集成与文档 | 0.5—1日 | 高，兑现升级与跨入口一致性 |

合计原估4.5—7个有效开发日。依赖、后台领域、界面和文档分别提交；没有新增脚本编程语言、模板目录生成器、定时整库补标签或另一套下载系统。
