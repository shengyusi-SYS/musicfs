# MusicFS 性能与使用体验复评

日期：2026-10-22。基于 dev.11 的现行产品代码、已有验证，以及六位 `module_advisor` 顾问的独立评估；模型均为 `gpt-6-luna / high`。只给出目标、领域和操作边界，没有预设优化技术或候选清单。顾问已分别覆盖目录/持久化、来源/SDK/会话、文件协议/表示、桌面挂载、Worker/生命周期/发行、产品旅程/界面，讨论保存在应用的“模块智囊”分组。

**仍有优化空间，优先级应从“再建缓存”转向减少热路径重建、无变化写盘及不必要的等待。** 不需要重划整个领域，也没有依据重开平台压力、全格式客户端或免费云端验证矩阵。以下是主代理核查后的结论，不是把六份建议取并集。

## 应用场景续评

用户进一步明确按实际用途持续优化：本地播放器经挂载播放、直接DAV、本地/NAS入库、文件名/内嵌资料/网络匹配/音频分析刮削、下载复制和同步。这些视角不自动产生新功能需求。

| 方向 | 场景、依据与选择 | 投入 / ROI / 边界 |
|---|---|---|
| S1 未打开文件的表示稳定性 | **已实现**。网易云冷清单原来每轮scan都给未读歌曲分配新代次，2首离线不变刷新中2首身份/mtime全变。现在按同一媒体和资料描述键复用有期限的预留代次；重刷不延长期限，真正准备后由原ready期限接管 | 小型插件修正，高ROI；有助于增量入库/同步及缓存复用。批量查询/保存合并到原操作，代次索引很小但增加少量行/字节；不宣称原生同步器已实测 |
| S2 纯音频Range的无关资料读取 | **已实现**。正式codec的64B纯音频Range由额外读取43,692B共享封面base64、一次缓存查询降到0B/0次；新codec内部按Range恢复，旧计划保守兼容 | 原估0.25—0.5日，条件性中高ROI；Worker和未命中VFS的seek省缓存搬运，完整下载/标签扫描不因此省图 |
| O9 退出与缓存开关一致 | **已实现**。容量0同样从open开始跟踪准备/流，结束或取消释放，沿用原有忙状态和恢复接收；12项模块/HTTP定向回归通过 | 原估0.25—0.5日，可靠性收益；只修原有计数与流生命周期，不新建退出框架 |
| O6 跨open来源定位 | **已实现**。复核发现清单原已跨调用缓存完整播放版本/定位，读取消费改为只读复用同一有效记录并核对完整原媒体身份。两次新打开SDK2→0，CDN仍2；不续期、不新增定位缓存 | 有界SDK/受控HTTP样本支持。每调用增加一次SQLite/D1读，miss仍回原SDK；收益限有效期，不外推全部播放或免费CPU |
| 新导出/旁置资料/稳定命名模式 | 当前不实施。普通完整GET已能复制带标签文件；容量0可关闭一次性复制的新缓存；顺序文件名属于现合同。暂无具体消费端缺字段或新的命名迁移需求 | 预留填充是已接受取舍；真实大批下载成本、旁置文件兼容需求或路径稳定性要求改变时再比较最小方案，不先建导出系统 |
| 指纹/响度/哈希、外部联网匹配 | 消费者确实需要音频/外部请求的部分不能被清单缓存消除 | 不新增分析或搜配服务；仅消除MusicFS自身重复工作 |

S1保留文件名的序号和重复出现合同，因此换序仍可能改路径；解决的是不变资料的表示身份，不冒称永久路径已解决。资料到期后不能既不重新取得资料、又保证发现平台变化；仍按已有期限换代或使用用户选择的长期保留策略，旧引用字节继续冻结。[局部证据](../docs/verification/performance-local-2026-10-22.md)

## 当前ROI停止决定

上述有证据的高收益改动完成后，剩余方向按实际场景选择，不把理论空间变成新必做功能。

2026-10-23补充少量增删场景：已修正同目录旧索引占用预算，直接DAV共享音频桶登记新键改用文件通知，保留同桶既有节点；App目录失效、完整索引重建和原序号命名保持。11—13ms的离线索引样本支持暂不建设增量索引。逐文件时间回退、改名后的原生路径缓存和不同客户端的范围分别记录在[本轮评估](../docs/verification/partial-directory-update.md)，不承诺所有文件缓存均不受影响。

| 剩余方向 / 场景 | 当前停止理由 | 重开依据 |
|---|---|---|
| 本地/直接DAV重复读取再造缓存 | App与直接DAV已有原生稀疏缓存；本轮已减少身份变化及插件内部多余工作，没有未被覆盖的重复区段证据 | 指定版本、入口、同一最终表示/范围的重复回源计数 |
| 资料到期后仍保持原身份 | 发现外部歌词/封面变化需要重取资料；不能以不变身份偷偷返回新标签。现有期限与0长期保留已表达选择 | 实际周期性重扫成本仍突出，且能接受明确的新鲜度方案，再比较按需复核与表示复用 |
| 保存播放列表/按路径同步的稳定命名 | 序号和重复出现是已确认合同，直接改名会迁移所有现有路径；本轮只保持表示身份 | 明确希望新增稳定路径入口或改变顺序合同，再选择最小迁移方案 |
| 下载复制的紧凑导出 | 普通完整GET已能复制；1MiB预留是已接受取舍，当前无高频整库导出成本证据 | 实际大批复制中填充/存储成为主要成本，再复用精确准备比较，不先建下载管理器 |
| 一次性复制的完整缓存副本 | 原生缓存是可关闭的已有策略，本机挂载已避免同次共享层双写 | 现有开关无法满足明确复制/播放共用工作集，再比较现成rclone能力 |
| 外置歌词/封面、外部搜配与音频分析 | 未有指定客户端缺资料的反馈；外部搜索、指纹/响度/哈希真正需要的音频工作不能靠MusicFS清单消除 | 明确播放器/刮削器的消费缺口或MusicFS自身重复字节证据 |
| O4/O5 页面续步与查询新鲜度 | 租约已防止重复平台执行；目前仅本机控制往返/管理页重取，没有外部播放、复制或入库主成本证据，属于中低优先级 | 管理页面等待成为实际瓶颈，或空step/重复列表量化显示明显成本 |
| O7 数据回收、O8 全部缓存预算汇总 | 永久计划仍服务旧公开引用，不能按TTL删；现有缓存能分别查询/配置，暂无增长量或多缓存体验证据 | 实际行数/字节增长、磁盘压力或用户无法管理预算，再做有界量级核对 |
| O10 M4A头部合并 | 唯一样本6个Range共1,002B且不读mdat，默认源音质通常MP3；准备后计划可复用，不能只凭往返存在判定高收益 | 实际M4A占比与冷准备等待明显，再在已知结构内合并 |
| 扩大批次、预读参数及跨Worker协调 | 已有批量完整性、原生预读及宿主预算证据；无依据扩大请求或添加付费协调服务 | 新实际瓶颈及可复现净收益，保留平台限流与免费预算约束 |

没有据此新增全局队列、格式、联网搜配、旁置文件、分析服务或写回平台。本轮到必要交付物一致后收口；新实际反馈可重开，不能将停止解释为没有任何理论优化空间。

## 实际场景覆盖

| 使用场景 | 现有能力及复评结论 |
|---|---|
| 首次安装、授权、创建实例 | 公开插件合同及独立实例继续保留。地址检查/安装的重复下载确实存在，但低频，不值得为它先造归档暂存服务 |
| 首次进入大歌单 | 已分离清单、准确属性与标签准备。继续保留网易云按需表示，不恢复全库预处理作为默认前置步骤 |
| 重进目录、在多个歌单间切换 | 目录索引存在容量门槛，超过预算会重建；浏览器查询也可复用更明确的短期新鲜度。两者与 rclone 音频片段缓存分别处理 |
| 每天只增加、删除少量歌曲 | 名单仍需确认完整性；已准备文件可复用。没有依据盲目增大批次或实现平台不提供的增量接口 |
| 首次打开一首歌曲 | 已在空余两个名额内重叠歌词和封面；专辑依赖、批量及预算路径保留。该收益与整库刷新速度不同 |
| 播放器首次入库 | 按需准备仍有逐曲成本，预留填充也有传输/存储代价。用户已接受这项取舍，现有消费证据复用，不再为理论兼容性重跑矩阵 |
| 持续播放、seek、切换客户端 | 现有 VFS 复用保留。网易云跨调用重新定位仍有潜在请求减法，但先证明临时地址复用合同，不能直接取消表示核对 |
| 多歌单、多音质与较大目录 | 文件数会超过曲目数；多视图竞争内存以及多挂载占盘是不同成本，配置须按实际宿主和工作集评估 |
| 刷新时继续播放、关闭管理网页 | 持久后台已接线；桌面页面仍主动推进同一任务，可减少重复控制请求，Worker 的页面续步能力继续保留 |
| 弱网、限流、失败后恢复 | 已有冷却、取消、旧成功快照和续步；没有依据再叠一层重试或新队列 |
| 后台重启、退出及缓存关闭 | 已缓存范围可持久复用；缓存禁用时的退出计数与监听器关闭顺序仍值得一次定向核对，不能扩大成系统故障矩阵 |
| 长期运行、定时刷新 | 终态任务与永久标签计划有增长路径。先评估增长量和仍被引用的事实，不能按资料 TTL 删除不可变计划 |
| 免费 Worker、多设备访问 | 需要分别看来源调用、SQL、行数/字节与 CPU；现有计数不是统一成本分数，付费或本地结果也不替代免费证据 |
| 升级插件、升级核心、打包 | 保留精确代码/状态迁移与版本目录。检查和最终安装身份、归档覆盖窗口属于低频可预期性改进，不抢占访问性能主线 |

## 值得先做的局部优化

下列投入是评估时的单人有效开发日粗估，包含定向检查，不含外部环境等待。用户随后授权按 O2 → O1 → O3 实施；进度以[实施计划](musicfs-implementation-plan.md)为准。互斥方案及条件性候选不相加。

| 编号 / 方向 | 依据、用户收益 | 投入 / 风险 / ROI |
|---|---|---|
| O1 大目录视图的容量与保留方式 | **已实现**：[发布视图](../src/core/library/published-views.ts)只保留投影索引，不附带原始快照；桌面估算总预算32MiB，Worker维持8MiB。单项超预算仍可读。两个各6,000项视图轮换已做定向离线测试 | 原估0.5—1.5日；风险是额外内存。**条件性高ROI，有界复现已覆盖**；未放大所有宿主上限，不把局部命中外推整库体验 |
| O2 状态不变时避免挂载配置写盘 | **已实现**：[mounts](../src/hosts/desktop/mounts.ts)只在保存内容变化时写盘；[页面](../src/web/pages/mounts.tsx)稳定挂载由每3秒改为15秒查询，操作后立即刷新 | 原估0.25—0.5日；低风险。**高ROI的小减法**，主要减少本机I/O、原生控制往返和无效工作，不声称能单独消除整目录十秒等待 |
| O3 缩短首次单文件资料准备的等待链 | **已实现**：[网易云](../plugins/netease/metadata.ts)与[QQ](../plugins/qq/metadata.ts)在单曲有空余名额时重叠歌词/封面，保留专辑依赖和批量/预算策略。[80ms有限样本](../docs/verification/performance-local-2026-10-22.md)约243ms→162ms，成功请求集合相同 | 原估0.5—1日；涉及失败取消和请求峰值。样本支持局部实现，**不外推平台或全库提速**；失败时另一个请求可能已启动，完成收束后返回，不叠加重试 |

这三项最初粗估 **1.25—3个有效开发日**，现已按 O2 → O1 → O3 完成局部实现与定向核对；未重打桌面发行包。后续从实际反馈重新排序，不先重构整条链路。

## 其余可选方向

| 编号 / 方向 | 代码事实与建议 | 投入 / 重开条件 |
|---|---|---|
| O4 桌面刷新由后台主要推进 | [usePersistentRefresh](../src/web/components/refresh.tsx)主动 POST step，同时[桌面runner](../src/hosts/desktop/service.ts)也推进；租约保证正确性，但争用时仍有控制请求/状态读取。桌面可主要观察，Worker继续页面续步；必要时根据运行中进度调整观察节奏 | 0.25—0.5日；中ROI。先数一次本地刷新中的有效步与空步，不能为了减请求让完成提示明显变慢 |
| O5 管理页短期重进复用查询 | [QueryClient](../src/web/shell.tsx)未设 staleTime，[目录查询](../src/web/pages/library.tsx)也未覆盖。已有数据可先显示，但默认重挂载仍可能重取整份列表；可对已发布浏览结果设短新鲜期，沿已有成功变更失效 | 0.25—0.5日；中ROI，低风险。只改善管理页，**不能当成 Windows 挂载盘重进问题的修复**；跨窗口变更仍须说明可见期限 |

| O7 长期数据增长与表示复用 | [终态刷新任务](../src/infrastructure/persistence/refresh-sql.ts)未见保留回收；[网易云ready索引](../plugins/netease/tagged.ts)到期后可产生新代次永久计划，即使部分资料未变。先按键类统计行数/字节和变化频率，优先减少不必要的新表示 | 先0.25—0.5日量级核对；中、条件性ROI。不能直接删仍服务公开表示的计划，也不先造通用引用回收框架 |
| O8 多缓存的资源预期 | 多挂载和直接DAV容量独立，用户可能难以合计预算。可在打开管理窗口时汇总已有采样与未知项，明确软上限、采样时间和清理对象 | 0.25—0.5日；多入口用户中ROI。不开新常驻轮询，不为统计唤醒未使用VFS，不将unknown算作0，不建全局淘汰器 |
| O9 退出行为与缓存开关一致 | **已在应用场景续评实现**，容量0沿用同一活动读取/退出门禁；未改监听器关闭顺序，停止接收由既有门禁处理 | 原估0.25—0.75日；有限模块/HTTP回归通过，不做宿主网络或平台故障验证 |
| O10 M4A 准备往返 | [M4A顶层box](../packages/audio-tags/src/m4a.ts)逐项读头，某些布局可能形成多个小Range。只有准备阶段确实被往返主导时，才在已知结构边界内合并，不能预读mdat | 低至中、待证ROI；先复用已有样本计数。常见布局成本很小则保留，不为格式统一重写工具 |

O4—O10是备选，不作为必须逐一实施或验证的清单。免费 Worker 的预算观察应随被选中的改动进行，复用既有工作量证据；不单独恢复大目录云端验收。批量缓存扣一次查询与“一条SQL读取多行”可以一致，CPU和传输量另看，不能机械按条目数扣成数百次查询。

## 有界核对与证据等级

最初六顾问复评只执行一个会影响决定的离线保留检查：正式 `createPublishedViews` Module，使用合成网易云v4条目形状和计数存储，连续取得同一发布身份两次。后续实现及应用场景样本另见本页上节和[局部证据](../docs/verification/performance-local-2026-10-22.md)，不将下表改写成新版本整体耗时。

| 合成条目数 | 模块估算保留量 | 完整快照装载次数 | 第二次对象复用 |
|---:|---:|---:|---|
| 1,000 | 1,732,586字节 | 1 | 是 |
| 4,000 | 6,934,586字节 | 1 | 是 |
| 6,000 | 10,402,586字节 | 2 | 否 |

评估时默认预算为8,388,608字节。该结果证明大项不保留的机制，不证明用户4,000首已超过预算，也不是实际SQL、GUI耗时、堆内存或免费Worker测量。文件引用、名称、音质数量及多个目录竞争会改变结果。[匿名原始结果](../docs/verification/data/published-view-budget-2026-10-22.json)。实现后桌面预算提高为32MiB；[定向测试](../tests/library-views.test.ts)覆盖两个各6,000项且单项估算超过8MiB的视图轮换，快照各装载一次；同时保留发布切换、取消和LRU边界检查。

## 对顾问建议的复核

| 顾问 | 主要提醒 | 复核后的处理 |
|---|---|---|
| 目录/持久化 | 终态记录增长；不可达旧目录重复刷新 | 增长保留为O7；后者**不采纳为新缺陷**：[刷新实现](../src/core/library/refresh.ts)仅将本轮实际遇到且known的子目录入队，[既有测试](../tests/instance-refresh.test.ts)明确覆盖跳过不可达旧快照 |
| 来源/SDK/会话 | 大封面与单缓存值上限；工作预算维度 | 封面读取确实可撞单值上限，但网易云已请求固定尺寸且没有频率证据；降为有实际失败再处理。不能静默丢封面违背用户目标；预算维度按上节分别判断 |
| 文件协议/表示 | 填充成本、较大标签、M4A往返、工具许可 | 填充是已接受且已有证据的取舍，不重跑矩阵；大封面已做共享codec但单值上限仍独立；M4A保留O10。GPL选择已明确，不因性能评估重开许可研究 |
| 桌面 | 退出门禁、多缓存占用、刷新含义与LAN提示 | 退出/占用分别为O9/O8；刷新含义可随相关UI改动改善。LAN明文提示不进入本次加速降本主线，不扩系统策略或确认流程 |
| Worker/发行 | 免费资源证据、归档覆盖窗口 | 免费预算保持诚实边界并随选定改动观察；本地workerd不能认证真实免费CPU。覆盖窗口是低频工具改进，不抢占访问性能工作 |
| 用户旅程/UI | 准备提示、检查与安装身份、系统操作确认 | **准备提示不采纳为新缺陷**：[pendingFileInfo统计](../src/core/library/refresh.ts)只计缺info的显式延迟项，[新预留表示](../plugins/netease/catalog.ts)带完整info，不显示该提示。URL检查/安装身份可作为低频可预期性改进，暂不建暂存平台或额外确认矩阵 |

顾问独立视角有价值，但“快照中没看见”不等于没有实现，代码事实也不自动证明用户影响。经筛选后的 O1—O10 包含主代理补充的跨环节发现，不冒充六位顾问一致结论。

## 架构与推进方式

继续保留原领域和依赖方向。O1落在library与宿主预算；O2/O8/O9落在桌面资源管理；O3/O6落在来源插件；O4/O5落在页面与宿主接线。沿用现有 lru-cache、TanStack Query、rclone及插件中已有的并发工具，不需要新增通用缓存、队列、事件总线或SDK框架。

按无变化写盘、大目录保留、首次准备等待的顺序推进，具体进度见实施计划。保留准确最终大小、字节身份、取消、来源代际及完整发布；优化不得以增加平台总请求、预热整库或丢弃用户要求的资料换取表面速度。每项只验证其实际改变的旅程，不恢复历史全矩阵，不部署或覆盖旧发行物。
