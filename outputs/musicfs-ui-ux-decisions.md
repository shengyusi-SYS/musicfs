# MusicFS UI / UX 取舍

以当前来源插件、只读文件服务和既有实际使用场景为边界。以下比较先考虑用户能否完成任务，再考虑点击数、理解成本、来源请求和实现投入；不会把少一个按钮当作唯一目标。现行结构见[界面设计](../docs/architecture/web-ui.md)，操作证据见[走查记录](../docs/verification/ui-redesign.md)。

| 环节与使用场景 | 比较的方向 | 决定与依据 |
|---|---|---|
| 首次打开与再次使用 | 全程步骤向导；空状态引导；始终显示完整设置面板 | 选空状态引导。首次给一个明确入口，已添加来源后直接展示列表，不让老用户重复走向导。导航按音乐来源、音乐目录和连接组织，插件作为次级管理入口。 |
| 找到和安装插件 | 随包插件选择器；手动检查后安装；选包自动检查再安装 | 本轮选自动检查。去掉独立检查按钮，保留安装动作及版本信息。随包选择器确实能进一步减少找文件，但需要桌面资源发现和 Worker 分发的宿主合同，不在界面里写死两个平台；本轮先在选包处给出随包文件夹位置。 |
| 创建来源、多账号与配置 | 所有配置前置；直接按默认值创建；有默认值并允许修改后创建 | 选第三项。自动选中唯一插件，隐藏重复的选择与可选显示名称；插件配置仍可在创建前调整，避免已经扫描大量歌曲后才发现音质选错。通用表单不按字段名猜哪些来源设置可以隐藏。 |
| 登录与切换账号 | 点击开始后再生成步骤；每次打开都重新生成；新建或明确重新登录时自动开始 | 选第三项，减少一次无意义的开始按钮。有效的进行中步骤可继续；成功后展示账号和浏览内容入口。没有直接自动关闭成功页：QQ/微信可能对应不同账号，确认实际账号有真实价值。 |
| 内容加载与更新 | 登录后刷新整个实例；用户逐个准备；浏览时仅加载需要的目录 | 默认按需浏览，保留显式单目录和全部更新。不为简化页面而自动扫完整音乐库。内容管理和当前对外目录各有入口，不根据显示名称猜源到布局路径的映射。 |
| 默认目录与自定义布局 | 抽屉中局部编辑；逐层文件夹管理；独立整理工作区 | 普通浏览保持简洁，整理时进入独立工作区。原抽屉在批量选择、移动和对照结构时空间不足，改为来源内容与目标树并列；窄屏切换两栏。 |
| 在数千首歌中找文件 | 保留分页；改成虚拟滚动；当前目录内筛选加分页 | 选本地筛选加分页。单纯虚拟滚动不能解决找歌，服务端或跨来源搜索会增加请求和范围。本页已有完整清单，按文件名筛选无需额外来源请求，也不改变原顺序。 |
| 本地播放器与 WebDAV 播放器 | 一页并列所有连接方式；按使用目的分标签；首次强制选择连接向导 | 选标签页。桌面先显示挂载，Worker 显示 DAV；切页记住使用方式。地址、用户名、密码分别复制，局域网和原生映射设置在需要时展开。 |
| 挂载位置与缓存 | 所有参数都填写；全部自动选择；默认参数加可选设置 | 选第三项。Windows 使用既有自动盘符能力，位置可不填；其他系统仍填写挂载目录。缓存沿用默认值，按需展开。未新增目录选择器、系统托盘或后台安装框架。 |
| 配置和诊断的可见性 | 全部常驻；统一高级设置大页面；跟随当前任务按需展开 | 选第三项。插件技术信息、缓存位置、证书信息各留在所属任务中，避免为了查一个信息跳转多个页面。来源设置只读取已连接来源使用的插件配置，避免加载未使用插件。 |
| 更新反馈和恢复 | 保留成功历史横幅；只显示当前任务及异常；独立全局任务中心 | 选当前任务及异常。成功后用轻提示和新内容反馈；处理中保留进度、取消与实际重试时间。沿用后台任务合同，不额外建一套队列。 |
| 移除、退出和服务切换 | 每步确认；有明确影响时简短确认；所有操作立即执行 | 采用第二项。永久删除来源、暂停插件等操作保留一条具体影响说明；缓存清理、展开设置、切换页面没有额外确认。服务退出移到全局入口，窄屏同样可访问。 |

## 目录整理的进一步取舍

用户反馈原目录树操作繁琐后，重新检查实际任务，替换原抽屉编辑器。

| 环节 | 比较的方向 | 选择与理由 |
|---|---|---|
| 从默认目录开始 | 清空后重建；新增一个转换向导；在现有目录上直接整理 | 直接整理。后端复用现行路径命名与来源入口快照，生成编辑起点，保留同名目录的实际路径。首次修改才转为自定义草稿。 |
| 添加多个歌单 | 两个下拉框逐个添加；多选弹窗；常驻来源清单 | 桌面采用可搜索、多选的来源清单，一次加入多项。窄屏切换到“添加内容”，选择和目标位置仍会保留。 |
| 指定添加位置 | 隐含依赖选中节点；每次弹窗选位置；可见的目标文件夹选择 | 树的选中位置会同步到“添加到”，也可直接选择目标。选中来源入口时使用其所属文件夹。 |
| 改名和新建 | 底部属性表单；弹窗；节点原位输入 | 原位输入。新建后直接命名，Enter 或离开输入框确认，Escape 取消改名。 |
| 移动与排序 | 仅拖动；仅剪切粘贴；拖动与明确操作并存 | 保留拖动，并提供移动到、上移和下移；触屏和较深的树无需精确拖拽。移动目标不包含自己及其下级。 |
| 找到节点 | 一直展开；递归向后台搜索；本地筛选并保留上级 | 本地筛选，保留匹配项的上级，匹配文件夹时保留其内容。筛选时关闭拖动，排序仍以完整草稿为准。 |
| 误操作与生效时机 | 每步确认；立即保存；草稿撤销后统一保存 | 新建、添加、改名、移动和移除都可撤销、重做，不加逐步确认。保存时沿用版本检查和一次发布；返回浏览及切页保留草稿。保存后回根目录，避免落在改名前的失效路径。 |

自动排列继续跟随来源；自定义布局保存用户选定的入口和顺序。编辑器不展开来源内部的歌曲清单，也不将“整理目录”变成整库扫描。

## 本轮停止位置

界面不新增播放器、全局音乐搜索、插件市场或新的同步系统。它们是独立的产品能力，不能仅从“操作简单”推导为必做。

未采用的方向不等于永久放弃。随包插件选择器在首次安装仍频繁卡住时值得优先重开；插件配置若仍有明显困扰，应由插件提供分组或显示条件，而不是宿主识别网易云、QQ 的字段。现有分页或局部筛选若有实际性能问题，再考虑虚拟列表或后台查询；不预先增加两套实现。
