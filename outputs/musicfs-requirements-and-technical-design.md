# 云端音乐虚拟文件系统需求与技术方案

日期：2026-10-20  
版本：插件式数据源统一方案，已合并插件 Q1—Q11 与既有 WebUI、Bun 方向  
状态：需求已对齐，已进入 P4/P5 交付收尾；当前进度与未完成范围见验收台账

暂定项目名：`musicfs`。

本项目通过可安装的数据源插件，把音乐服务或音频文件来源转换为可浏览、可播放的只读音乐目录。采用 TypeScript 实现，共用业务核心、插件合同与 WebUI，分别运行在 Windows、Linux、macOS 的本地后台，以及 Cloudflare Worker。

网易云音乐与 QQ 音乐作为首批示例插件，要求完整提供登录、发现、自建与收藏歌单、喜欢的音乐及音质等能力，通过与第三方插件相同的公开接口接入。核心不内置平台规则，其他插件也不必具备这些全部能力。

用户通过 WebUI 安装插件、配置来源实例、完成认证、设置目录与查看状态。桌面用户点击启动器打开本机 WebUI，再点击挂载，由后台管理内置 rclone。通过标准 WebDAV 接入 OpenList，使用现有驱动即可。

桌面与 Worker 独立部署；使用任意一种都不依赖另一种常驻。不要求额外部署网易云 API、QQ API 或签名服务器。产品不再提供面向用户的 CLI 操作流程。

桌面宿主建议采用 Bun，将运行时、后端与 WebUI 打包为可执行程序；这条路线待 P0 实测，当前不是已完成的兼容承诺。[Bun 评估](musicfs-bun-desktop-evaluation.md)

前端保留 React + Vite 与成熟交互组件。Vite 统一生成 WebUI 静态产物，Bun 负责桌面后端及发行打包，不为采用 Bun 替换前端工具链。

Worker 插件安装、更新和移除允许由后台自动发布普通 Worker 新版本，用户无需手工编译或部署。这是避免付费动态加载前提的优先验证路线，普通Worker的实际发布/配置保留和核心升级已有证据；免费计划结论及切换影响仍按台账收口。[插件边界](../docs/adr/0001-installable-source-plugins.md)、[Worker 安装决定](../docs/adr/0002-worker-plugin-installation-by-deployment.md)

## 1 范围与已确定方向

| 项目 | 要求 |
|---|---|
| 语言 | 自有业务代码采用 TypeScript |
| 桌面 | Windows、Linux、macOS，提供可点击启动器与本地后台 |
| 云端 | Cloudflare Worker，提供相同 WebUI、核心和兼容插件的执行入口 |
| 来源范围 | 插件接入音乐服务、自建服务或 HTTP/WebDAV 音频来源；首批完整示例为网易云与 QQ |
| 插件安装 | 上传作者构建好的插件包或填写发布地址，用户主动更新和移除 |
| 来源实例 | 同一插件可配置多个独立实例，各自保存连接配置、认证及来源设置 |
| 宿主兼容 | 第三方插件声明桌面、Worker 或两者；网易云与 QQ 示例要求双端验证 |
| 管理入口 | WebUI，覆盖插件管理、实例配置与认证、目录布局、刷新和状态 |
| 目录布局 | 提供拖拽树，默认按来源实例分组；示例插件的内容分类由插件提供 |
| 数据更新 | 内容源随对应实例刷新；用户布局独立保存 |
| 文件协议 | 只读 WebDAV，支持播放、HEAD 和范围读取 |
| OpenList | 使用现有 WebDAV 驱动，不修改 OpenList |
| 桌面挂载 | 集成 rclone，在 WebUI 一键挂载、卸载，无需用户配置 remote |
| Worker 挂载 | Worker 本身不挂载本机磁盘；桌面可挂载其 WebDAV |
| 音质 | 插件定义并按实例保存；网易云与 QQ 示例提供单/多版本、隐藏与自动回退 |
| 无完整播放权限 | 示例插件默认隐藏并报告原因；通用核心不把技术失败推断为无权限 |
| Worker 插件变更 | 允许后台自动部署新版本，优先验证普通免费计划路线 |

继续按自用、只读场景收敛。多个实例不引入公共多用户服务或共享权限体系；首版不附加播放器、MPD、独立 SMB 服务、云端歌单写入、转码或批量离线下载管理。来源插件可提供音乐文件目录，不据此扩展为通用可写网盘产品；插件市场、自动升级和任意插件前端页面不作为首版交付。

不以高并发服务为设计或验收目标。真实来源验证按单用户、低频、串行和少量代表样本执行，复用已有结果，不做压力、容量极限、持续负载或反复全账号扫描。出现验证码、限流或风险提示时停止该来源验证，记录结果并等待恢复，不换账号、渠道或出口继续试探。不涉及真实平台、对UX影响明显的本地性能、并发或故障测试可以做，按用户影响与收益确定范围，采用有界样本和明确结束条件。

开发和部署仍可使用正常的构建工具与 Cloudflare 部署工具；取消的是产品要求用户操作的 CLI 界面。

## 2 用户场景

### 2.1 桌面使用

安装发行包，点击启动器，后台启动并打开系统浏览器中的本机 WebUI。用户安装兼容插件、创建数据源实例，按插件提供的表单与认证流程完成配置；使用网易云或 QQ 时扫码登录并在该实例中选择音质。调整目录后选择盘符或挂载路径并点击挂载。依赖就绪后，一次点击完成 WebDAV 与 rclone 的内部配置和启动。

挂载后可用普通文件管理器或播放器浏览、播放并拖动进度。关闭浏览器页面不停止后台与挂载；用户在 WebUI 中卸载或退出后台。系统注销、关机后的自动恢复不作为当前必需功能。

### 2.2 WebDAV 与 OpenList

桌面后台或 Worker 提供 WebDAV 地址与读取凭据。OpenList、手机播放器等使用该地址访问。局域网服务地址通过设置配置；桌面默认服务本机。

### 2.3 Worker 独立使用

部署后直接打开 Worker 的 WebUI，安装 Worker 兼容插件、创建实例、配置并认证，再设置目录。示例插件的扫码与音质设置在对应实例页面完成。Worker 提供 WebDAV，不要求用户安装桌面端完成来源认证。插件变更可触发后台自动部署，页面展示进度与结果；不承诺尚未经验证的无中断切换。

### 2.4 桌面挂载远程实例

在本地 WebUI 添加 Worker 的 WebDAV 地址与凭据，由本地后台启动 rclone 挂载。平台账号与音乐接口运行在远端，本地无需重复登录平台，也无需再代理同一份音乐。

### 2.5 多实例与插件移除

安装一次插件后，可以连接两个不同服务器或配置两个账号，各自拥有设置、认证和内容源。例如，同一示例插件的两个实例可以采用不同音质。移除插件后，管理界面保留实例配置和布局引用并标记插件缺失，停止相应读取；重装兼容插件可恢复。彻底删除实例及其数据是单独操作。

| FR23 | 移除与恢复 | 移除插件保留实例配置和布局引用，标记缺失并停止读取；重装兼容版本可恢复，删除实例数据另作操作 |

## 4 WebUI 与目录布局

### 4.1 WebUI 页面范围

| 页面或区域 | 主要操作 |
|---|---|
| 插件 | 上传包或发布地址安装，查看版本与兼容性、主动更新和移除，Worker 显示部署进度 |
| 数据源实例 | 创建多个来源连接；按插件声明配置、认证、退出及刷新，单独删除实例 |
| 目录布局 | 选择内容源、创建分组、拖拽树节点、预览并保存导出结构 |
| 全局设置 | 必要的 WebDAV、应用及缓存参数 |
| 实例配置 | 插件声明的来源设置；示例插件在此配置音质模式、档位和缺失策略 |
| 服务状态 | 插件/实例状态、最近刷新时间、文件数和插件提供的曲目/隐藏统计、错误与重试 |
| 桌面挂载 | 本地或远程来源、挂载位置、挂载与卸载、系统依赖检测 |

Worker 不提供本机挂载操作。WebUI 是管理入口，首版不附加播放器功能。具体组件库和页面排版属于实现选择，不作为新的需求问题。

新增插件通过声明式字段、校验与认证步骤复用通用界面；核心提供表单、二维码、链接和验证码等交互承载，插件负责流程语义与状态。没有认证或音质概念的来源不显示这些设置，首版不要求运行任意插件前端页面。

### 4.2 默认目录

默认按数据源实例分组。下面是分别配置一个网易云与 QQ 示例插件实例时的布局；发现与歌单等内部分类由插件提供，其他来源可以直接提供音乐文件夹。

```text
/
├── 网易云音乐/
│   ├── 发现/
│   │   ├── 每日推荐/
│   │   └── 推荐歌单/
│   ├── 你的歌单/
│   │   ├── 喜欢的音乐/
│   │   └── 歌单名称/
│   │       ├── 0001 - 歌手 - 歌名 [高品质].mp3
│   │       └── 0001 - 歌手 - 歌名 [无损].flac
│   └── 收藏的歌单/
└── QQ音乐/
    ├── 发现/
    ├── 你的歌单/
    │   └── 喜欢的音乐/
    └── 收藏的歌单/
```

例子展示示例插件的多版本模式，具体扩展名取决于实际音频。各实例提供自己的内容源，可用实例名称区分同一插件的多个连接；未认证、插件缺失或读取失败在 WebUI 显示，不伪装成成功空目录。

### 4.3 目录布局与内容源

目录布局保存用户安排的层级与显示名称。内容源属于某个数据源实例，可以是喜欢的音乐、自建歌单集合、某张歌单或服务器中的音乐文件夹；核心无需枚举所有来源分类。

拖拽操作对象是目录与内容源节点，曲目随来源更新。把“你的歌单”放到指定位置后，平台新增歌单会在刷新后出现在该处；不要求用户再次逐个拖入。布局操作只改变本项目导出的路径，不修改云端歌单，也不逐首搬动平台歌曲。

用户可以构建如下布局，默认布局不是唯一结构：

```text
/
├── 我常听的/
│   ├── 网易喜欢/     ← 网易云喜欢的音乐
│   └── QQ喜欢/       ← QQ喜欢的音乐
└── 每日推荐/
    ├── 网易云/       ← 网易云每日推荐
    └── QQ音乐/       ← QQ每日推荐
```

布局和来源内容独立保存。刷新只更新内容，不重置用户布局。插件移除后保留原引用并在管理界面显示缺失；未恢复插件时停止相应读取，不能将保留的快照误认为仍可播放。建议编辑时预览、保存后生效，重名或不可用来源在界面说明。

### 4.4 命名与身份

区分插件身份、安装版本、数据源实例、来源对象、对象在目录中的一次出现和实际音频身份。内容以实例与插件给出的稳定对象身份关联，不以账号显示名、路径或临时 URL 当主键；两个实例即使连接同一服务也分别保存凭据与状态。插件更新保留实例身份，示例插件保留同曲在歌单中的不同出现位置。

插件提供目录/文件显示名称及可用元数据，示例插件以曲序、歌手、歌名和实际音质生成原始名称。用户可选择自定义模板，来源默认及单目录覆盖独立于内容配置保存；命名资料由插件可选提供，不为命名额外抓取音频或资料。核心统一处理 Windows 保留名、禁止字符、尾部空格和点、大小写冲突、Unicode、路径长度与稳定的冲突后缀；不要求所有插件都有歌手或曲序字段，不强制展示内部技术版本号。现行职责见[自动更新与命名](../docs/architecture/updates-and-naming.md)。

目录改名、拖拽、曲序和音质设置变化会影响路径。客户端刷新后看到新布局；不承诺所有第三方目录缓存立即更新。

## 5 示例插件的单版本、多版本与回退

本节属于网易云与 QQ 示例插件的业务合同。插件定义选项、校验、音质选择、回退和实际音频去重，配置按实例保存；核心保存并展示插件配置、接收最终目录与文件，不设全局 `audio` 策略或统一音质枚举。其他插件按自身来源定义能力。

### 5.1 模式与设置

| 设置 | 行为 |
|---|---|
| 单版本 | 只允许选择一个目标音质，每首曲目最多导出一个实际音频文件 |
| 多版本 | 允许选择多个目标音质，每个可提供的实际音质对应一个文件 |
| 音质缺失：隐藏 | 不导出缺失档位，其他所选可用档位正常展示 |
| 音质缺失：自动回退 | 目标档位不可用时，按平台的音质顺序向下查找可用完整音频 |

可选音质来自对应插件及实例的实际能力，不固定为三个档位；界面说明该来源支持范围。建议示例插件初始使用单版本与隐藏策略，用户可在实例配置中修改；该初值是实现建议。

### 5.2 回退规则

回退在同一数据源实例、同一歌曲内进行，按插件定义的可回退顺序选择较低档位。不换实例、平台或歌曲，不把试听片段当完整音频。

文件名与扩展名按实际取得的音质和格式生成，不把回退后的高品质 MP3 标为无损。目标音质与实际音质可在状态中区分。

多版本下，不同目标回退到同一份实际音频时只导出一次。例如选择高品质与无损，歌曲只有高品质：

| 策略 | 导出结果 |
|---|---|
| 隐藏 | 保留高品质文件；省略无损文件 |
| 自动回退 | 无损回退为高品质，与已选高品质去重，仍为一个高品质文件 |

只选无损时，隐藏策略不导出该曲目；自动回退策略则导出实际可用的较低音质文件。所有可回退档位均不可用时隐藏，并在 WebUI 报告原因。

以上回退顺序、实际标注和去重是已确认的示例插件规则；不新增每种异常各自一套开关。

### 5.3 不可播与临时故障

平台确认没有完整播放权限或仅提供试听的歌曲默认隐藏，只在状态中统计，不生成 `.unavailable.json` 文件。暂时的认证、网络、限流或解析错误按各自状态处理；不通过回退掩盖这些故障，不覆盖最近成功目录为“全部不可用”。

曲目数和文件数分开统计。同一曲目导出两个音质时是一首歌曲、两个文件；隐藏或去重不改变平台原始曲目数量。

## 6 总体架构与 TS 边界

领域、Module、Interface、状态所有者与依赖方向的设计见 [架构设计](../docs/architecture/README.md)。结构与关键时序统一维护在 [架构与流程图](../docs/architecture/diagrams.md)，公开插件操作与字节合同见 [插件 Interface 草案](../docs/architecture/plugin-interface.md)。本文保留需求层面的职责约束，不另维护一套图或实现目录。

桌面和 Worker 独立运行共用核心与合同；插件根据兼容声明进入对应宿主。桌面建议使用包含 Bun 运行时的编译产物、外置安装的插件及随包 rclone；Worker 优先验证预构建模块组装与自动部署。两种宿主均不依赖另一端常驻。

下面是职责划分。核心保持一个应用、少量存储操作与两个宿主入口；可独立安装的来源适配作为插件交付，不把每个核心职责再拆成独立包或服务。通用 HTTP 和 WebUI 优先复用成熟依赖，第 13 节列出建议。

| 模块 | 责任 |
|---|---|
| 数据源插件 | 来源协议与认证、完整分页、内容分类、配置含义、实际音频版本选择/回退/去重、元数据及范围取流 |
| 插件宿主 | 插件包与兼容检查、安装版本切换、实例生命周期、公开调用合同及存储/请求等必要宿主能力 |
| 实例管理 | 隔离配置与认证状态、合并刷新、条件提交、退出和删除；认证语义由插件实现 |
| 布局与目录 | 实例内容源引用、用户目录树、合法命名与冲突、通用刷新调度、完整导出快照 |
| 音频接线 | 将插件元数据和读取能力接入协议，维持同一实际音频的字节、长度、范围与取消合同 |
| WebDAV | 路径、读取认证、XML、HTTP 状态和响应头 |
| WebUI 与管理 API | 插件/实例管理、通用配置表单与认证步骤、布局保存、状态与诊断 |
| 存储适配 | 本地 SQLite 与 Worker D1，提供必要的条件更新与快照操作 |
| 桌面宿主 | 启动器、HTTP、静态资源、外置插件加载、本地挂载和后台生命周期 |
| Worker 宿主 | Fetch、静态资源与绑定，插件变更时的模块组装和后台自动部署 |

共用模块优先采用标准 `Request`、`Response`、`fetch`、Web Streams 和 `AbortSignal`。文件系统、子进程、HTTP 监听与 Bun API 留在宿主边界；仅支持桌面的插件可声明实际所需能力，不能据此假定兼容 Worker。

插件合同显式区分实例上下文、内容游标、调用版本与取消信号，提供可浏览入口、目录、文件元数据和读取能力；不要求返回裸音频 URL。签名、必要请求头、临时地址续期和来源特殊读取仍可由插件执行。目标/实际音质与试听权限等语义留在相应插件内，核心接收可导出的实际文件和诊断结果。

插件可使用宿主提供的持久化设施保存实例状态，不能依赖模块全局 Cookie 或 Worker isolate。配置修改、换号、退出、更新及删除后的旧认证/刷新结果不得写回当前状态；核心协调版本与提交，插件解释自身数据与必要迁移。具体接口形状、包格式和迁移操作在 P0 与实现设计中收敛。

## 7 插件安装、实例认证与示例实现

### 7.0 安装与生命周期

插件作者发布已经处理依赖及资源的插件包，声明稳定身份、插件版本、公开合同兼容范围和目标宿主。用户通过 WebUI 上传包或填写发布地址安装，并主动更新；使用者无需自行编译核心或 WebUI。首版以插件包与公开开发合同为扩展入口，不要求插件市场、自动升级或来源专用前端页面。

桌面优先验证从真实应用数据目录加载兼容的预构建插件，保持 Bun 编译核心与插件安装独立；具体加载和资源路径行为须在编译产物中实测。Worker 安装路线见第 10 节。

更新需协调代码、配置和实例状态，失败应保留可用版本，不能以一次构建成功作为迁移或运行正确的证据。移除停止该插件相应实例的读取与后续任务，保留实例配置和布局引用并标记缺失；重装兼容插件后可恢复。彻底删除实例及其数据由用户单独操作，旧任务不能恢复已移除的状态。

## 8 音频与 WebDAV

### 8.1 音频表示与元数据

音乐资料补全属于来源插件的可选能力：可以直接提供原文件、自带补标签，或选用共用工具。核心不强制改写、不要求所有插件提供歌曲/封面/歌词字段、不新增格式白名单；共用工具作为插件依赖打包。QQ、网易云本次扩展以基础资料、封面和来源已有歌词随音频携带为目标，保持音频编码与音质不变；缺失资料不自行生成，保留已有时间轴、译文和罗马音。按来源实际格式验证，未提供的格式不纳入该来源范围。模块设计与当前实现状态见[可选补标签设计](../docs/architecture/audio-tags.md)。

来源对象身份与实际音频文件身份分开。插件提供属于某个实例的实际文件身份、格式、准确大小及可读取能力；临时 URL、请求头、过期处理和来源音质语义可留在插件内部。核心不能将 URL 作为内容身份，也不能要求插件必须返回 URL。示例插件记录目标与实际音质，但最终缓存和读取必须对应实际音频。

插件优先使用来源的可靠大小与格式，缺失时再有界地 HEAD 或探测范围读取并复用结果；通用探测机制可由宿主复用。不为取大小下载整曲，也不伪造大小。元数据准备时机以 OpenList、rclone 和播放器实测为准，优先使用批量信息，避免预设逐首探测整个歌单。

插件负责完整读取来源分页，核心调度并只发布完整成功快照，不能把一页内容当整个目录。准备任务限并发、可重试，失败不能发布为成功空列表；未知大小不能认定无播放权限。没有曲目统计的插件也能导出文件，核心不伪造曲目数。

### 8.2 HTTP 读取

| 请求 | 行为 |
|---|---|
| GET | 以正确类型和长度流式响应，保持背压，不缓冲完整歌曲 |
| HEAD | 返回对应读取元数据，无音频正文 |
| 单段 Range | 支持起止、开放尾部、后缀范围，206 与准确的 Content-Range、区间长度 |
| 不可满足范围 | 416 与 `Content-Range: bytes */总大小` |
| 多段 Range | 首版可按规范忽略范围返回完整 200，或后续实现 multipart |
| 客户端取消 | 取消上游读取并释放连接 |

上游忽略 Range 时不能把完整 200 响应改标成 206。首版需实测头部、尾部、大偏移与反复拖动；仅能从头播放不满足验收。避免透明压缩改变音频字节偏移。

临时 URL 过期后重新解析同一实际音频，使用可靠的媒体标识核对，不把 CDN URL 当身份。不在响应输出一半后从头重试拼接；需要时结束该响应，由客户端重新读取。内容变化通过正确元数据和缓存失效处理；具体机制由实测决定，不强制全量哈希或在文件名展示内部技术版本。

改变音质或布局后发布相应新视图，避免把已有缓存中的同一路径随意替换为另一编码。多音质缓存必须隔离，同一份实际回退音频可以复用。

### 8.3 DAV 路由与方法

| 路由 | 用途 |
|---|---|
| `/` | WebUI 与静态资源 |
| `/api/v1/` | 账号、设置、布局、刷新和状态 |
| `/dav/` | 只读目录与音频 |
| `/healthz` | 最小存活状态 |

通过复用服务端或薄适配提供 OPTIONS、PROPFIND Depth 0/1、GET、HEAD；正确处理 207、属性状态、中文路径、URL 编码、XML 转义和目录尾斜杠。写入方法明确拒绝，深度无限遍历与未实现的锁能力不宣称支持。

WebDAV 已执行 Nephele 自定义资源与官方 Worker Node HTTP 桥接的 PoC；本地 Worker 完整取流未通过，因此按原备选采用共用 Fetch 只读映射，复用 xmldom 的 XML/命名空间与 range-parser。当前 Bun、本地 workerd 和真实 rclone 路径已有证据，真实云端、平台、OpenList 和播放器仍待验。[ADR 0004](../docs/adr/0004-shared-fetch-readonly-dav.md)、[P0 记录](../docs/verification/p0-library-dav.md)

插件原始接口仅在内部使用，不整套映射到公网。首版音频经当前部署流式代理，插件负责来源认证与必要请求头，核心负责 DAV/HTTP 响应与取消传递；直接重定向仅作为通过验证后的优化。

### 8.4 OpenList

添加现有 WebDAV 存储驱动，填写 `/dav/` 地址与读取凭据，默认启用 Web Proxy。Root path 可选 `/` 或自定义布局下的某个目录，挂载路径由用户决定。无需编写 Go 驱动或提交上游。[驱动文档](https://doc.oplist.org/guide/drivers/webdav)

实测 OpenList 转发 HEAD、Range 与错误状态。部署地址必须从 OpenList 机器可达；本机、Docker、局域网与 Worker 分别提供配置说明。

## 9 桌面后台、rclone 与发行

建议由 Bun 可执行程序启动或复用当前用户的后台，使用 `open` 等成熟辅助打开本机 WebUI。HTTP 使用 `Bun.serve` 接入共用 Hono Fetch 入口，rclone 使用 `Bun.spawn`，不再需要 `@hono/node-server` 或额外子进程包装。前端点击挂载后，由后台验证路径、系统依赖、账号或远端连接，生成 rclone 配置并启动随包二进制；实际挂载就绪、根目录可读后报告成功。[Hono Bun](https://hono.dev/docs/getting-started/bun)、[Bun 子进程](https://bun.com/docs/runtime/child-process)

| 系统 | 路线 | 需要验证的系统设施 |
|---|---|---|
| Windows | rclone mount | WinFsp、盘符或目录挂载、后台启动 |
| Linux | rclone mount | FUSE、fusermount、用户权限 |
| macOS | 优先验证 rclone nfsmount | 系统 NFS 挂载与播放器行为；必要时提供实测的 macFUSE 路线 |

一键挂载以系统依赖就绪为前提；首次安装 WinFsp、FUSE 或其他设施时在 WebUI 检测并引导。普通用户不单独安装 Bun、Node 或 rclone。[安装](https://rclone.org/install/)、[mount](https://rclone.org/commands/rclone_mount/)、[nfsmount](https://rclone.org/commands/rclone_nfsmount/)

后台管理进程、挂载和临时配置生命周期，关闭网页不停止挂载。重复启动打开现有实例；失败回收本次资源，残留检测核对真实进程与挂载。卸载先采用系统正常机制，失败在页面说明，不默认强制操作。

使用 rclone VFS 缓存，不另做第二套音频磁盘缓存。`--vfs-cache-mode full` 是建议起点，大小和保留期可调；其上限为软目标，需如实显示磁盘不足等错误。[VFS 缓存](https://rclone.org/commands/rclone_mount/#vfs-file-caching)

前端先由 Vite 构建为普通静态资源。桌面使用 `bun build --compile` 编译核心后端与运行时，在打包阶段完整收录这些已生成的 WebUI 文件，保持分块和资源路径关系，不再使用 Bun 重编译前端源码。可安装插件使用真实的应用数据目录，安装新插件不得要求用户重新编译可执行程序；外置加载须在编译产物内验证。rclone 可随发行包并列提供；若选择单文件下载，则内嵌为资产，首次使用释放到真实路径再启动。实例数据库、设置与缓存不写入内嵌资源。详细依据与未验证边界见 [Bun 发行核查](research-bun-executable-packaging.md)。

发行物包含锁定的应用产物、rclone 和依赖许可，提供适合各系统的安装或解压运行方式。Windows 可使用隐藏控制台选项，macOS 按实际路线做薄 `.app` 包装；具体格式、签名和公证按实际发行路线验证，不预先作为额外产品门槛。至少测试 Windows x64、Linux x64、macOS Intel 与 Apple Silicon，其他架构标明实际验证范围。交叉编译不替代目标系统运行验收。

## 10 Worker 部署与状态

WebUI 构建为静态资源，和 Worker 一起部署。API 与 DAV 路径优先进入 Worker，避免 SPA 回退把协议请求返回成 HTML。页面和核心共用，不要求另部署前端服务。[Static Assets](https://developers.cloudflare.com/workers/static-assets/)、[路由控制](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)

WebUI 统一由 Vite 构建，Worker 复用其静态产物，不执行 Bun 可执行程序或 `Bun.*` API。Worker 使用独立入口，初始工程构建与部署可使用 Wrangler；后续插件安装、更新和移除通过 WebUI 驱动后台自动发布新版本，用户无需自己执行命令。

### 10.1 插件变更与自动部署

用户已接受“预构建模块 + 后台自动部署普通 Worker”为 P0 优先路线。作者预先构建插件并处理依赖，宿主组装预构建核心、插件模块与注册入口，通过部署接口发布新版本；不为安装插件重新构建 React/Vite 前端。具体上传接口、模块组织和部署生命周期尚未验证。[决定](../docs/adr/0002-worker-plugin-installation-by-deployment.md)、[候选调查与证据边界](research-worker-free-plugin-loading.md)

目标是避免付费动态加载成为首版部署前提，并核查普通免费计划能否承载应用与示例插件；不承诺任意插件数量、体积或使用量均免费。需要在部署时配置能更新目标 Worker 的凭据，具体权限与保存方式按实际 API 验证。付费 Dynamic Workers、独立插件 Worker 或解释器保留为技术备选，不自动改为必需条件。

安装、更新、移除是一次插件版本变更，页面显示进行中、成功或具体失败。验证代码与持久插件清单的对应关系、Secrets/D1/静态资源绑定保留、失败恢复以及当前请求和音频流的影响；不假定当前 Worker 更新自身后仍能完成全部尾部工作。允许后台部署不表示接受数据丢失、错误报告成功或未经测量的无中断承诺。

### 10.2 持久状态与运行限制

默认方案使用 Worker、D1 和必要 Secrets。D1 保存插件安装记录、实例配置/认证、布局、元数据和必要刷新进度，不存音频。预构建核心和插件产物的取得、保存及版本一致性在 P0 收敛；不预先要求 KV、R2 或 Durable Objects，也不因插件化引入长期登录守护服务。

Worker 内存只作短期缓存，插件和核心的持久状态都不能依赖某个 isolate。会话与配置以实例及版本条件更新，刷新合并并限制并发；大目录确需跨请求恢复时保存必要游标，跨请求互斥使用轻量数据库协调，不建立独立调度或工作流系统。退出、换配置、更新或移除后旧结果不能覆盖新状态。

目录完整刷新成功后切换快照，失败保留最近成功版本。设置和布局独立于目录快照。`waitUntil` 只做有界尾部工作，不承担长期登录守护或无限同步。

发布提供部署模板、D1 迁移、必要 Secrets 与插件部署凭据清单。部署者创建资源并注入秘密后打开 WebUI，安装兼容插件、创建和认证实例、设置布局并取得 DAV 地址；日常使用不需要产品 CLI。

所需接口必须在真实 CF 出口验证，尤其扫码后的凭据交换、刷新、歌单读取、音频与范围请求。Bun 本地成功不能替代 Worker 验收。`nodejs_compat` 也不代表全部 Node 依赖自动兼容。[Node 兼容性](https://developers.cloudflare.com/workers/runtime-apis/nodejs/)

采用 Web Streams，内存不随歌曲大小增长。核对部署计划的内存、CPU、子请求、包体积与流量限制；HTTP 流与后台任务的生命周期分别处理。实施时按官方当前规则复核。[Worker 限额](https://developers.cloudflare.com/workers/platform/limits/)

## 11 存储、设置与管理接口

本地使用 `bun:sqlite` 打开真实数据库文件，Worker 使用 D1，通过少量明确操作隔离差异，不建立通用数据库插件系统。核心保存插件安装记录、实例配置/认证、应用设置/布局与最近成功缓存；认证挑战、分页进度和音频元数据按实际需要保存，不强制每项独立成表。宿主提供按实例隔离的存储，插件解释自身配置、授权及必要状态迁移。使用参数化 SQL 与原生接口；表和查询明显增加后再评估 Drizzle，避免 ORM 上再套通用 Repository。SQL 结构可共用，调用与事务语义分别验证。[Bun SQLite](https://bun.com/docs/runtime/sqlite)、[D1](https://developers.cloudflare.com/d1/worker-api/d1-database/)

配置由 WebUI 修改并持久保存。全局设置仅包括应用与 WebDAV 等通用参数；音质、服务器地址或来源认证等设置由对应插件定义，按实例保存。下例只说明某个示例插件实例的音质配置含义，不是全局配置、通用插件 schema 或要求用户手写的文件，也不固定实际音质枚举：

```json
{
  "instanceId": "example-instance",
  "pluginId": "example-music-provider",
  "config": {
    "schemaVersion": 1,
    "audio": {
      "mode": "multiple",
      "qualities": ["high", "lossless"],
      "missingQuality": "fallback"
    }
  }
}
```

示例插件校验单版本时选择一档，多版本至少一档，缺失策略为 `hide` 或 `fallback`；核心承载校验结果而不硬编码这些来源规则。不同插件的原生参数不当作统一数值，没有音质设置的插件也不必提供此字段。

管理 API 支持以下必要操作，路径为建议：

| 路由，省略 `/api/v1` | 操作 |
|---|---|
| `/status`、`/plugins`、`/instances` | 服务、插件安装和实例状态 |
| `/plugin-operations`、`/plugin-operations/:id` | 安装、更新、移除与进度；Worker 包含自动部署结果 |
| `/instances/:id/config` | 插件配置声明、读取、校验和保存实例设置 |
| `/instances/:id/auth-challenges` | 创建、查询、推进及取消插件声明的认证流程 |
| `/instances/:id/session` | 退出对应实例的授权 |
| `/instances`、`/instances/:id` | 创建/管理实例与单独删除实例数据，具体方法按实现收敛 |
| `/settings` | 读取与保存通用应用设置 |
| `/layout`、`/sources` | 读取内容源与布局，校验并保存布局 |
| `/refresh-jobs`、`/refresh-jobs/:id` | 请求刷新与查询进度 |
| `/mounts`、`/mounts/:id`，仅本地 | 本机挂载、状态与卸载 |

服务端验证插件包与宿主兼容、实例引用、布局和节点关系，配置语义校验交给对应插件，不能只依赖页面控件。布局保存是一次可见变更，内容刷新不能部分覆盖它。安装版本、实例、内容节点和实际文件身份各自保存；移除插件不删除实例及布局引用。

## 12 缓存、错误与必要的凭据处理

目录与推荐允许短期缓存，提供手动刷新。临时音频地址遵循其有效期并留出余量，实际音频元数据不因 URL 换签而失去身份。具体 TTL、缓存大小和预取量属于可调实现参数，不逐项形成产品决策。

| 情况 | 行为 |
|---|---|
| DAV 凭据错误 | 401 与认证挑战 |
| 插件缺失或不兼容 | 保留实例配置与布局引用，管理页面说明原因，停止相应读取 |
| 实例需要重新认证 | WebUI 按插件步骤重新认证；DAV 明确不可用，避免误导为读取密码错误 |
| 示例插件无完整播放权限 | 由插件隐藏并报告统计；已有访问返回适当错误 |
| 示例插件所选音质缺失 | 由插件按对应实例的隐藏或回退设置执行 |
| 网络或来源暂时错误 | 保留最近成功目录，报告过期与可重试状态 |
| 插件更新或 Worker 发布失败 | 报告具体失败，保留可用版本与持久状态；不能假报安装成功 |
| 节点不存在 | 404 |
| 不可满足范围 | 416，携带总大小 |
| 写操作 | 明确拒绝，不修改音乐平台数据 |
| 限流与超时 | 有限退避、清楚的重试信息，不无限重试 |

用户的来源凭据由后台保存，按实例隔离，不交给 DAV 客户端。WebUI 管理和 DAV 读取分开鉴权；远程连接使用 HTTPS。基本认证、秘密存储和日志脱敏属于实现责任，不扩展为多用户权限产品。

本地保护凭据存储文件，采用适合随包环境的秘密保存方式；不强制首版集成每种系统密钥库。Worker 的必要密钥放在 Secrets，敏感凭据按既定加密方案保存。日志与诊断不输出 Cookie、会话密钥、扫码秘密、管理凭据或私有媒体地址。

媒体读取限定为已配置实例经插件提供的文件与读取能力；HTTP/WebDAV 插件可以访问用户配置的来源，不提供独立的任意 URL 公共转发入口。退出阻止该实例后续凭据使用；已经被播放器或用户保存的文件不具备远程收回能力。

## 13 工程组织

核心保持一个应用，领域 Module 不机械拆成独立服务；插件公开合同需要独立提供给作者，示例插件拥有独立交付产物。具体源码层级和禁止依赖方向只在 [架构设计](../docs/architecture/README.md#模块组织)维护，通用机制的依赖选择与采用条件在 [依赖选择](musicfs-simplification-and-dependencies.md)维护。

在源码建立时引入现成导入图检查工具执行模块规则，不能等各层穿透后再补限制。新增来源只依赖公开插件合同，核心和 DAV 不导入平台 SDK；SQLite/D1、桌面/Worker 加载发布与流转换留在真实 Adapter。结构校验、表单、归档、版本范围和部署请求优先复用成熟依赖，来源语义与状态提交由本项目负责。[新增依赖依据](research-architecture-dependencies.md)

Ant Tree 已覆盖树内拖拽，Query 已覆盖认证轮询；不为相同职责再叠加另一套树、拖拽或服务状态框架。首版可先选择内容源加入树，再拖动排序和改变层级。库只替代通用机制，核心仍负责插件管理、动态布局与实际挂载，示例插件负责平台归一化和音质规则。[依赖选择依据](musicfs-simplification-and-dependencies.md)

前端工具与交互依赖按开发体验、实际功能和整体维护成本选择。目录编辑中的拖拽、异步内容、草稿保存与状态反馈需要正常处理；若组件能力有实际缺口，可补充合适依赖。Bun 不限制前端生态，也不要求前端测试统一迁入 `bun:test`。

TS 开启严格检查；在适配边界检查平台响应。Bun 与 Worker 分别构建并核查导入图，将 Bun 专用 API、子进程和本机文件操作留在桌面入口及本地存储实现。锁定版本支持时采用 `bun check`，后端与共享逻辑可使用 `bun:test`；前端按自身工具链执行类型与交互检查，真实 Worker 与三端测试仍需完成。若 DAV 采用官方 Node HTTP 桥接，单独核查其实际依赖，而非笼统禁止所有 Node HTTP 导入。[Bun 设计依据](musicfs-bun-desktop-evaluation.md)

示例插件依赖与 rclone 锁定版本、来源和校验，记录补丁与回归结果，不在每次挂载时自动下载最新版。第三方插件按用户指定包或发布地址安装，记录实际安装版本与兼容性。发行与插件包保留各自依赖许可及必要说明。[网易云许可](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/19c7dad6db7d660954c7a615a686ff0acb030f91/LICENSE)、[QQ 许可](https://github.com/yakult-green-tea/qq-music-api/blob/e7dff2e1e2496780702bda528362edbdaf6bbf6e/LICENSE)、[rclone 许可](https://rclone.org/licence/)

## 14 验证与发布验收

真实平台资源验收观察正常自用操作是否可用，不以压测触达平台上限；目录规模优先复用已有快照或本地夹具。本地可针对大目录渲染、页面卡顿、重复操作、取消和挂载退出等有明显UX影响的行为进行有界性能、并发与故障测试。真实音乐平台仅补必要正常旅程，不主动制造限流或风控。

- [ ] 三种桌面系统均可从发行包点击启动 WebUI，不要求开发环境或用户 CLI。关闭页面后挂载继续，正常卸载和退出可用。
- [ ] WebUI 上传包或发布地址安装新插件，主动更新和移除；无需重新编译核心可执行程序或 WebUI，兼容声明正确展示。
- [ ] 同插件多个实例的配置、认证、缓存及内容隔离；同一来源的不同实例不会互相覆盖状态。
- [ ] 网易云与 QQ 示例插件仅经公开合同接入核心，在本地与真实 Worker 完成扫码、重启后使用、失效后重登及会话刷新。
- [ ] 示例插件自建、收藏、喜欢与发现分类正确，完成分页，顺序与重复位置不丢失。
- [ ] 无账号、无推荐/歌单、无音质设置的最小插件也能安装、配置并导出文件，核心及前端无需来源专用修改。
- [ ] 拖拽目录、保存和重启后布局一致；平台新增歌单或曲目刷新后出现，用户布局不变。
- [ ] 布局操作不修改平台歌单。名字冲突与三端文件名得到正确处理。
- [ ] 示例插件音质按实例配置：单版本一档，多版本多档；文件标签、格式、实际音质一致，曲目数与文件数分别准确，不存在全局音质强制策略。
- [ ] 示例插件隐藏和回退分别验证；回退不误标音质，多个目标回退到同一实际音频时去重，无完整权限仍隐藏。
- [ ] 对已知样本校验头部、尾部、跨块和大偏移字节；HEAD、206、416、取消与上游忽略 Range 正确处理。
- [ ] OpenList 使用现有 DAV 驱动成功列出、播放和拖动；普通播放器与 rclone 也通过实播。
- [ ] WebUI 可一键挂载本地与 Worker DAV；系统依赖缺失、路径占用、断网和磁盘不足有清楚状态。
- [ ] 临时失败保留最近成功目录，不伪造空列表，不把元数据未就绪当无播放权限。
- [ ] 插件移除保留实例配置及布局引用、标记缺失并停止读取；重装兼容插件后恢复，单独删除实例数据不会被旧任务恢复。
- [ ] 插件更新失败保留可用版本；换号、配置变化、更新或移除后，旧认证和刷新任务不能写回新状态。
- [ ] 普通免费 Worker 计划的插件组装/自动部署流程给出实际结果，包括 API 权限、模块体积、CPU、Secrets/D1/静态资源保留，以及读取和管理页面在切换期间的影响。
- [ ] 服务不缓冲整曲，记录正常自用下的目录访问、缓存命中和内存表现；复用已有流式/并发证据，按实际UX影响保留必要的本地测试，不以高并发容量作为交付门禁。
- [ ] 读取凭据不能管理账号或设置，日志与诊断不泄漏平台凭据。
- [ ] 三端发行包、示例插件包、公开插件合同及作者说明、Worker 模板、数据库迁移、依赖许可和使用说明齐全。

需求确认、平台源码调查和构建成功均不等于运行验收。P0 优先验证公开插件合同与新增最小插件、Bun 编译产物的外置加载、Worker 免费路线自动部署，再验证示例插件的真实登录与取流、大小/Range 和三端挂载。阶段可交错；若事实差距要求改变部署前提或范围，应给出具体证据，不能默认添加外部 API 服务、付费条件或把未验证能力写成已支持。

## 15 实施阶段

具体优先顺序、首条可用链路、当前环境限制及阶段完成条件见 [实施与交付计划](musicfs-implementation-plan.md)。阶段可交错，P0 不构成等待全部目标环境就绪才进行任何业务实现的全局门禁。

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| P0 关键验证 | 最小插件与公开合同；Bun 编译产物外置加载、Vite 资源与外部 SQLite；Worker 免费路线组装/部署；示例插件双宿主登录取流；DAV/Range 与三端挂载 | 给出真实结果、版本与支持矩阵；部署切换和免费额度限制明确 |
| P1 核心与示例插件 | 通用实例、布局与快照；示例插件认证、分页、来源分类、音质/回退及真实元数据 | 不依赖来源特例即可生成完整一致视图，示例插件按公开合同工作 |
| P2 共用服务 | 插件管理、WebDAV、管理 API、隔离存储、错误与状态 | 安装/更新/移除可恢复，协议通过，OpenList 与 rclone 实播 |
| P3 WebUI | 插件/实例管理、声明式配置认证、目录树、保存刷新与诊断 | 新插件无需重编译前端即可完成管理流程 |
| P4 双端产品化 | 桌面启动器、外置插件与 rclone；Worker 资源路由与自动部署 | 三端点击启动与挂载，云端独立安装和运行兼容插件 |
| P5 发布验收 | 真实客户端、故障恢复、发行包、文档与许可 | 第 14 节通过，标明实际测试范围 |

阶段可在合同稳定后交错推进，不预估未经验证的工期。已对齐的需求与设计现由 [Codex 主线目标](../docs/codex-goal.md)承接完整实现与交付；当前处于 P4/P5 收尾，真实进展与未完成义务见[验收台账](../docs/verification.md)。
