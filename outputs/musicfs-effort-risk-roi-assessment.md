# MusicFS 剩余工作量与方案复盘

更新日期：2026-10-20。依据：[统一需求 FR01—FR25](musicfs-requirements-and-technical-design.md)、[验收台账](../docs/verification.md)与当前源码。本文保存当前估算和推进取舍；历史固定平台估算保存在 Git 基线 `bfee998`，不再与当前估算并列生效。数值是工程判断，不是实测速度或交付承诺。

## 核心需求与当前进度

交付一个插件式只读音乐文件服务：WebUI 安装插件、配置认证独立实例、组织目录，以 DAV 接 OpenList/普通播放器；桌面随包 rclone 管理本地/远程挂载；普通免费 Worker 路线优先、独立部署并在插件变更时自动发布。网易云与 QQ 是完整双宿主示例；来源内容、认证和音质留在插件，其他插件无须具备音乐平台全部能力。

当前已进入**P4/P5收尾，完整交付尚未成立**。主干业务及双宿主正式入口可用；目录失败/磁盘不足、退出授权、桌面网络设置和大目录分页已补齐。真实云端自行发布、双示例授权及读取、独立作者接入、核心/页面升级保留插件均已有证据。“已实现”不等于跨宿主/系统验收完成；目标系统、示例尚缺的真实流程和免费计划结论继续分别记账。

| 用户旅程 | 当前可确认结果 | 剩余主要缺口 |
|---|---|---|

## 近期问题与深层原因

| 观察 | 核实结论 | 更有效的处理 |
|---|---|---|
| 新增内容似乎没有刷新出来 | 数据在微信账号，原先登录手机 QQ；新增收藏为专辑，接口枚举的是收藏歌单；曲目数与可导出文件数也不同 | 核对账号、内容对象和实际文件三个维度；保留通用计数，不能把返回空列表直接判成缓存或权限故障 |
| 刷新按钮未覆盖已浏览内容 | 按钮只请求 roots，已有目录快照仍被复用；这是独立复现的问题，不能冒认为上次账号报告的唯一根因 | 已由 library 统一实现实例刷新和单目录刷新；来源不承担用户刷新范围编排 |
| SDK facade 后续不断补原始接口 | 规范化 facade 会丢掉来源角色/顺序或未暴露取消；“支持 serverless”不等于满足当前插件合同 | 在每个插件内集中使用固定 SDK 的必要接口和实例传输，不扩建另一套通用平台 SDK，不修改上游算法 |
| 轻量列目录仍逐曲探测音频 | DAV 的展示属性和真实音频描述未分开；stat 路径又重复枚举整个父目录 | 按实际属性取元数据、复用当前列出的目标、只给冲突名称散列；先减少工作，再决定并发/缓存 |
| 网易云喜欢第二页被判为重复数据 | 100个歌曲ID返回102行，实际是同曲standard/MP3和lossless/FLAC；歌曲身份与实际文件表示混淆 | 插件按目标音质与完整表示选择，不按曲ID盲目判重；同实际引用可合并，真实冲突仍失败 |
| 大集合本地成功但云预算不成立 | 真实4158曲42页，当前插件每页4个来源请求约168；完整分页被塞进同次HTTP，DAV allprop还逐文件探测 | library持久分步、完整后发布；插件减少重取；单独收敛文件描述路径，不以并发重置预算 |
| 首条本地链路后持续深挖 QQ | 执行顺序偏向立即可验证的局部成功，最不确定的云发布、第二来源和挂载仍未闭合 | QQ 样本不再成为全局串行门槛；切换为三个可审阅交付包，尽早完成高风险宿主旅程 |
| allprop仍逐文件读来源与DB | 列表准备和内容读取边界未落实到接口；已有解析结果未随快照保存 | API0.1.3完整info与statMany已落地，真实来源/正式D1验证；旧插件保持原语义 |
| 请求数量下降后仍不能承诺免费云端 | XML/散列/序列化是另一条O(N)CPU成本，网络限额与CPU不能混为一项 | 已有正式workerd热点和XML投影/命名/SQL快照头减法；下一验证描述派生量的准备时机，不把本地改善写成云配额通过 |
| 认证、冷目录和读客户端交接没有完整闭环 | 管理请求可推进准备，普通DAV客户端不会调用管理step；202受理也不等于目录可读 | 已复用现有来源刷新/目录预览入口完成本地OpenList/mpv实测；使用说明明确冷准备与客户端缓存刷新 |
| FR22被“后端已拒绝不兼容”覆盖 | 已有服务端规则，但原安装弹窗没有安装前展示API范围和宿主兼容信息 | 共用归档解析和semver规则提供只读检查，用户审阅后安装；安装仍重新校验，不建暂存平台 |
| 插件声明了迁移钩子但更新仍拒绝schema变更 | 接口存在不等于生命周期已实现；与已经执行的数据库迁移混淆 | 已以v1→v2正式桌面/本地D1切片补齐；Worker须新调用持精确候选模块，不扩任意迁移图 |
| SDK能续期但插件从未保存新令牌 | 平台机制、实例持久化和跨控制器并发被混为SDK一个职责；SDK内存表不能跨isolate | 插件复用原生轮换并保存检查间隔；sources只按需取得实例短租约，两驱动共同SQL保存结果，普通读取仍并发 |
| 网易云存在login/refresh端点就计划定时调用 | 端点存在不等于适用于当前登录凭据；固定SDK文档明确排除二维码Cookie | 保留有效Cookie，明确失效后重登，不增加无效定时刷新或新登录渠道 |
| 插件confirmed恢复测试通过，正式宿主仍按旧QR期限结束 | 授权完成、账号资料补全和UI步骤期限是不同事实；只测插件层遗漏宿主合同 | 两示例现已凭据就绪即完成、资料按内容需要补齐；正式API/资料失败后重试及QQ实际workerd包已验，不扩通用认证状态机 |
| 桌面异常退出后立即重开失败 | proper-lockfile需30秒判陈旧，前台原只等15秒，宿主只试一次；整体时间合同不一致 | 已协调锁等待/健康后台识别，实际SIGKILL立即重开约32秒恢复，保留凭据和端口 |
| 多份摘要同步计数、项目长期无提交 | 状态记录与历史证据混杂，缺少可回退检查点 | 台账保存当前事实；计划只排下一交付；历史验证保留当时版本。基线已提交，后续按完整语义变更提交 |
| 各宿主目录构建通过仍不能作为一套发行物 | 不同时间生成的页面/插件可能混用；原Worker包有注册模块但没有供用户安装的ZIP，随包步骤无法闭合 | 共用内容身份与归档入口，原ZIP独立随包；实际解压和作者从零接入验收，构建数量不抵扣使用结果 |
| 保留旧目录却在重开页面后看不出失败 | 目录error已持久化，但为减少读取而新增的快照头投影丢掉了error；页面只看最近任务，另一目录成功后原失败提示消失 | 复用同一error贯通共同SQL、DirectoryStatus和页面；A失败→B成功→重建后A仍标旧内容，A成功才清除，不新增状态表或缓存 |
| 所有FR长期都是“进行中” | 把真实环境缺口与缺实现合并，台账又使用“其余档位/完整交错”这类无有限出口的词 | 分开实现与验证；按六类音质行为、四种旧写触发和每示例每宿主至少一种扫码收口，不生成全排列测试 |
| 反复验证局部链路，仍漏掉退出授权及局域网设置 | FR编号摘要没有完整覆盖页面范围、管理路由和使用场景中的明确要求；“重新授权”不等于“退出”，远程挂载也不等于其他设备能访问桌面DAV | 对照完整用户旅程补正式入口，复用来源代际和宿主监听；不新增认证平台或全局设置框架 |
| 已知FLAC可读取但旧DAV目录需重新准备 | 快照绑定安装修订，纯许可更新也改变包修订；来源样本可用不等于当前完整目录已发布 | 保留已有失效规则，冻结版本后集中准备/验收；本轮只验证一个历史样本小Range，不改快照身份或新增缓存兼容协议 |
| 更新核心可能覆盖已安装插件 | 初始构建物描述初始代码集合，D1安装和云端模块会在用户安装后变化；仅保留数据库不足以保留可执行插件 | 已从实际云端模块组装新核心/页面，保留精确注册表和修订；一次升级核对通过，不新增运行机制 |
| 台账仍要求真云人为制造响应丢失 | 需求要求失败恢复与切换影响，没有要求每个故障在每个环境重演；正式D1+SDK已证明核对及不重复上传 | 保留机制证据和真云未人为制造的边界；仅补真实切换观察，不为勾选同一故障重复发布 |

## 架构取舍与减法

2026-10-20补充复盘：近期把第三方发行材料扩大为上游Bun/JSC源码重建和完整依赖闭包调查，已超过当前产品开发所需。共因是没有区分已确认需求、发行资料缺口与可选工程证明，导致“全部完成”不断衍生待办。停止扩大该调查；保留已有材料及真实未完成项，不据此豁免必要许可，也不把上游源码重建自行升级为验收门禁。后续新增工作须说明对应的用户行为、已复现问题或明确发行要求；仅有结构可能性时先记录，不直接实施。

共因是模块能力先于正式用户旅程收口：插件自己的成功不一定是宿主认证成功，后台规则存在也不等于界面满足需求；只看FR摘要又会遗漏正文中的退出与局域网配置。本地能够重复验证的工作比真实环境更容易持续推进，造成测试和研究越做越细、用户入口却仍缺失。后续每轮以一个可观察用户行为或发行出口组织工作，对照对应的完整需求正文；外部环境缺口单列，避免用局部测试/交叉构建的增加抵扣它。

本次有界源码复核没有发现需要整体重划领域或立即换库的证据。更深的问题是“已实现、机制已证、真实环境已证、发行已更新”四个事实未充分区分，导致旧待办和估算长期保留、每个细节都再生成一项验收。现在以需求中的用户行为为完成粒度：库或宿主适配修正在同一Module收口，平台边界只补必要差异；没有相关代码变化或实际失败，不重启整条矩阵。免费计划仍是产品可行性缺口，其他OS仍是环境缺口，均不能靠更多本地测试抵扣。

本轮进一步删除跨需求重复记账：FR03/13/14/19/20/21/23已具备各自合同的证据，最终资料归FR16、免费资源/切换归FR25、原生挂载归FR10—12，不能把这些缺口复制成所有功能的共同尾巴。六个真云分类列表以12次管理请求补齐；QQ收藏0是有效账号结果，无须人为制造非空集合。磁盘不足沿用正式错误边界验证，不要求物理写满磁盘；严格播放器参数和本机Pulse差异不再衍生产品门槛。

另一个更宏观的约束是普通免费Worker、大目录和动态来源适配同时成立的成本。已有本地热点证据，免费额度是否满足仍是待实测的产品可行性问题，不能靠继续拆模块或增加测试证明。未获得真实环境前保留当前已验证实现，不预建付费后端、通用缓存平台或新的部署服务；若实测确实不满足，再携具体结果讨论范围与方案。

保留 `extensions → 包/安装`、`sources → 实例/配置/认证`、`library → 快照/布局/文件` 的职责与 `library → sources → extensions` 依赖方向。当前没有必要重新划分领域、拆更多包或引入通用 Service/Manager 层。宿主负责存储、进程/挂载及发布，协议与页面只是调用适配。

本轮需要调整的是交付顺序和验收记账。目录失败展示、认证complete与当前失效分开、磁盘不足提示均已沿原Module补齐；现有状态和错误足以承载，不新增全局健康表、定时探活或认证平台。Schema默认值双写、registry少量生成重复留到下一次相关配置/格式修改再收敛，不单独开重构。

必须保留状态 CAS/代际、完整快照发布、失败保留、稳定出现身份及实际内容/Range 校验：它们直接实现已确认需求。减法针对重复工作和淘汰路线，不删用户已经确认的能力。

- 淘汰的 Nephele/Node 桥接五份诊断源码与三项专用开发依赖退出当前工程；原始试验和锁文件可从 `bfee998` 恢复。继续一套 Fetch DAV，XML、Range、ZIP、版本和表单机制分别复用已有成熟依赖。
- `fflate` 只保留为开发期独立 ZIP 编码器，验证产品 zip.js 的互操作；不维护第二套安装器。
- 普通目录缓存缺失读取与主动刷新要区分：前者合并重复工作，后者仍允许更新请求取代旧请求。现已按持久操作/实例与来源戳合并，数据库租约保证跨控制器不重复执行同一页，不另加进程缓存。
- SQLite/D1 的驱动差异是真实的，分页刷新已经提取共同SQL计划和行映射，原有短领域操作按需要继续收敛；不为消除两份短 Adapter 就引入 ORM 或通用仓储。
- 迁移激活已用一个跨领域用例及两驱动共同SQL计划落地；sources只准备候选，宿主只处理代码差异。复用原操作/租约和桌面唯一后台循环，不引入通用工作流、ORM、任意回滚图、依赖解析器、插件市场或VM。
- 会话续期只增加公开可选能力和sources内部协调模块；过期、重试和渠道由插件解释。SDK、WebCrypto、tough-cookie与原生取消负责现成机制，核心只承担实际需要的跨实例版本/持久化规则。无需新增认证平台或全局串行读取队列；没有实测并发问题前不引入p-limit。
- 不继续重复 DAV 候选研究、已通过的随机字节探针或所有理论交错。来源账号与格式样本有缺口时记录具体未验项，继续其他工作；不会把必要真实验收降成模拟通过。
- 发行工具复用zip.js、Bun构建清单及Vite内建许可输出，sample复用公开插件构建器；作者包仅保留公开类型和最小工具。没有新增发行框架、包管理协议或SDK服务。原递归复制整个node_modules的许可路径退出；实际依赖资料和运行时缺口分别记录。

## 需要前移的交付约束

## 执行节奏

先保存并验证可回退基线，完成当前有证据的局部减法；随后按 [实施计划](musicfs-implementation-plan.md)推进 Worker、桌面、网易云三个交付包。子代理只承担已明确的接口/文件所有权，主代理协调合同、合并和集成验证；避免并发改锁文件或反复构建生成文件。

验收按风险覆盖，不展开账号×音质×客户端×系统的全排列：共用状态/协议用必要夹具证明，真实来源覆盖实际格式/策略，目标系统重点验宿主差异，云端单独验传播与资源。新事实或相关代码变化才扩大回归；已确认能力仍全部保留。

提交按完整行为组织：基线、局部性能/工程减法、一个正式宿主用例、一个来源切片等。文档随相关行为提交；每个小改动不重复全部探针。类型/边界/必要回归检查通过后继续，只有新增代码、失败或未解疑点才扩大测试。
