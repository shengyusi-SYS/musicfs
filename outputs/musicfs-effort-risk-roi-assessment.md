# MusicFS 剩余工作量与方案复盘

更新日期：2026-10-20。依据：[统一需求 FR01—FR25](musicfs-requirements-and-technical-design.md)、[验收台账](../docs/verification.md)与当前源码。本文保存当前估算和推进取舍；历史固定平台估算保存在 Git 基线 `bfee998`，不再与当前估算并列生效。数值是工程判断，不是实测速度或交付承诺。

## 核心需求与当前进度

交付一个插件式只读音乐文件服务：WebUI 安装插件、配置认证独立实例、组织目录，以 DAV 接 OpenList/普通播放器；桌面随包 rclone 管理本地/远程挂载；普通免费 Worker 路线优先、独立部署并在插件变更时自动发布。网易云与 QQ 是完整双宿主示例；来源内容、认证和音质留在插件，其他插件无须具备音乐平台全部能力。

当前是**本地开发 alpha 已成立，完整产品交付尚未成立**。25 项 FR 中，21 项已有部分实现和验证，4 项尚未开始（FR10—FR12 挂载及 FR25 自动部署）；不能把“进行中”按整项计成完成。

| 用户旅程 | 当前可确认结果 | 剩余主要缺口 |
|---|---|---|
| 安装、实例、认证、配置、目录布局 | 共用 WebUI、独立最小插件、QQ 手机/微信扫码与重启恢复已有证据 | 正式启动凭据、完整生命周期、作者交付 |
| 内容与读取 | QQ 分类、音质策略、真实 MP3/M4A、DAV/rclone 范围字节已有证据 | 网易云、续期、其余真实样本和客户端实播 |
| Worker | 本地 workerd/D1、打包 QQ ESM 的真实会话恢复已验 | 正式入口、模板、后台发布、云出口及免费资源表现 |
| 桌面 | 开发服务、Linux 编译后外置插件/重启探针已验 | 启动器、挂载管理、四个目标发行物和实机 |

## 剩余工作量

口径：一名熟悉 TypeScript/HTTP 的开发者，正常使用 AI 辅助，一人日约 6—8 小时有效工作；按剩余正式实现、各自验证及集成估算，不重复计费同一项验收。已有实现继续复用。外部扫码、Cloudflare 授权、目标机器和驱动环境等待不计入人日。

## 近期问题与深层原因

| 观察 | 核实结论 | 更有效的处理 |
|---|---|---|
| 新增内容似乎没有刷新出来 | 数据在微信账号，原先登录手机 QQ；新增收藏为专辑，接口枚举的是收藏歌单；曲目数与可导出文件数也不同 | 核对账号、内容对象和实际文件三个维度；保留通用计数，不能把返回空列表直接判成缓存或权限故障 |
| 刷新按钮未覆盖已浏览内容 | 按钮只请求 roots，已有目录快照仍被复用；这是独立复现的问题，不能冒认为上次账号报告的唯一根因 | 已由 library 统一实现实例刷新和单目录刷新；来源不承担用户刷新范围编排 |
| SDK facade 后续不断补原始接口 | 规范化 facade 会丢掉来源角色/顺序或未暴露取消；“支持 serverless”不等于满足当前插件合同 | 在每个插件内集中使用固定 SDK 的必要接口和实例传输，不扩建另一套通用平台 SDK，不修改上游算法 |
| 轻量列目录仍逐曲探测音频 | DAV 的展示属性和真实音频描述未分开；stat 路径又重复枚举整个父目录 | 按实际属性取元数据、复用当前列出的目标、只给冲突名称散列；先减少工作，再决定并发/缓存 |
| 首条本地链路后持续深挖 QQ | 执行顺序偏向立即可验证的局部成功，最不确定的云发布、第二来源和挂载仍未闭合 | QQ 样本不再成为全局串行门槛；切换为三个可审阅交付包，尽早完成高风险宿主旅程 |
| 多份摘要同步计数、项目长期无提交 | 状态记录与历史证据混杂，缺少可回退检查点 | 台账保存当前事实；计划只排下一交付；历史验证保留当时版本。基线已提交，后续按完整语义变更提交 |

## 架构取舍与减法

保留 `extensions → 包/安装`、`sources → 实例/配置/认证`、`library → 快照/布局/文件` 的职责与 `library → sources → extensions` 依赖方向。当前没有必要重新划分领域、拆更多包或引入通用 Service/Manager 层。宿主负责存储、进程/挂载及发布，协议与页面只是调用适配。

必须保留状态 CAS/代际、完整快照发布、失败保留、稳定出现身份及实际内容/Range 校验：它们直接实现已确认需求。减法针对重复工作和淘汰路线，不删用户已经确认的能力。

- 淘汰的 Nephele/Node 桥接五份诊断源码与三项专用开发依赖退出当前工程；原始试验和锁文件可从 `bfee998` 恢复。继续一套 Fetch DAV，XML、Range、ZIP、版本和表单机制分别复用已有成熟依赖。
- `fflate` 只保留为开发期独立 ZIP 编码器，验证产品 zip.js 的互操作；不维护第二套安装器。
- 普通目录缓存缺失读取与主动刷新要区分：前者合并重复工作，后者仍允许更新请求取代旧请求。先做当前进程内、按实例与来源戳区分的必要合并；是否需要跨 isolate 协调由真实 Worker 结果决定。
- SQLite/D1 的驱动差异是真实的，相同 SQL 谓词/行映射存在重复。下次修改这些操作时提取必要公共片段；不为消除两份短 Adapter 就引入 ORM 或通用仓储。
- 迁移激活属于已确认更新需求，仍需完成；不提前实现任意回滚图、依赖解析器、插件市场、热插拔 VM 或多租户框架。
- 不继续重复 DAV 候选研究、已通过的随机字节探针或所有理论交错。来源账号与格式样本有缺口时记录具体未验项，继续其他工作；不会把必要真实验收降成模拟通过。

网易云先验证 [固定 SDK 的必要模块与原样加密](research-netease-worker-sdk.md)。保留现成密码实现及公开回调，实例 Fetch/Cookie/错误由插件适配；不要为 SDK 整个服务端入口增加 Node 兼容补丁。只有实际产物和真实请求失败才扩大候选调查。

## 需要前移的交付约束

普通 Worker 免费路线要求测量**一次请求内的工作量**。当前完整目录分页、音质解析和实例多目录刷新会在同一 HTTP 调用中连续执行；本地 workerd 成功不能证明云端免费资源可承受。官方当前限制包含每次 HTTP 请求 10 ms CPU、50 次外部子请求，D1 等内部请求另有限额。[官方限额](https://developers.cloudflare.com/workers/platform/limits/)、[子请求限制说明](https://developers.cloudflare.com/changelog/post/2026-02-11-subrequests-limit/)

先减掉无用 stat/重复命名，再用代表性集合测量 CPU、外部请求和 D1 调用。若必要旅程确实超限，采用分步继续的刷新、暂存分页结果并在完整成功后发布；该用例由 library 拥有，执行差异留在宿主。不得仅提高本地 budget 或加并发来冒充符合免费限额，也不因此擅自增加付费服务。

桌面挂载的系统依赖、四目标运行和真实云出口同样前移。当前环境无 `/dev/fuse`，Windows/macOS 和 Cloudflare 测试资源尚未验证；先交付可操作程序与精确步骤，再请求相应协作，等待期间继续其他工作。

## 执行节奏

先保存并验证可回退基线，完成当前有证据的局部减法；随后按 [实施计划](musicfs-implementation-plan.md)推进 Worker、桌面、网易云三个交付包。子代理只承担已明确的接口/文件所有权，主代理协调合同、合并和集成验证；避免并发改锁文件或反复构建生成文件。

提交按完整行为组织：基线、局部性能/工程减法、一个正式宿主用例、一个来源切片等。文档随相关行为提交；每个小改动不重复全部探针。类型/边界/必要回归检查通过后继续，只有新增代码、失败或未解疑点才扩大测试。
