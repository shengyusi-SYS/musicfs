# WebUI 方向变更评估

日期：2026-10-18  
状态：WebUI 方向与本轮三个功能边界已确认；已并入 [统一需求与技术方案](musicfs-requirements-and-technical-design.md)。本文保留变更依据，实际音质标注、回退去重等细则随统一草案审阅。

2026-10-20 范围修订：本文是从 CLI 转向 WebUI 的历史评估。当前采用 Bun 桌面宿主和可安装来源插件，WebUI 增加插件/实例管理及通用声明式配置认证；音质、扫码和歌单规则属于示例插件，不属于所有来源或全局设置。Worker 插件变更已接受后台自动部署。下文旧 Node 后台、固定双平台集成及默认分类均不能覆盖 [统一方案](musicfs-requirements-and-technical-design.md) 的新决定。

## 1 结论

新方向可行：用一套 WebUI 取代面向用户的 CLI，提供平台登录、设置和目录布局编辑；桌面与 Worker 继续共用 TS 业务核心、平台模块和 WebDAV。

桌面系统挂载需要本地后台启动内置 rclone。用户已确认点击启动器打开本机 WebUI，再在页面操作挂载、卸载；普通网页本身没有系统虚拟盘挂载接口。此处的本地后台不是用户需要操作的命令行。

Worker 可以同时提供 WebUI、管理 API 和 WebDAV；扫码登录、重新登录、设置和目录布局都能从浏览器完成。Worker 仍不运行本机挂载。

## 2 已确认的新需求

| 项目 | 当前要求 |
|---|---|
| 用户入口 | 取消用户 CLI，集成 WebUI |
| 设置 | 部分配置通过 WebUI 设置项修改；具体字段按已确定能力收敛 |
| 目录布局 | WebUI 提供可拖拽树结构，由用户选择内容并构建层级 |
| 默认布局 | 按平台分为网易云音乐与 QQ 音乐，各自包含发现、你的歌单、收藏的歌单 |
| 单版本模式 | 只能选择一个音质档位，每首歌曲最多显示一个对应文件 |
| 多版本模式 | 可选择多个音质档位，同一歌曲显示多个对应文件 |
| 音质缺失 | 提供隐藏与自动回退设置，用户自行选择 |
| 无完整播放权限 | 默认隐藏，在状态中报告数量与原因，不导出 JSON 占位文件 |
| Worker 登录 | 通过 WebUI 完成，具体平台在 CF 的真实流程仍待验收 |

临时网络失败、平台暂时限流和尚未探测音频大小，不等同于“平台确认无完整播放权限”。保留最近成功目录并报告失败状态的原则仍然适用。

## 3 WebUI 与双端运行方式

采用以下已确认的桌面交互结构，具体打包方式在实现时验证：

```text
桌面
  可点击启动器 → 本地 Node 后台
                    ├── 提供 WebUI、管理 API、WebDAV
                    ├── 内嵌网易云、QQ 接口
                    └── 启动和管理内置 rclone → 本机盘符或目录

Cloudflare
  同一部署 → WebUI 静态资源 + Worker
                               ├── 管理 API、WebDAV
                               ├── 内嵌网易云、QQ 接口
                               └── D1 中的账号、设置与目录布局
```

这条桌面路线不要求引入 Electron 或自行开发原生 GUI，系统浏览器可以显示同一套 WebUI。本地后台可以通过 Node 的 `child_process.spawn()` 管理 rclone。[Node 子进程文档](https://nodejs.org/api/child_process.html)

普通浏览器的 File System API 允许用户选择并访问现有文件或目录，不提供创建系统虚拟盘和启动 rclone 的标准能力；“保留一键挂载就需要本地执行部分”是据此作出的架构判断。[MDN File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)

Cloudflare 官方支持静态资源与 Worker 脚本一起部署。建议 `/` 提供 WebUI，`/api/*` 和 `/dav/*` 交给 Worker；配置路由优先级，防止 SPA 回退把 WebDAV 的 PROPFIND 请求变成 HTML 页面。[Static Assets](https://developers.cloudflare.com/workers/static-assets/)、[Worker 路由](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)

取消产品 CLI 不改变平台接口的 Worker 适配工作，也不意味着浏览器直接访问网易云或 QQ 的全部接口。浏览器调用本项目后台，由后台执行平台协议并保存登录状态。

## 4 WebUI 扫码登录

完整流程可以是：打开账号页 → 选择平台与可用扫码通道 → 后台创建二维码 → 页面显示二维码 → 用户在手机确认 → 页面查询状态 → 后台保存会话 → 页面显示登录成功。

网易云候选项目已有浏览器扫码示例：获取 key、显示二维码、定时查询并处理成功状态，因此不需要依赖终端才能完成页面交互。[锁定提交中的 qrlogin.html](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/19c7dad6db7d660954c7a615a686ff0acb030f91/public/qrlogin.html)

QQ 候选项目提供获取二维码和查询状态的路由，二维码为可直接展示的 data URL。Worker 无中继时可以提供手机 QQ 的 HTTP 扫码及微信扫码；QQ 音乐 App 扫码才涉及额外中继。页面按当前后台返回的通道展示，不因改为 WebUI 而新增强制中继。[扫码流程](https://github.com/yakult-green-tea/qq-music-api/blob/e7dff2e1e2496780702bda528362edbdaf6bbf6e/docs/README.md)、[通道实现](https://github.com/yakult-green-tea/qq-music-api/blob/e7dff2e1e2496780702bda528362edbdaf6bbf6e/src/serverless/qrRuntime.ts)

以上是官方运行能力与已有源码核查。尚未以真实账号完成本项目的 Worker 登录与取流验收，不能把页面流程可实现说成所有平台接口已经在 CF 上通过。

## 5 目录树设计评估

拖拽树适合本项目，因为用户要组织的是导出目录。推荐把“目录布局”与“平台内容”分开：布局保存位置、层级与显示名称；内容源继续从平台读取歌曲与歌单。

建议界面有可选择的内容源和目标目录树。用户创建分组、把内容源拖入目标位置，并查看导出路径。以下仅是展示可构建层级的例子，不是额外预设目录：

```text
/
├── 我常听的/
│   ├── 网易喜欢的音乐/   ← 网易云喜欢的音乐
│   └── QQ喜欢的音乐/     ← QQ喜欢的音乐
└── 发现/
    ├── 网易每日推荐/     ← 网易云每日推荐
    └── QQ每日推荐/       ← QQ每日推荐
```

首版操作目录和内容源节点，曲目随来源同步；例如把“你的歌单”拖到某处后，平台新增歌单在刷新后自动出现在该处，不要求再次逐个拖入。拖动导出节点不会修改云端歌单，此边界已由用户确认。

目录布局应单独保存，平台刷新不能覆盖用户安排。布局变化后，WebDAV 路径随之变化；WebUI 可以提供保存前预览。第三方客户端的目录刷新按实际缓存行为处理，不额外承诺平台变化立即出现在所有客户端。

## 6 单版本与多版本音质

两种模式共用“歌曲 + 音质版本”的读取模型，只改变展示哪些文件。单版本的选择控件限制为一个，多版本允许多选；可选档位由平台实际支持的音质确定，不固定为之前草案中的三个名称。

例如选择高品质与无损，多版本目录可以显示：

```text
0001 - 歌手 - 歌名 [高品质].mp3
0001 - 歌手 - 歌名 [无损].flac
```

音质标识用于区分用户选择的版本，不是此前提出的内部技术版本号。扩展名以实际编码容器为准，同一扩展名的不同档位也要能区分。多版本使用平台现有音频，不因这项需求引入转码。

曲目数和音频文件数分别统计：同一曲目导出两个音质时，仍是一首歌、两个音频文件。缓存与音频解析也必须区分音质，不能把两个档位当作同一文件。

用户已选择把缺失行为做成设置：隐藏时省略缺失档位；自动回退时向下查找可用完整音频。回退按实际音质命名，不把较低档位标成目标高档位。多版本中若多个目标回退到同一份实际音频，建议合并为一个文件。细则已放入统一草案供整体审阅。

## 7 本轮确认结果

| 编号 | 问题 | 用户决定 |
|---|---|---|
| Q5 | 桌面采用启动器、本地后台和 WebUI 挂载？ | 是 |
| Q6 | 拖拽目录与内容源，动态更新，仅改变导出层级？ | 是 |
| Q7 | 音质不可用如何处理？ | 提供隐藏或自动回退设置 |

目前没有新的必须追问的功能边界。组件库、缓存参数、平台兼容性与实际回退顺序由技术设计和验证处理，新增细则在统一草案中清楚标示。
