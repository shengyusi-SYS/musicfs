# 网易云示例插件（开发预览）

此插件通过与第三方相同的公开合同安装、配置、认证和访问文件。核心、WebUI 与宿主不需要网易云分支。平台协议来自固定 `NeteaseCloudMusicApi@4.32.0` 的必要模块与原样密码实现，不启动另一个 API 服务，不修改 SDK 源文件。

## 当前入口

在仓库根目录运行：

```sh
bun run scripts/build-netease.ts
bun test tests/netease-plugin.test.ts
bun run scripts/probe-worker-netease.ts
```

作者构建输出 `dist/netease/org.musicfs.netease.zip`，安装到桌面服务后新建网易云实例，选择“来源授权”并开始扫码。二维码由共用界面呈现，使用网易云音乐 App 扫描并确认。实例 Cookie 只存为插件私有状态；确认后的会话会先经过账号状态接口核实。每次调用持有自己的 CookieJar、Fetch 与 AbortSignal，取消/旧结果写入由宿主公开合同控制。

Worker 产物保留静态 `node:crypto`、`node:zlib` 导入，部署需要适当的 Node 兼容日期/开关。作者构建用静态导入桥接上游 CommonJS 内置模块调用，不替换密码算法。`tough-cookie` 负责 Cookie 的域名、路径、过期和持久化，Fetch 的 `Headers.getSetCookie()` 提供独立响应头；没有自行按逗号拆 Cookie。

会话恢复与失效遵循扫码登录的实际能力。固定 [4.32.0 随包文档](https://unpkg.com/NeteaseCloudMusicApi@4.32.0/public/docs/home.md)的“刷新登录”段明确 `login/refresh` 不支持二维码登录的 Cookie，因此插件不定时调用此接口，也不承诺永久免扫码。有效 `MUSIC_U` 缺失或到期时，在请求受保护内容前返回“需要重新认证”；来源明确返回未登录状态或账号状态中的 `profile: null` 时，也回到共用扫码流程。账号响应缺字段、编号损坏、网络或服务暂时失败均保留原会话，避免把临时故障当成授权失效。

同次调用的 Cookie 更新由独立 CookieJar 合并，即使后续业务失败，也通过 `nextPrivateState` 提议保存；宿主仍按实例版本条件提交，旧调用不能覆盖新授权。认证确认后的临时账号查询失败会保留已收到的凭据，后续重试不重复消费二维码。

## 当前能力与缺口

当前预览提供喜欢、每日推荐歌曲、自建歌单、收藏歌单和每日推荐歌单的目录实现。系统喜欢歌单根据 `specialType: 5` 识别；自建/收藏按原生 owner 编号分类。歌单详情以完整 trackIds 为基准，分页详情按原顺序重组并保留重复位置；连续页会核对曲目序列摘要。未完整返回、分页期间变化及暂时网络错误返回失败，由核心保留最近成功目录。

alpha.4 把首次确认的喜欢歌单编号放进绑定实例的分页游标，后续页直接复用；旧游标没有该字段时仍正常定位。每页完整 trackIds、trackCount 和序列摘要检查保持不变，也没有全局或跨实例缓存。受控传输回归中，标准单版本/隐藏、用户歌单首批即可定位的基线从每页 4 次来源请求变为首次 4 次、后续 3 次；这不是实际多档、CPU 或免费 Worker 整体预算已通过的证据。

音质是实例配置。alpha.3 提供标准、极高、无损、Hi-Res 的单版本/多版本，以及隐藏/向下回退策略。`quality` 是单版本目标，保留旧实例原值；`audio.mode` 选择模式，`audio.qualities` 只在多版本生效，`audio.missingQuality` 决定缺失处理。旧配置即使只有 `quality: "exhigh"`，仍按极高、单版本、隐藏运行；切换多版本后使用独立的多目标列表。

回退顺序为 Hi-Res → 无损 → 极高 → 标准。原生响应直接返回较低实际档位时，也只有回退策略允许使用。文件标签和扩展名以实际版本生成；多个目标取得同一实际引用时每个曲目位置只导出一次，重复曲目位置仍各自保留。曲目、文件、隐藏曲目、缺失目标、回退目标和合并重复版本分别统计。试听不作为完整版本；暂时请求、认证、限流和解析错误直接失败，不通过回退掩盖。已引用文件的读取只重新解析该实际版本，不能因当前回退设置换成其他字节。

alpha.3 已在真实账号与本地 workerd 复测：每日30曲，多目标无损/标准+回退导出35文件（极高17、标准18），统计一致；真实极高MP3的完整/范围/rclone通过。该阶段没有取得真实FLAC，因此不表示全部档位已验，后续结果以[实际来源记录](../../docs/verification/p2-netease-source.md)为准。当前支持范围之外的特殊音效/格式、真实会话过期后重登，以及免费 Worker 下的新多目标请求预算仍待后续收口。

alpha.2 处理原生音频响应中“同曲多个实际版本”的情况：先核对请求编号均有回应，再选择所配置音质的完整版本；格式名仅做大小写规范。其他音质不参与隐式回退；同一目标音质的候选仅在编号、音质、格式、MD5 和大小全部一致时合并，临时 URL 可以不同。缺少/未知编号或目标音质存在冲突实际文件仍失败。

文件引用包含歌曲编号、实际格式、音质、MD5 与大小，包含短期音频 URL 的上游结果不进入稳定引用。stat 和 open 都重新解析地址，再向音频源执行真实 Range/GET，核对总大小、请求范围和 Content-Length，直接交付可取消的响应流。

## 验证口径

聚焦测试使用真实 SDK 业务回调/加密代码与可控 Fetch 响应，证明配置、独立 CookieJar、确认后状态保存/恢复、认证暂时失败、取消、目录归属/顺序、试播隐藏、重新解析地址及范围读取。模拟测试不能替代实际账号、权限和真实音频测试。

会话回归另外覆盖缺失/过期 Cookie 在发送业务请求前要求重登、明确未登录后重新扫码、畸形或临时账号响应保留会话，以及正常响应和后续失败响应的 Cookie 更新均能保存并在恢复后复用。这些是受控传输证据，不表示已等待真实 Cookie 自然到期或完成真实 Worker 的失效重登。

alpha.3 定向回归另外覆盖旧极高配置保持原义、多版本不受旧单目标限制、相同实际文件合并/重复位置、不同实际文件同时导出、回退的实际标签、读取不回退，以及试听/错误边界。主线已统一构建安装，并完成上述实际多目标与workerd验证，其余档位仍待验。

双宿主探针读取实际预构建产物：Bun 直接取得真实二维码；本地 workerd 经正式管理 API 创建两个 D1 实例并取得真实二维码。它不自动完成手机授权，也不证明云端部署、免费 CPU 预算或真实播放已经通过。

已有真实授权实例后，可显式选择只读桌面数据库与实例编号，将该私有会话临时导入本地 D1 验证状态恢复和每日推荐目录：

```sh
MUSICFS_NETEASE_TEST_STATE_DB=/absolute/path/state.sqlite \
MUSICFS_NETEASE_TEST_INSTANCE_ID=instance-id \
bun run scripts/probe-worker-netease.ts
```

探针只输出计数与通过状态，临时 D1 完成后删除。不要把账号 Cookie、私有状态、二维码或真实账号截图放入仓库。

SDK 候选与取舍见 [研究记录](../../outputs/research-netease-worker-sdk.md)。发布包附 MIT 插件许可和实际打包依赖的第三方许可。
