# 网易云音乐示例插件

此插件通过与第三方相同的公开合同安装、配置、认证和访问文件。核心、WebUI 与宿主不需要网易云分支。平台协议来自固定 `NeteaseCloudMusicApi@4.32.0` 的必要模块与原样密码实现，不启动另一个 API 服务，不修改 SDK 源文件。

版本及接口兼容范围见 [manifest.json](manifest.json)；配置版本2、私有状态版本1。默认以200首/页发布完整目录，批量确认歌曲详情与实际播放版本；MP3/FLAC/M4A 每首最终大小是上游准确大小加1MiB，不取全库封面、歌词或音频。清单完成即可直接挂载和扫描，HEAD不准备，首个GET只处理所选歌曲。剩余空间按格式合法填充，Range仍对应真实最终字节，不转码、不缓存整曲。可选命名字段直接来自这些清单资料，用户模板不增加平台请求。

`@musicfs/audio-tags` 为来源实际返回的MP3、FLAC、M4A构造最终文件的区段计划，保留声音数据；文件描述和读取始终使用准确的最终大小与内容身份。歌曲和专辑详情提供多位歌手、专辑、专辑艺术家、发行日期及原专辑曲号/碟号，缺失字段留空；曲号不使用歌单序号。封面及原文/译文/罗马音歌词按上游返回补充，不刮削其他平台。第三方插件可保持透传，不需要使用补标签能力。

alpha.11已有的请求减法继续用于文件准备（当时批量100首，alpha.13提升至200）：通过原SDK的通用`api`模块调用富歌曲详情，返回的专辑艺术家和日期避免逐专辑查询，缺失资料仍可回补；已知图片CDN分片按同一资源共享封面；MP3准备可用一次多Range请求读取头尾。MIME解析使用固定`@remix-run/multipart-parser 0.16.5`，容纳已实测的CDN外层类型错误，不手写解析器。单曲原生版本核对、取消、429冷却与精确最终文件保持不变。此前接口证据见[冷准备验证](../../docs/verification/netease-cold-request-reduction.md)。

认证行为沿用alpha.7：扫码得到有效MUSIC_U即完成授权，不再把额外账号资料查询放在二维码步骤内。昵称不是登录条件；个人歌单首次需要UID时查询并保存，根入口已有的账号查询也会更新身份。换号先清旧UID/昵称，避免后续内容误用旧账号。

补充专辑资料、封面、歌词和稳定歌曲详情默认缓存365天，`metadataCacheDays: 0`长期保留；空或缺失结果最多30天。修改保留天数保留既有目录和缓存，新期限用于后续取得的资料。目录菜单可显式重新获取音乐资料，同一任务跨页复用新封面和专辑资料，完成后发布新表示，旧引用保持原字节。临时扫描检查点仍保留1天，播放版本不超过原生期限且最多5分钟，歌单名单和每日推荐更新策略不变。

v4引用保存原表示、紧凑`tag-seed`、扫描代次与时间；首次GET原子保存永久计划，后续资料缓存到期不会改变同一引用的字节。未来刷新在ready索引仍有效时复用已准备引用；全部资料长期有效时ready也长期保留，仍含缺失资料时按最早到期时间重试。未读取文件不保存1MiB空白，而是在读取所需区间时生成。封面独立共享，计划和资料不进入私有授权状态；`open`重新定位同一上游版本，流式拼接准确Range。旧v3延迟引用、v2计划引用及v1透传仍可读取。

预算包含新增标签和容器结构，不承诺任意资料都放得下。超预算仅对该首走精确准备，旧读取返回`content_changed`并提示刷新，下一次目录使用新的准确大小；不截断歌词/封面，不改变旧引用已公布大小。M4A支持当前普通单moov布局，分片MP4仍明确不支持；网易云不增加APE等上游未提供格式。缺少缓存时新目录准备明确返回不支持；没有`putIfAbsent`的合同测试/旧宿主实现维持原v3延迟准备路线。

alpha.12本机隔离冷缓存实测：4,159首完整清单用时24.945秒、42页、87次平台调用（歌单列表1、成员名单2、详情42、播放版本42），导出1,915文件、隐藏2,244曲目，没有生成标签计划。首个单文件HEAD为306.74毫秒、热HEAD为2.62毫秒、仅名称DAV请求为24.71毫秒。它们不是全库标签准备或播放器完整扫描耗时；环境与范围见[两阶段验证](../../docs/verification/deferred-catalogue.md)。下文旧版本证据不自动延伸到当前全部能力。

alpha.13另以两次真实调用确认200首详情/播放版本全部返回，约322/421ms；随后离线4,000首验证20页、43次基础调用，本地workerd/D1的200首清单一页26SQL、精确准备最多38SQL/步。没有再次真实整库测速，不把请求数减少写成已测耗时减半。

## 当前入口

在仓库根目录运行：

```sh
bun run scripts/build-netease.ts
bun test tests/netease-plugin.test.ts
bun run scripts/probe-worker-netease.ts
```

作者构建输出 `dist/netease/org.musicfs.netease.zip`，安装到桌面服务后新建网易云实例，选择“来源授权”并开始扫码。二维码由共用界面呈现，使用网易云音乐 App 扫描并确认。实例 Cookie 只存为插件私有状态；后续内容读取独立处理账号状态。每次调用持有自己的 CookieJar、Fetch 与 AbortSignal，取消/旧结果写入由宿主公开合同控制。

Worker 产物保留静态 `node:crypto`、`node:zlib` 导入，部署需要适当的 Node 兼容日期/开关。作者构建用静态导入桥接上游 CommonJS 内置模块调用，不替换密码算法。`tough-cookie` 负责 Cookie 的域名、路径、过期和持久化，Fetch 的 `Headers.getSetCookie()` 提供独立响应头；没有自行按逗号拆 Cookie。

会话恢复与失效遵循扫码登录的实际能力。固定 [4.32.0 随包文档](https://unpkg.com/NeteaseCloudMusicApi@4.32.0/public/docs/home.md)的“刷新登录”段明确 `login/refresh` 不支持二维码登录的 Cookie，因此插件不定时调用此接口，也不承诺永久免扫码。有效 `MUSIC_U` 缺失或到期时，在请求受保护内容前返回“需要重新认证”；来源明确返回未登录状态或账号状态中的 `profile: null` 时，也回到共用扫码流程。账号响应缺字段、编号损坏、网络或服务暂时失败均保留原会话，避免把临时故障当成授权失效。

同次调用的 Cookie 更新由独立 CookieJar 合并，即使后续业务失败，也通过 `nextPrivateState` 提议保存；宿主仍按实例版本条件提交，旧调用不能覆盖新授权。后续账号查询失败不回退已经完成的扫码；内容可重试，无须重复消费二维码。明确失效时通过tough-cookie移除MUSIC_U，保留设备Cookie和另行进行的扫码挑战。

## 当前能力与缺口

当前预览提供喜欢、每日推荐歌曲、自建歌单、收藏歌单和每日推荐歌单的目录实现。系统喜欢歌单根据 `specialType: 5` 识别；自建/收藏按原生 owner 编号分类。歌单详情以完整 trackIds 为基准，分页详情按原顺序重组并保留重复位置；本次开始冻结序列，完成前再核对一次摘要。未完整返回、分页期间变化及暂时网络错误返回失败，由核心保留最近成功目录。

每次歌单扫描只在开始和完成前取完整成员名单；歌曲详情/播放版本使用200首批量，仅补缓存缺失项。默认清单页处理200首，准备索引命中不载入封面、歌词或大计划。文件准备仍最多两项冷工作并发，数量、耗时与可选宿主预算共同决定检查点，热页最多100文件。桌面和Worker使用相同算法。目录进度与真实限流冷却由公开合同投影。每日推荐列表继续缓存30分钟。

API0.1.9提供可选原子缓存`putIfAbsent`固定首读计划；SQLite与D1共用相同语义，不增加数据库迁移。API0.1.8的`Entry.deferredInfo`与`Context.fileInfo: 'required'`继续保留给需分阶段准备的其他插件/旧引用，不再是本版网易云默认目录的前置步骤。真实打包插件已通过本地workerd/D1的200首离线集成：完整属性207且零准备，HEAD零上游，首GET只处理一曲，单请求最多32条SQL；这些是受控夹具计数，不是真实平台速度承诺。

音质是实例配置。alpha.3 提供标准、极高、无损、Hi-Res 的单版本/多版本，以及隐藏/向下回退策略。`quality` 是单版本目标，保留旧实例原值；`audio.mode` 选择模式，`audio.qualities` 只在多版本生效，`audio.missingQuality` 决定缺失处理。旧配置即使只有 `quality: "exhigh"`，仍按极高、单版本、隐藏运行；切换多版本后使用独立的多目标列表。

回退顺序为 Hi-Res → 无损 → 极高 → 标准。原生响应直接返回较低实际档位时，也只有回退策略允许使用。文件标签和扩展名以实际版本生成；多个目标取得同一实际引用时每个曲目位置只导出一次，重复曲目位置仍各自保留。曲目、文件、隐藏曲目、缺失目标、回退目标和合并重复版本分别统计。试听不作为完整版本；暂时请求、认证、限流和解析错误直接失败，不通过回退掩盖。已引用文件的读取只重新解析该实际版本，不能因当前回退设置换成其他字节。

alpha.3 已在真实账号与本地 workerd 复测：每日30曲，多目标无损/标准+回退导出35文件（极高17、标准18），统计一致；真实极高MP3的完整/范围/rclone通过。该阶段没有取得真实FLAC，因此不表示全部档位已验，后续结果以[实际来源记录](../../docs/verification/p2-netease-source.md)为准。当前支持范围之外的特殊音效/格式、真实会话过期后重登，以及免费 Worker 下的新多目标请求预算仍待后续收口。

alpha.2 处理原生音频响应中“同曲多个实际版本”的情况：先核对请求编号均有回应，再选择所配置音质的完整版本；格式名仅做大小写规范。其他音质不参与隐式回退；同一目标音质的候选仅在编号、音质、格式、MD5 和大小全部一致时合并，临时 URL 可以不同。缺少/未知编号或目标音质存在冲突实际文件仍失败。

原表示引用包含歌曲编号、实际格式、音质、MD5与大小，短期音频URL不进入稳定引用。v3补标签文件引用另含稳定seed键，完整计划仍按最终内容身份保存；`Entry.info`（若已就绪）与`stat`描述最终输出，`open`核对源版本并按已选计划映射范围，一次调用复用一个临时定位，保留取消和长度核对。`reference.ts`集中定义原表示身份，`metadata.ts`负责来源资料，`tagged.ts`负责计划缓存与输出引用，核心没有网易云或标签格式分支。

## 验证口径

聚焦测试使用真实 SDK 业务回调/加密代码与可控 Fetch 响应，证明配置、独立 CookieJar、确认后状态保存/恢复、认证暂时失败、取消、目录归属/顺序、试播隐藏、重新解析地址及范围读取。模拟测试不能替代实际账号、权限和真实音频测试。

会话回归另外覆盖缺失/过期 Cookie 在发送业务请求前要求重登、明确未登录后重新扫码、畸形或临时账号响应保留会话，以及正常响应和后续失败响应的 Cookie 更新均能保存并在恢复后复用。这些是受控传输证据，不表示已等待真实 Cookie 自然到期或完成真实 Worker 的失效重登。

alpha.3 定向回归另外覆盖旧极高配置保持原义、多版本不受旧单目标限制、相同实际文件合并/重复位置、不同实际文件同时导出、回退的实际标签、读取不回退，以及试听/错误边界。主线已统一构建安装，并完成上述实际多目标与workerd验证，其余档位仍待验。

双宿主探针读取实际预构建产物：Bun 直接取得真实二维码；本地 workerd 经正式管理 API 创建两个 D1 实例并取得真实二维码。它不自动完成手机授权，也不证明云端部署、免费 CPU 预算或真实播放已经通过。

已有真实授权实例后，可显式选择只读桌面数据库与实例编号，将该私有会话临时导入本地 D1 验证状态恢复和每日推荐目录：

```sh
MUSICFS_NETEASE_TEST_STATE_DB=/absolute/path/state.sqlite \
MUSICFS_NETEASE_TEST_INSTANCE_ID=instance-id \
bun run scripts/probe-worker-netease.ts
```

探针只输出计数与通过状态，临时 D1 完成后删除。不要把账号 Cookie、私有状态、二维码或真实账号截图放入仓库。

SDK 候选与取舍见 [研究记录](../../outputs/research-netease-worker-sdk.md)。插件自有代码采用GPL-3.0-only；发布包保留该正文及实际打包依赖各自的第三方许可和署名。
