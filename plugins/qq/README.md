# QQ 音乐示例插件

插件标识为 `org.musicfs.qq`，版本和宿主兼容范围见 [manifest.json](manifest.json)。它通过公开插件合同提供来源能力，核心、DAV 和共用页面没有 QQ 专用分支。

## 构建与使用

```sh
bun run build:qq
```

产物为 `dist/plugins/org.musicfs.qq.zip`，在管理页安装后添加来源。QQ 与微信扫码分别配置，可能对应不同音乐账号。支持喜欢、自建/收藏歌单、每日推荐及推荐歌单，保留曲目顺序和重复位置。

音质按实例配置，支持单版本、多版本以及缺失时隐藏或回退。实际可用格式包括 M4A、MP3、FLAC 和 APE；文件名和标签使用实际音质，多个目标落到同一实际文件时合并。

## SDK 与文件读取

固定使用 `@yakult-green-tea/qq-music-api` 3.3.3，构建适配见[脚本](../../scripts/build-qq.ts)。SDK 处理平台登录、密文会话和原生请求；插件接入宿主 Fetch、取消信号、实例私有状态和续期协调。凭据就绪即可完成授权，昵称等补充资料按内容需要取得。

歌曲页先准备准确的最终描述，再发布目录。`@musicfs/audio-tags` 补充来源已有的基础资料、封面和歌词，保持原音频编码；曲号和碟号取自原专辑位置。资料缓存、不可变文件计划与临时播放地址分别保存，音乐资料保留期限可配置，也可主动重新获取。

读取时重新定位同一原表示，核对其身份后按最终文件 Range 拼接。文件引用不携带凭据或临时地址；已发布文件不会因资料到期而悄悄改变字节。命名模板所需字段直接复用清单资料。

## 验证与开发

`bun run probe:worker:qq` 验证实际构建模块的本地 workerd/D1 接线。可选真实会话与播放器复测见[开发检查](../../docs/development-reference.md)；格式、平台和真实续期范围见[兼容性说明](../../docs/verification.md)。

开发第三方来源见[插件作者指南](../../docs/plugin-authoring.md)。示例自有代码采用 GPL-3.0-only；打包时保留依赖各自的许可和署名。
