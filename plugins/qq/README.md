# QQ 音乐示例插件

插件标识为 `org.musicfs.qq`，版本及接口兼容范围见 [manifest.json](manifest.json)，配置与私有状态版本均为2。它使用与独立最小插件相同的接口和安装器；核心、DAV 和共用页面没有 QQ 专用分支。可选命名字段从当前曲目清单提供，由共用模板渲染，不增加平台请求。

alpha.11 在示例插件内默认补充音乐资料；第三方插件仍可完全透传，不需要提供音乐字段或使用补标签库。MP3、FLAC、APE、M4A 使用 `@musicfs/audio-tags` 构造最终文件的区段计划，复用来源音频数据，先准备准确的最终大小和内容身份，再发布目录。基础字段优先使用已有歌曲资料，缺失时补读原歌曲/专辑详情；歌手保留多值，专辑艺术家来自专辑，曲号/碟号来自来源的专辑位置，绝不使用歌单位置代替。封面和原文/译文/罗马音歌词按来源实际返回补充，缺失字段不伪造。

补充歌曲/专辑资料、封面和歌词默认缓存365天，`metadataCacheDays: 0`长期保留；空或缺失结果最多30天。同曲/同专辑跨音质和重复出现复用，命中不顺延到期。修改保留天数保留既有目录和缓存，新期限用于后续取得的资料；目录菜单可显式重新获取音乐资料，同一任务跨页复用本轮封面和专辑资料，完成后发布新表示，旧引用保持原字节。临时播放地址、授权和歌单名单更新策略不变，每日推荐列表仍缓存30分钟以供续页。

最终计划按内容寻址保存且不设期限；全部音乐资料长期有效时，目录使用的准备索引也长期保留，仍含缺失资料时按最早到期时间重试。文件引用只带原表示和计划键，不包含封面、歌词、临时地址或凭据。新文件的 `stat` 从计划返回准确描述，`open` 重新定位原表示后按最终文件的Range拼接；计划缺失时明确要求重新刷新，不改回原始字节。旧版本1文件引用仍按原字节读取。需要支持可选插件缓存的宿主，否则新目录准备返回不支持。

本轮只做受控Fetch与本地合成媒体验证，没有访问真实音乐平台、刷新账号或部署Worker。下文旧版本的真实来源证据保留原范围，不自动表示补标签版本已通过真实账号、播放器或云端验收。

alpha.10 为 SDK 的扫码初始化、QQ/微信轮询和目录账号状态装配调用专属的 Fetch/取消信号。沿用 SDK 的登录操作、认证服务、密文 QR、驱动以及 Cookie/重定向处理，不改全局 Fetch 或平台协议。受控测试验证底层在途请求实际取消、已取消调用不发请求、取消结果不提供可保存状态。实际安装模块已在无Node兼容开关的本地workerd验证底层取消；Bun及正式workerd管理入口均完成真实QQ/微信二维码创建、未扫码轮询及取消，本轮未要求用户重新扫码。认证Fetch显式使用`cache: no-store`，避免Axios默认cache模式被workerd拒绝。

alpha.9 在 SDK 交换出有效密文后，本地解析确认并立即完成授权，不再等待额外账号资料请求。昵称只取新凭据中可用的字段，缺失时不继承旧账号名。资料查询留在后续目录读取；临时故障可以独立重试，不需要再次消费二维码。宿主仍拒绝二维码步骤本身已到期后才返回的结果，没有放宽旧操作/取消检查。

alpha.8 接入插件声明的会话续期准备；私有状态升级为版本 2，保留旧账号、密钥、令牌和已确认挑战，并加入下一检查时间。读取前只用 SDK 在本地检查令牌寿命；需要续期时由宿主按实例协调并持久保存结果，普通内容请求在协调结束后继续执行。真实账号长时间续期与完整失效重登仍待验，不把受控 SDK 测试当作真实上游成功证据。

alpha.7 在歌曲小页中准备真实文件描述，复用当次 SDK 批量解析与选中 CDN 的 Range 探测；`Entry.info` 随目录发布。alpha.6 是打包修订，原 alpha.5 等版本的真实证据保留其版本，不自动改写为本候选已验。alpha.7 已构建并经正式本地安装保留真实会话；每日小页、完整描述及本地workerd/D1真实会话已验，见[目录元数据记录](../../docs/verification/p2-listing-metadata.md)。没有把此前所有格式/客户端结果自动归到本版。

## 已接入的路径

- 每实例独立的 QQ/微信扫码配置、加密会话密钥和私有授权状态；手机 QQ 与微信真实扫码、状态确认、服务重启后继续访问已验证；手机 QQ 还验证了兼容更新后继续访问。两种登录可能对应不同音乐账号。
- 自建/收藏分别读取原始接口；喜欢与歌单内容完整续读；每日推荐和 25 张推荐歌单作为有限集合。歌曲顺序和重复位置保留，明确不可读取的歌曲隐藏；异常数据、临时错误和不完整分页令整个刷新失败。
- 每实例配置单/多版本、M4A/128k MP3/320k MP3/FLAC/APE 与隐藏/回退。文件名依据实际版本，多个目标回退到同一文件时合并，重复曲序仍保留。原生音质解析通过固定 SDK 批量执行，试听不作为完整文件。
- 临时音频地址不进入公开文件引用。原表示通过真实 `bytes=0-0` 确认大小和版本；补标签计划另行描述最终字节，完整/范围读取流式拼接并核对源版本。原透传版本已有真实 MP3、M4A 及正式 DAV/rclone 字节证据；其他档位的真实可用账号和字节仍待验。
- 每页报告曲目、文件及隐藏/回退/合并计数，由共用核心完整汇总保存，共用界面按插件声明的标签展示。目录读取失败保留最近成功内容与计数。

歌曲页按 `max(1, floor(4 / 目标音质数))` 选择出现位置。每日推荐首次读取完整有限列表并保存其摘要和缓存，续页使用同一列表，不逐页重读平台推荐；新刷新可取得新推荐，过期缓存的旧游标明确要求重新刷新。目录调用共用宿主 Fetch/取消信号，SDK 重试为零，CDN 不自动转址；保留原 4 + 5 个候选地址策略，达到 45 次应用层请求护栏时整页临时失败。标签准备复用本页已解析定位，打开文件时同次调用的多个区段复用一次定位；不能据此保证任意故障情况下都能完成准备，也没有验证云端 CPU 或免费套餐整体额度。

会话续期复用固定 SDK 的 sealed resolver 与原生续期函数：进入最后 6 小时时才尝试，QQ/微信以实际凭证的登录类型续期；新令牌写回本实例私有状态。暂时网络或续期业务失败保留仍可用的旧令牌，不因此强制重登；无论令牌是否轮换，都持久保存至少 5 分钟的下一检查间隔，服务重启或换 Worker isolate 后仍生效。SDK 不会在令牌过期后补续，也不会把原始登录延长超过 30 天；旧令牌没有续期材料时用至到期后重新扫码。

明确授权失效或状态接口报告未登录时清除该实例的无效令牌和账号名；普通业务错误保留凭证。插件内部可恢复旧版本已经换得的confirmed令牌，不再次兑换已消费的二维码；新流程在取得有效凭据时直接完成，不产生等待资料的扫码步骤。扫码、账号状态、原始分类/歌单、推荐歌单、批量音质解析、续期和媒体读取已接入宿主取消。当前尚未完成全部真实双宿主验收。

“收藏歌单”表示收藏的整张歌单，不包含专辑或歌手收藏。已验证微信账号的 1 首喜欢、1 张自建歌单及其 1 首内容；当前会话未返回这些曲目的完整 128k 地址，因此导出 0 个文件。歌曲数与文件数分别核对，不能据文件数推断账号为空。实测细节见[分类与微信验证](../../docs/verification/p2-qq-catalog.md)。

## 模块与依赖

`index.ts` 仅装配公开接口；`configuration.ts` 管理实例默认值和策略；`client.ts` 管理实例私有状态、SDK 批量调用与错误翻译；`authentication.ts` 处理挑战和会话交换；`catalog.ts` 处理分类、分页、出现位置与计数，`collections.ts` 保留原始集合角色；`playback.ts` 处理目标到实际音频的解析、回退、去重、引用和 CDN；`file-info.ts` 统一解释真实响应头，`media.ts` 处理文件描述与字节读取；`metadata.ts` 解释来源音乐资料并复用缓存；`tagged.ts` 保存不可变输出计划及其文件引用。`upstream.ts` 只装配所需的五个 SDK 登录操作，将本次调用的 Fetch/取消信号传给 SDK 认证 HTTP 和纯 HTTP QQ 驱动；不能导入会自动启动 Koa 的 npm 根入口。旧歌词和专辑详情SDK依赖全局transport，这两项简单读取使用相同公开URL并显式传入当前Fetch/取消信号；不复制密码算法或改SDK。

默认音频设置为 `{mode:"single",qualities:["128"],missingQuality:"hide"}`，保存在本实例 config.audio。多版本可选择多档；FLAC 与 APE 同级，回退均按 320k MP3 → 128k MP3 → M4A，不互相充当较低档。APE 文件资料不能确认时报告临时失败，不按缺失静默隐藏。文件打开时仅读取已发布的实际版本，不再次回退到不同字节。完整结果与限制见[音质与统计验证](../../docs/verification/p2-qq-quality.md)。

上游固定为 `@yakult-green-tea/qq-music-api@3.3.3`，复用 SDK 登录服务/操作、原始读取客户端和续期函数，不需要另部署 API 服务。其公共 HTTP facade 未开放 Fetch 注入，因此作者入口复用下层可注入工厂，并使用 SDK 已安装的 Axios 1.20.0 Fetch adapter；没有新增另一份依赖。微信封存 Cookie 恢复使用 SDK 自带 jar helpers，重定向时保留更新、删除和多个 Set-Cookie。续期仅转换 SDK Fetch transport 与认证函数间的 JSON POST 结果形状；令牌解析、寿命、续期参数和签发仍由 SDK 处理。`generated-upstream` 由作者构建生成，直接复用固定发布包的 ESM 导出，不修改依赖源码；升级检查与代价见 [ADR 0005](../../docs/adr/0005-pinned-qq-sdk-read-adapter.md)。SDK 日志模块读取 `process.env`；作者构建时用 Bun 的 `define` 固定日志配置，生成的安装模块无需 `process` 全局或 Worker Node 兼容开关。包包含 SDK、Axios、Zod 和 Ajv 的必要许可及来源声明，不执行安装脚本。

插件自有代码采用 GPL-3.0-only；第三方依赖保留原许可证，随包提供各自许可及来源声明。

## 开发验证

在仓库根目录运行 `bun run build:qq`，生成 `dist/plugins/org.musicfs.qq.zip`，通过 WebUI 的插件安装入口上传。修改已发布内容必须更新 manifest 的插件版本；同版本不同摘要会被拒绝。配置版本为 1，私有状态版本为 2；从版本 1 更新通过协调迁移保留已有授权。

`bun run check` 包含插件构建、严格类型检查、导入边界和测试。`bun run probe:worker:qq` 将实际构建的安装模块放入本地 workerd/D1，验证初始化、实例隔离、SDK受控续期和正式管理路由的已确认凭据完成；可显式选择已有开发实例做真实会话恢复探测。操作与结果见[会话记录](../../docs/verification/p2-session-lifecycle.md)、[分类与分页](../../docs/verification/p2-qq-catalog.md)和[开发入口](../../docs/development.md)。账号、二维码、私有状态与临时音频保存在开发数据目录或 `/tmp`，不写入本仓库的证据文件。
