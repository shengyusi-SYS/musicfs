# QQ 音乐示例插件（开发预览）

当前开发候选为 `org.musicfs.qq` / `0.1.0-alpha.8`，需要公开插件合同 `>=0.1.5 <0.2.0`。它使用与独立最小插件相同的接口和安装器；核心、DAV 和共用页面没有 QQ 专用分支。当前不是完整发行版。

alpha.8 接入插件声明的会话续期准备；私有状态升级为版本 2，保留旧账号、密钥、令牌和已确认挑战，并加入下一检查时间。读取前只用 SDK 在本地检查令牌寿命；需要续期时由宿主按实例协调并持久保存结果，普通内容请求在协调结束后继续执行。真实账号长时间续期与完整失效重登仍待验，不把受控 SDK 测试当作真实上游成功证据。

alpha.7 在歌曲小页中准备真实文件描述，复用当次 SDK 批量解析与选中 CDN 的 Range 探测；`Entry.info` 随目录发布。alpha.6 是打包修订，原 alpha.5 等版本的真实证据保留其版本，不自动改写为本候选已验。alpha.7 已构建并经正式本地安装保留真实会话；每日小页、完整描述及本地workerd/D1真实会话已验，见[目录元数据记录](../../docs/verification/p2-listing-metadata.md)。没有把此前所有格式/客户端结果自动归到本版。

## 已接入的路径

- 每实例独立的 QQ/微信扫码配置、加密会话密钥和私有授权状态；手机 QQ 与微信真实扫码、状态确认、服务重启后继续访问已验证；手机 QQ 还验证了兼容更新后继续访问。两种登录可能对应不同音乐账号。
- 自建/收藏分别读取原始接口；喜欢与歌单内容完整续读；每日推荐和 25 张推荐歌单作为有限集合。歌曲顺序和重复位置保留，明确不可读取的歌曲隐藏；异常数据、临时错误和不完整分页令整个刷新失败。
- 每实例配置单/多版本、M4A/128k MP3/320k MP3/FLAC/APE 与隐藏/回退。文件名依据实际版本，多个目标回退到同一文件时合并，重复曲序仍保留。原生音质解析通过固定 SDK 批量执行，试听不作为完整文件。
- 临时音频地址不进入公开文件引用。元数据通过真实 `bytes=0-0` 确认大小和版本；完整/范围读取直接流式转发，核对范围、长度与内容版本。真实 MP3、M4A 及正式 DAV/rclone 字节已验；其他档位的真实可用账号和字节仍待验。
- 每页报告曲目、文件及隐藏/回退/合并计数，由共用核心完整汇总保存，共用界面按插件声明的标签展示。目录读取失败保留最近成功内容与计数。

歌曲页按 `floor(6 / 目标音质数)` 选择出现位置，最多准备 6 个实际文件。每日推荐每页重读有限集合并核对有序身份摘要，不保存整份曲目或临时地址；集合变化则拒绝混合发布。目录调用共用宿主 Fetch/取消信号，SDK 重试为零，CDN 不自动转址；保留原 4 + 5 个候选地址策略，达到 45 次应用层请求护栏时整页临时失败，不能据此保证任意故障情况下都能完成准备，也没有验证云端 CPU 或免费套餐整体额度。

会话续期复用固定 SDK 的 sealed resolver 与原生续期函数：进入最后 6 小时时才尝试，QQ/微信以实际凭证的登录类型续期；新令牌写回本实例私有状态。暂时网络或续期业务失败保留仍可用的旧令牌，不因此强制重登；无论令牌是否轮换，都持久保存至少 5 分钟的下一检查间隔，服务重启或换 Worker isolate 后仍生效。SDK 不会在令牌过期后补续，也不会把原始登录延长超过 30 天；旧令牌没有续期材料时用至到期后重新扫码。

明确授权失效或状态接口报告未登录时清除该实例的无效令牌和账号名；普通业务错误保留凭证。插件内部可恢复已经换得的confirmed令牌，不再次兑换已消费的二维码；宿主公开waiting步骤的到期合同仍需端到端核对，不能据该插件回归保证任意时长的恢复。原始分类/歌单、推荐歌单、批量音质解析、续期和媒体读取已接入宿主取消；仍经 SDK HTTP facade 的扫码及状态调用尚未全部贯通底层取消。当前尚未完成全部真实双宿主验收。

“收藏歌单”表示收藏的整张歌单，不包含专辑或歌手收藏。已验证微信账号的 1 首喜欢、1 张自建歌单及其 1 首内容；当前会话未返回这些曲目的完整 128k 地址，因此导出 0 个文件。歌曲数与文件数分别核对，不能据文件数推断账号为空。实测细节见[分类与微信验证](../../docs/verification/p2-qq-catalog.md)。

## 模块与依赖

`index.ts` 仅装配公开接口；`configuration.ts` 管理实例默认值和策略；`client.ts` 管理实例私有状态、SDK 批量调用与错误翻译；`authentication.ts` 处理挑战和会话交换；`catalog.ts` 处理分类、分页、出现位置与计数，`collections.ts` 保留原始集合角色；`playback.ts` 处理目标到实际音频的解析、回退、去重、引用和 CDN；`file-info.ts` 统一解释真实响应头，`media.ts` 处理文件描述与字节读取。`upstream.ts` 固定选择认证所用 SDK 的纯 `/serverless` 入口，不能导入会自动启动 Koa 的 npm 根入口。

默认音频设置为 `{mode:"single",qualities:["128"],missingQuality:"hide"}`，保存在本实例 config.audio。多版本可选择多档；FLAC 与 APE 同级，回退均按 320k MP3 → 128k MP3 → M4A，不互相充当较低档。APE 文件资料不能确认时报告临时失败，不按缺失静默隐藏。文件打开时仅读取已发布的实际版本，不再次回退到不同字节。完整结果与限制见[音质与统计验证](../../docs/verification/p2-qq-quality.md)。

上游固定为 `@yakult-green-tea/qq-music-api@3.3.3`，复用进程内 `handleRequest`、SDK 原始读取客户端和续期函数，不需要另部署 API 服务。续期仅转换 SDK Fetch transport 与认证函数间的 JSON POST 结果形状；令牌解析、寿命、续期参数和签发仍由 SDK 处理。`generated-upstream` 由作者构建生成，直接复用固定发布包的 ESM 导出，不修改依赖源码；升级检查与代价见 [ADR 0005](../../docs/adr/0005-pinned-qq-sdk-read-adapter.md)。SDK 日志模块读取 `process.env`；作者构建时用 Bun 的 `define` 固定日志配置，生成的安装模块无需 `process` 全局或 Worker Node 兼容开关。包包含 SDK、Zod 和 Ajv 的必要许可及来源声明，不执行安装脚本。

## 开发验证

在仓库根目录运行 `bun run build:qq`，生成 `dist/plugins/org.musicfs.qq.zip`，通过 WebUI 的插件安装入口上传。修改已发布内容必须更新 manifest 的插件版本；同版本不同摘要会被拒绝。配置版本为 1，私有状态版本为 2；从版本 1 更新通过协调迁移保留已有授权。

`bun run check` 包含插件构建、严格类型检查、导入边界和测试。`bun run probe:worker:qq` 将实际构建的安装模块放入本地 workerd/D1，验证初始化与实例隔离；可显式选择已有开发实例做真实会话恢复探测。操作与结果见[分类与分页验证记录](../../docs/verification/p2-qq-catalog.md)和[开发入口](../../docs/development.md)。账号、二维码、私有状态与临时音频保存在开发数据目录或 `/tmp`，不写入本仓库的证据文件。
