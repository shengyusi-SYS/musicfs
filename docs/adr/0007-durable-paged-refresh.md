# 目录刷新按持久页推进

2026-10-20，采用。真实网易云 4,158 曲需要 42 页，原先在一次 HTTP 请求中读完约需 168 次来源请求；把同一循环移到 `waitUntil` 仍共用该次调用的限制。因此由 `library` 拥有持久刷新操作、分页暂存及完整目录发布，每步至多调用一次插件分页，桌面后台和 Worker 只负责安排下一步。

SQLite/D1 共用条件 SQL，按有序行追加条目，最后一页才原子切换发布指针；失败保留最近成功快照。租约、操作修订及实例/安装代际共同阻止迟到页覆盖。管理接口从同步结果改为 `202 + operationId`，GET 只查询，POST step 推进；冷读取返回可重试的 503。桌面后台连续续步，Worker 的 HTTP 后台工作或每分钟定时调用各最多推进一页。没有新增付费队列或通用任务框架。

刷新操作身份与内容版本分开：完整候选和原有序条目、来源身份相同，则保留发布指针与内容ID，只更新最近成功检查时间、统计和错误状态。实际变化才切换版本；内容修改时间单独保存，旧行兼容原完成时间。比较与发布共用一个事务和已有条目索引，不受分页大小影响；候选仍按原流程暂存、回收，不跳过平台确认或部分发布。

这会增加初次浏览的准备过程及任务持久化，但解除完整集合与单次请求预算的绑定。它不证明单页的 CPU/请求预算足够，也不解决 DAV allprop 逐文件元数据工作；这些仍须分别测量与收敛。执行合同见[管理接口](../management-api.md)，状态与验证见[分页刷新记录](../verification/p2-durable-refresh.md)。
