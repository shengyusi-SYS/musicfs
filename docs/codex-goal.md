# MusicFS Codex 主线目标

日期：2026-10-20。范围：持续完成本仓库的产品实现与交付。本文件定义执行目标与完成条件；[统一需求](../outputs/musicfs-requirements-and-technical-design.md)保存产品合同，[实施计划](../outputs/musicfs-implementation-plan.md)保存具体执行顺序，[验收台账](verification.md)保存实现与验证状态。

## 总目标

在本仓库把已确认方案实现为完整可交付的 MusicFS：以可安装数据源插件提供只读音乐目录，通过共用 WebUI 管理插件、多个独立实例、配置认证和目录布局，通过标准 WebDAV 接入播放器与 OpenList；交付 Windows、Linux、macOS 桌面发行物及独立 Cloudflare Worker 部署。桌面由可点击启动器启动后台并管理随包 rclone，可挂载本地或远程 DAV。网易云与 QQ 是经相同公开合同接入、完整可用的双宿主示例插件。

完成范围包含全部 FR01—FR25、统一需求第 14 节的全部验收项、对应发行物、使用与插件作者文档、架构图表及真实验证证据。持续推进至这些条件全部满足；P0、首条链路、原型、模拟测试或构建通过均是阶段结果。

独立作者插件真实云端接入、核心/WebUI升级保留实际插件模块均已通过，目录分页已进入开发与云端页面。当前优先定位云端播放器控制超时，再继续双示例行为、正常操作资源及客户端证据，源码/页面冻结后统一更新桌面归档；其他OS原生环境、自然到期和免费计划的未验证结论独立保留，不用重复本地测试抵扣。目标工具已由用户清除旧目标后重建为active，从本阶段续接。

系统操作仅在WSL内执行，禁止调用Windows宿主或外部默认浏览器；用户已允许Codex内置浏览器。沿用已授权的单Worker/D1和现有付费账号，控制请求与部署次数，不新建冗余资源、不变更账号套餐。许可沿用GPL-3.0-only及必要第三方材料，不恢复大型上游源码或完整依赖闭包调查。

## 必须保持的设计边界

- 核心拥有插件与实例管理、隔离存储、布局、命名、快照、HTTP/DAV 和挂载；插件拥有来源认证、内容分类、音质、回退、隐藏、实际文件去重、元数据与范围取流。来源设置按实例保存。
- 公开插件合同独立于核心实现与特定 UI/校验库对象。网易云、QQ 和独立最小插件使用同一接口；没有账号、歌单或音质概念的插件也能接入。
- 用户通过 WebUI 安装预构建包或发布地址、主动更新与移除。桌面加载外置插件；Worker 插件变更采用已接受的后台组装/自动部署路线，优先验证普通免费计划。新插件接入无需用户编译核心或 WebUI。
- 插件移除保留实例配置和布局引用，停止对应读取；重装兼容插件可恢复。删除实例数据是独立操作。失败更新保留可用版本，旧任务不能覆盖新实例或新插件状态。
- 目录刷新完整成功后发布，失败保留最近成功内容；用户布局独立。音频元数据与实际字节一致，范围响应和取消真实有效，服务以流式方式传递音频。
- 采用少量深模块与真实宿主适配，遵守架构定义的依赖方向。优先采用适合的成熟依赖，以整体维护成本取舍；ZIP 库先比较 zip.js/fflate，第三方插件校验实现保持可替换。
- 保持已确认的自用、只读范围。播放器、多用户权限产品、云端写入、转码、插件市场等新能力须另行确认。
- 不以高并发服务为目标。真实来源只做单用户、低频串行、少量代表样本的必要验收；复用已有快照和结果，不对真实来源做压力/极限测试、持续负载或反复全账号扫描。遇到验证码、限流或风险提示即停止该来源验证，不通过换账号、渠道或出口继续试探。不涉及平台且对UX影响明显的本地性能、并发与故障测试可以做，按实际影响与收益选取有界范围。

## 全部完成的判定

只有同时满足以下条件，才可把 Codex 目标标记为 complete：

1. **功能齐全**：FR01—FR25 均有正式可达的实现路径，统一需求第 14 节每项均有对应证据；无占位实现、模拟登录或替代数据充当必需的真实来源结果。
2. **扩展成立**：公开合同、作者构建说明及预构建安装包可用；无认证/歌单/音质的独立插件可以经 WebUI 安装并提供内容，核心及前端保持不变。安装、更新、移除、兼容拒绝、重装和实例删除符合合同。
3. **示例完整**：网易云和 QQ 在桌面与真实 Worker 上完成已确认的扫码、授权持久化/刷新/失效重登、内容分类和完整分页、顺序/重复位置、单多音质、隐藏/回退/去重及真实音频读取。
4. **协议和客户端正确**：已知字节样本证明 HEAD、首中尾/大偏移范围、206/416、取消、上游忽略 Range 与中途失败处理正确；真实来源经 OpenList、rclone 和普通播放器完成列目录、播放及双向拖动，音频资源使用符合流式设计。
5. **目标系统可用**：Windows x64、Linux x64、macOS Intel/Apple Silicon 的目标系统运行证据齐全；从发行物点击启动，WebUI 挂载/卸载、本地及远程 DAV、重复启动、关闭页面后后台存活和必要故障提示均符合要求。
6. **Worker 独立可用**：由部署模板运行完整共用 WebUI 与兼容插件；插件变更由后台完成发布，验证状态/Secrets/D1/静态资源保留、失败恢复及切换影响，并记录普通免费路线的实际配额与运行结果。若事实要求改变付费或外部服务前提，先携具体证据与用户对齐。
7. **状态与访问边界可靠**：账号、配置、缓存和任务按实例隔离；刷新失败保留目录；换号、更新、移除、删除后的过期任务不能写回。读取凭据不能管理服务，平台凭据不进入客户端媒体地址或诊断输出。
8. **交付可复现**：项目提供明确构建/测试/打包入口和锁定依赖；适用的类型检查、边界检查、集成及故障回归通过。三端发行物、两个示例插件包、独立最小插件、Worker 模板/迁移、使用与作者文档、许可均可找到，图表与最终实现一致。记录正常自用下的目录、缓存和内存表现，已有流式/并发证据直接复用；按实际UX影响保留必要本地测试，不以高并发容量作为交付门禁。
9. **证据已收口**：[验收台账](verification.md)不存在必需项的未实现、失败、待验或环境阻塞；最终交付说明关联实际产物与测试版本，并准确列出支持范围。

## 验证与持续恢复

- 每完成一条真实链路或发现实质障碍，更新[验收台账](verification.md)及实施计划的当前状态和下一项可执行工作。台账分别记录实现与验证，逐项指向代码、产物、命令或人工实测记录。
- 验证根据风险选择：核心合同、状态交错、数据库条件写入和 Range 采用有意义的测试；配置/界面简单调整采用适当检查。真实平台、目标系统挂载和 Cloudflare 部署以对应环境的运行结果收口。
- 需要账号扫码、已授权测试部署资源或目标机器时，先准备完整可审阅的程序、界面与步骤，再提出精确的外部协作需求；等待期间继续不依赖该条件的工作。环境不足的项目保留为待验，保持最终完成标准。
- 可自主处理常规实现、可逆修正和候选替换。仅当实测差距要求改变已确认产品范围、必要付费前提、外部服务或明显使用行为时，带具体差距请求决策；已有授权可直接使用。
- 阶段报告说明可用旅程、验证范围、剩余义务和下一步。目标状态按宿主工具规则更新；只有达到上述全部完成条件才使用 complete。外部条件未齐不等于暂停或完成，记录准确障碍并继续可执行部分。
