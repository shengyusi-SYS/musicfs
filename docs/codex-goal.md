## 持续执行循环

1. **恢复事实**：读本目标、实施计划的当前状态、实际工作树；行为依据查[统一需求](../outputs/musicfs-requirements-and-technical-design.md)。复用已有测量，确认正在运行的代理和文件所有权。
2. **沿用户旅程找成本**：跟踪从用户动作到来源请求、SQL/行装载、命名/哈希、标签准备、客户端缓存及最终响应的完整路径。区分来源工作、宿主开销和用户可见等待；不把接口调用少等同于整体体验快。
3. **先评估 ROI**：每项记录触发场景/频率、代码或测量证据、预计用户收益、平台覆盖、实现与迁移/维护成本、不确定性。高收益且小到中等成本优先；收益待证先做能改变决策的有界探针。没有依据的反例与假想需求不扩成待办。
4. **设计后实施**：确认 Module 的 Interface、职责归属和共享/宿主差异。优先删除重复工作、复用现有机制与合适依赖。局部重构要替换旧路径，不叠加第二套事实源、刷新算法或队列。
5. **相称验证与提交**：针对变化的正常旅程和实际失效边界检查，记录结果与适用范围。按独立可审阅的行为提交，依赖变更与调用者保持一致；主代理统一检查集成、公共文档和发行身份。
6. **重新排序**：完成一项或新证据推翻方案后，更新 ROI 台账，再检查全部旅程是否仍有值得推进的方向。有高 ROI 项继续做；仅完成初始清单不算完成目标。

## 必须评估的使用角度

| 角度 | 关注结果 |
|---|---|
| 首次接入、小目录及约4,000首大目录 | 首次可用等待、来源调用、准备进度、后台持续工作 |
| 日常新增、删除、换序、不变刷新 | 只做必要工作；路径、mtime、内容身份变化与真实内容一致 |
| 基本资料、音质/权益、歌词封面及临时地址到期 | 新鲜度与可用性各自有清晰期限，避免全部事实一起重建 |
| 播放、重复打开、首中尾seek及播放器扫库 | 单项读取不反复遍历整库，Range与取消准确，来源定位不过度重复 |
| 多歌单/多音质复用与刷新同时播放 | 相同资料复用，前台响应不被无意义后台工作拖累 |
| 网络短断、关闭页面、重启、限流 | 持久进度可继续、错误原因清楚、旧完整目录可用 |
| 保存设置、换号、插件更新/重装 | 必要失效范围明确，保留可复用资料；不同来源状态不混用 |
| 本地/远程挂载、手机/OpenList及WebUI | App发布与客户端看到的内容衔接，现成缓存机制恰当，界面响应可接受 |
| 免费Worker | 请求、CPU、SQL/行读取、持久写入与后台执行粒度的整体成本；不能以付费结果替代免费结论 |

这些是审视角度，不是要求为每个角度新增功能、写一组测试或引入开关。已有表现足够、没有高 ROI 缺口的角度，记录依据后保持。

## 架构与执行约束

- 产品继续是插件式只读音乐文件服务。核心拥有实例、命名、已发布快照、文件视图与通用刷新；来源插件拥有认证、音质/权益、音乐资料、实际表示与定位；协议层拥有HTTP/DAV；宿主拥有平台运行、调度与挂载适配。网易云/QQ是示例插件，不进入核心分支。
- 桌面三端和Worker尽量复用算法与领域模型，按实际宿主预算、存储与生命周期差异适配；不按账号套餐复制整套实现。Worker内存可加速，持久数据承担恢复与正确性。
- 保持完整成功后发布、失败保留旧目录；顺序和重复位置、最终音频大小/标签/内容身份/Range、流式读取与取消、来源代际隔离不能因优化丢失。文件名等明显用户行为改变先明确收益与迁移影响。
- 新依赖比较现有依赖、标准能力和少量直接实现的整体维护成本；采用时锁定版本并检查实际打包/目标运行时。避免仅为“统一”造跨平台音乐框架或通用缓存迁移系统。
- 并行任务按领域与文件所有权拆分；主代理负责目标、ROI台账、依赖/锁文件、公共合同/图表、集成和提交。子代理在明确范围内设计与实现，不并行改同一个核心入口或擅自全局提交。
- 只在WSL内操作，禁止调用Windows宿主。必要目标系统验收仅用现有授权VM；不因设备暂不可用而重复排查与当前性能无关的网络。浏览器使用内置浏览器。
- 验证以单用户常见旅程、有界离线夹具及必要已有证据为主，不做真实平台压力、反复全账号刷新、冗余部署或高并发容量设计。已有付费账号仅在确有必要时使用，控制成本；免费能力保留明确证据边界。

## 全部完成的判定

仅在以下条件同时成立时将Codex目标标记为complete：

1. 上表各实际使用角度已有代码/已有证据或相称探针评估，关键瓶颈与真实用户结果的关系清楚。
2. 有证据且足够高 ROI 的方向已实现、集成并完成必要验证；已知高 ROI 缺口不能仅因初始清单做完而搁置。
3. 所有剩余候选有明确结论：收益不足、实现/迁移/维护或行为代价高于收益，或需要哪项新证据才值得重开。低成本且能决定高收益方向的探针仍值得做时，应继续调查。
4. 最后一轮复盘后，没有仍值得推进的高 ROI 项；结论基于实际场景、频率和成本，而非无限搜索微优化或假想故障。
5. 必要回归、类型/依赖方向、文档/图表与提交一致；需要交付的变更进入与对应源码一致的最新产物。未执行的真实平台、原生或免费云端验证明确保留，不写成通过。

最终报告给出主要使用收益、相称证据、交付入口，以及剩余候选停止的理由。目标在还有高 ROI 工作时保持active；暂停、阻塞与完成遵守目标工具的实际状态规则。
