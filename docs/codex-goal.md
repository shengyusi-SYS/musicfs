# MusicFS Codex 主线目标

目标是**从实际使用角度持续优化性能，直到没有足够高 ROI 的方向**。优先桌面端，多平台共用领域模型和算法，Worker 以免费版约束评估并允许必要的宿主差异。

本文件定义执行与完成标准，不代表目标工具当前正在运行，也不自动创建或恢复目标。当前进展和候选只在[实施计划](../outputs/musicfs-implementation-plan.md)维护，已交付版本见[发行页](release.md)，工程经验见[经验总结](engineering-lessons.md)。

## 持续执行循环

1. 恢复当前工作树、需求、相关设计与已有证据，先确认真实用户旅程及其瓶颈。
2. 按触发频率、用户收益、请求/字节/CPU/存储成本、实现及维护代价评估 ROI；缺少依据时，只做能改变决定的有界探针。
3. 在拥有该事实的模块实施，优先删除重复工作、局部重构与复用合适依赖；替换旧路径，避免叠加第二套事实源或队列。
4. 验证受影响的正常旅程及真实失效边界，按可审阅行为提交。代码、文档、图表和必要交付物一致后再收口。
5. 重新排序候选。有高 ROI 项继续推进；其余写明停止理由及重开所需证据，不无限寻找理论微优化。

## 使用角度

| 旅程 | 评估重点 |
|---|---|
| 首次接入与大小目录刷新 | 清单首次可用、准确属性、逐曲准备分别耗时多少；失败时旧快照是否可用 |
| 日常增删、换序、不变刷新 | 是否只处理必要变化；路径与表示身份是否一致 |
| 目录重进、播放器入库 | 目录之外的文件打开、实际启用的缓存、工作集容量和重复字节 |
| 播放、重开、首中尾 seek | 源请求/预读成本、准确 Range、背压与取消，不能只看接口计数 |
| 刷新同时浏览或播放 | 前台响应、后台公平性、持久续步和限流冷却 |
| 资料/地址到期、换号及插件变更 | 新鲜度、表示稳定性与必要失效范围 |
| 本地/远程挂载与直接 DAV | 各消费入口的缓存和更新交接，不能用一种客户端代替全部 |
| 免费 Worker | 单次 CPU、子请求、SQL、持久写入与续步整体成本，不以付费账号结果替代 |

这些是审视角度，不要求每项新增功能或再跑一套矩阵。

## 架构与执行约束

- 保持插件式只读文件服务。模块所有权、依赖和文件合同见[架构](architecture/README.md)，来源专属配置不进入核心。
- 完整成功后发布、失败保留旧目录；顺序与重复位置、最终字节身份/大小/Range、取消及来源代际隔离不能因优化丢失。
- 验证以常见单用户旅程、已有证据和有界离线夹具为主；不重复真实全库冷扫、平台压力、冗余云部署或低价值反例。
- 在 WSL 操作，禁止调用 Windows 宿主；必要目标验收只用现有授权 VM。VM 不可达时继续独立工作，不默认扩大环境排障。
- 委派仅在获得授权且能按模块/文件所有权拆分时使用；公共合同、依赖锁文件、集成和提交统一协调。
- 成组完成受影响改动后打包，按[开发说明](development.md)与[发行说明](release.md)核对输入和证据；不因文档变化反复重建所有目标。

## 全部完成的判定

1. 已从上述旅程评估关键瓶颈，用户等待与实际成本的关系清楚。
2. 有依据且足够高 ROI 的方向已实现、集成并完成相称验证，不能仅因初始清单做完而忽略已知高收益缺口。
3. 剩余候选有停止理由和重开条件；仍有低成本、足以决定高收益方向的探针时应继续调查。
4. 必要文档、图表、提交与交付物一致；未执行的真实平台、目标系统及免费云端验证如实保留。

新的实际反馈可以重开已收口主题，但不自动恢复此前跳过的全平台、许可闭包或来源验证矩阵。目标状态变更仍遵守目标工具的规则。
