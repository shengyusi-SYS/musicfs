# 可选的音频补标签设计

日期：2026-10-21。来源插件可自行补标签，也可选用共用工具或完全透传。QQ、网易云已通过可选 `@musicfs/audio-tags` 接通资料准备、持久计划和最终读取；当前证据见[实现记录](../verification/metadata-implementation.md)，前期路线比较见[可行性验证](../verification/metadata-tagging-feasibility.md)。

## 核心只接收最终文件

公开 `SourcePlugin` 的 `list/stat/open` 已能表达三种实现，不增加强制的 `tag` 方法、音乐字段、标签能力开关或新的插件类别：

| 插件实现 | 交付的内容 | 核心的处理 |
|---|---|---|
| 透传 | 上游原文件，可能已有完整标签，也可能没有 | 按通用文件合同读取 |
| 自带补标签 | 插件自己的代码、第三方库或来源已生成的带标签文件 | 按同一合同读取，不再次补写 |
| 选用共用工具 | 插件取得音乐资料，调用可选工具形成带标签文件 | 按同一合同读取，不依赖工具实现 |

补标签不是所有来源的必选能力。上游不提供的格式和资料不由核心补造；共用工具未支持的格式，也不禁止其他插件输出。QQ、网易云按其实际来源能力补全本次目标资料，不把示例格式集合变成核心白名单。

三种实现的 `Entry.info`、`stat` 和 `open` 都描述同一份最终字节：准确大小、媒体类型、内容身份及实际范围。标签改变也改变文件内容身份；临时 URL 更新而字节未变，不构成新文件。不能先公布原大小，再在首次读取时悄悄增加封面或歌词。这是已有文件合同，不是新增音乐协议。

## 模块与依赖方向

| Module | 隐藏的实现责任 | 对调用者的 Interface |
|---|---|---|
| 来源插件 | 平台请求、字段映射、原标签处理、资料缺失与更新策略、音质版本、资料准备与复用 | 既有 `SourcePlugin` 文件操作 |
| 可选音频工具 | 库的格式差异、标签序列化、文件区段组合、最终描述与范围映射 | 准备最终表示，再按该表示读取；不知道账号、歌单和平台接口 |
| `library` / DAV / `mounts` | 快照、路径、HTTP 属性和实际文件访问 | 既有通用文件 Interface |

工具是插件构建时选用并打包的依赖，不由核心全局注入。插件可替换它，无需修改核心或重新编译 MusicFS。工具只引用公开类型和所需格式库，不导入 `core`、DAV、宿主入口或数据库。结构图见[可选标签处理](diagrams.md#可选标签处理设计)。

两个示例复用一个 [packages/audio-tags](../../packages/audio-tags/README.md) Module，只有 `prepare/open` 两个操作。不创建格式注册中心或多层透传包装；`plugin-api` 继续作为公开类型合同，音频工具独立版本、按需采用，不成为宿主必选能力。导入图检查禁止核心引用这个可选包，也禁止工具依赖来源插件或宿主。

工具的最小 Interface 围绕最终表示：

1. 准备：接受插件映射后的资料和可取消的原文件范围读取能力，返回最终描述与可重建的表示计划；隐藏必要头尾探测和标签编码。
2. 读取：接受同一计划及最终范围，组合标签与原音频区段，返回实际范围及可取消流。

实际类型见[工具 Interface](../../packages/audio-tags/src/types.ts)。现成库负责标签编码；少量区段/偏移适配集中在工具内部。来源语义、资料缓存和请求预算不塞进格式编码器。计划只有原表示身份、最终描述、内嵌小区段及原文件区间，没有临时 URL；调用插件负责缓存。

## 准备、缓存与身份

QQ继续在现有分页准备中取得资料，再公布最终`info`。网易云自alpha.14起默认每页处理200首，批量确认完整成员、歌曲详情及实际播放版本；MP3/FLAC/M4A按`原大小 N + 1MiB`提供准确最终描述，清单完成即可直接挂载。HEAD和目录属性不读歌词、封面、音频；首个GET才取得该曲资料并构造标签和合法填充，原音频保持流式Range。

API0.1.8的`deferredInfo`两阶段流程继续供其他插件/旧引用使用，只有显式待准备文件才会在批量准确属性请求时安排`fileInfo: 'required'`并返回503。网易云新路径无需这一前置任务；核心、DAV和rclone仍使用原有准确文件合同，不增加特殊音频分支。

预留预算由来源插件选择；工具的可选`reserveBytes`只负责格式编码与准确填充，MP3使用ID3 padding、FLAC使用PADDING、M4A使用free。空白以紧凑`zeros`区段表示，读取时按需生成，缓存不保存每首1MiB空白；完整复制文件则实际包含这些字节。超预算时不截断资料或扩大旧表示：仅该曲走原有精确准备，旧GET明确`content_changed`，刷新目录后取得新的准确表示。APE未启用固定预算。

最终 `FileInfo` 继续随既有快照保存，不另建平行文件目录。表示身份由插件固定：精确准备路径使用音频与标签摘要，新按需路径使用音频身份、资料描述键及扫描代次，并由首次原子写入固定其实际计划；歌曲身份与目录出现身份分开。缓存引用和最终表示必须对应；刷新产生新表示，不能让旧引用悄悄读取新字节。

API0.1.6的可选`Context.cache`已在SQLite/D1上实现，JSON `get/put`支持`expiresAt`；0.1.7增加可选批量操作，0.1.9增加可选`putIfAbsent`。该原子操作在独立计划键保存首次胜出的完整值，SQLite事务和D1 batch使用相同语义；旧数据结构复用，不增加迁移。普通`put`仍可覆盖键，插件负责区分资料缓存与不可变计划。

小资料与永久计划分开：稳定辅助资料可按实例配置保留期，默认与0的含义统一见[缓存策略](cache-policy.md)；空结果仍短期重试，基本字段和音频版本沿用各自期限，临时地址不因长期资料缓存而延长。v4引用携带原表示、永久紧凑`tag-seed`、扫描代次和时间；首次读取的计划永久保存，资料TTL到期不改变旧引用字节。短期ready索引只决定未来刷新是否复用已准备引用；没有被读取的文件不生成计划。宿主按实例、代际和插件修订隔离并约束迟到写入，删除实例级联清理，不把资料塞进认证状态，不新增R2或整曲缓存。

## 格式与实施

本轮只取现有来源并集：MP3、FLAC、M4A，以及有上游 SDK 实现、尚缺真实来源样本的 QQ APE。网易云不增加 APE；WAV、OGG、Opus、DSD 等不因库支持而加入本轮。这不限制第三方插件输出其他格式；音质档位与实际容器分别判断。

可选工具固定 `node-taglib-sharp 6.0.3` 编码标签。MP3 使用兼容性优先的 ID3v2.3/UTF-16，FLAC 更新元数据块，APE 生成尾标签。M4A 不转移音频：旧 `moov` 原位变成等长 `free`，保留原 `mdat` 的位置和字节，在尾部追加更新后的 `moov`；只读取和处理元数据，不下载整曲。普通前/后置 `moov` 及原本没有音乐标签的布局已验证；分片 M4A 等不支持的变体明确返回错误，不隐式转码或整曲缓冲。具体格式局限见[工具说明](../../packages/audio-tags/README.md)。

文件准备按有界小页推进，重复歌曲/音质复用资料和表示计划；每日推荐后续页复用本次已取得的列表，不逐页重新取整个推荐。网易云新引用为`version:4`，既有v3延迟引用、v2计划引用及v1透传仍可读取；必要 seed 或计划缺失明确要求刷新，不能把原文件偷换到新标签身份下。歌词时间轴保存与播放器逐行滚动仍分别判断。

大封面由插件自己的存储codec按摘要共享，读取时恢复等价的字节区段；公共工具合同和核心不认识这种存储形式，最终大小、身份和音频保持一致。[按需挂载证据](../verification/lazy-mount-feasibility.md)记录本版链路与格式限制；[两阶段验证](../verification/deferred-catalogue.md)保留旧路径证据。清单完成不表示全库标签已准备，播放器入库仍需逐曲读取其需要的标签。
