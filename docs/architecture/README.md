# MusicFS 架构设计

日期：2026-10-20。状态：设计与当前实现并列说明，插件合同仍为 alpha。插件/实例、目录、共用协议和 UI 已接线；QQ 与[网易云](../verification/p2-netease-source.md)有真实扫码/目录/音频证据，[桌面启动/挂载](../desktop.md)与[Worker 后台发布](../worker.md)有正式入口及本地验证。真实云端、四目标运行/挂载和完整示例仍按台账收口。产品合同以 [统一需求](../../outputs/musicfs-requirements-and-technical-design.md) 为准，执行顺序以 [实施计划](../../outputs/musicfs-implementation-plan.md) 为准。

设计采用一个应用中的领域 Module、独立发布的插件合同，以及实际有差异的宿主 Adapter。Module 按其 Interface 能隐藏的业务责任划分，Interface 包括数据、调用顺序、失败与性能合同，不按文件行数或页面数量拆包。结构和流程见 [图表](diagrams.md)。

## 领域划分与所有权

| Module | 自己拥有的事实与行为 | 对调用者的主要 Interface |
|---|---|---|
| `extensions` 插件安装 | 插件身份、安装版本、兼容性、包清单与安装记录 | 解释包/版本策略、兼容安装和移除；不直接修改实例配置 |
| `sources` 来源实例 | 实例身份、插件关联、配置与认证状态、调用代际、插件私有状态保存 | 创建/配置/认证/删除实例、准备候选迁移；为目录与文件操作提供受实例约束的插件调用 |
| `library` 音乐目录 | 内容源引用、完整成功快照、布局版本、路径映射和读取句柄 | `list`、`stat`、`statMany`、`open`、刷新、保存布局；隐藏分页汇总、命名和快照选择 |
| 数据源插件 | 来源协议、认证含义、分类、完整分页、来源配置与音质、真实文件/读取事实 | 公开插件 Interface；不依赖核心内部、DAV 或数据库驱动 |
| `mounts` 桌面挂载 | 本地/远程 DAV 挂载定义、rclone 生命周期、就绪、卸载与残留识别 | 挂载、状态、卸载；只在桌面宿主装配 |

账号是部分来源内部概念，不单独建立与实例竞争的核心账号系统。`library` 不判断“无损”“推荐”或账号权益；插件不决定用户导出根路径，也不实现整套 WebDAV。实际音频去重由插件按自身策略完成，跨实例不合并凭据、内容或状态。

`extensions` 的安装版本与 `sources` 的配置/认证变化是不同事实。安装同一个插件不创建默认账号；插件移除不删除实例和布局，实例删除也不移除其他实例共用的插件包。插件包版本、公开合同版本、配置/私有状态版本和目录快照版本各有含义，不能用一个应用版本替代。

## 层级与依赖方向

| 层级 | 位置 | 可以知道什么 |
|---|---|---|
| 交互与协议 | `web`、`transport/http`、`transport/dav` | 公共管理结果或文件 Interface；前端只经 HTTP 访问后台 |
| 跨领域用例 | `application/change-plugin.ts` | 协调插件候选、实例迁移与宿主发布，不解释来源或持久状态内容 |
| 应用领域 | `core/extensions`、`core/sources`、`core/library` | 各自数据和行为；按下面的单向依赖调用其他 Module |
| 公开合同 | `packages/plugin-api` | 标准 JSON/字节类型、配置声明、来源目录、读取与错误语义 |
| 宿主与基础设施 | `hosts`、`infrastructure` | 实现领域声明的存储、代码加载/发布和系统能力 Interface |
| 装配入口 | `desktop.ts`、`worker.ts` | 选择实际 Adapter 并组成应用；不承载来源业务规则 |

领域依赖方向是 `library → sources → extensions`，都可依赖公开合同。跨领域安装由上层用例与宿主协调：检查包、冻结输入、准备代码、逐实例准备候选，最后整体条件激活；`extensions` 不回调 `sources` 或导入 `library`。刷新协调放在 `library`，认证协调放在 `sources`，迁移激活放在 `application/change-plugin.ts`，各只有一个所有者。其他单 Module 用例直接调用，不为所有请求增加同形的 Service/Manager 层。

存储和宿主 Interface 定义在使用它的 Module 内，实现从基础设施一侧依赖这些 Interface，由入口注入。只对已有真实差异建立 seam：SQLite/D1、桌面/Worker 安装执行、外部平台请求。使用普通工厂和参数装配，不引入通用 DI 容器、全应用事件总线或分布式调度框架。

禁止的依赖包括：公开合同 → 核心/宿主/React；示例插件 → 核心私有模块；核心 → 平台 SDK、Hono、Nephele 或 React；Worker 入口间接导入桌面挂载/本机数据库；前端导入后台实现。XML/HTTP 对象仅留在协议层，Cloudflare SDK 仅留在 Worker 发布 Adapter。淘汰的 Nephele/Node 桥接探针与专用依赖已归档到 Git 基线，产品 DAV 保持 Fetch 原生。

## 模块组织

```text
packages/plugin-api/          # 唯一需要独立提供给作者的公共类型/数据合同
src/
  application/change-plugin.ts # 真实跨 Module 的插件变更用例
  core/
    extensions/              # 包、兼容、安装计划与生命周期
    sources/                 # 实例、配置、认证与受约束插件调用
    library/                 # 内容源、快照、布局、命名和文件 Interface
  transport/
    http/                    # Hono 管理路由：输入检查、调用、响应映射
    dav/                     # 共用只读 Fetch DAV，复用 XML/Range 库
  infrastructure/
    persistence/             # Bun SQLite / D1，少量明确数据操作
    archives/                # zip.js 解包，包合同归 extensions
  hosts/
    desktop/                 # 插件加载、静态资源、应用目录与 mounts
    worker/                  # 模块注册、SDK 发布、绑定和静态资源
  web/                       # 页面、Query、RJSF 表单与认证步骤承载
  desktop.ts                 # 装配与启动
  worker.ts                  # 装配与 Fetch 入口
plugins/
  netease/                   # 必要上游模块、来源规则、配置 schema 与校验
  qq/                        # 与第三方相同的公共合同
tests/                       # 最小插件、协议样本、接口/集成与真实环境验证
```

这是实现职责图，不要求一开始创建全部空目录。每个领域 Module 只公开自身入口及实际 Adapter 所需的类型；内部算法、SQL 和辅助类型保持私有。避免把所有类型放进无所有者的 `shared`，也避免在 `service → manager → repository` 之间重复传同一组参数。

## 关键 Interface 与跨越 seam 的数据

插件 Interface 详见 [合同草案](plugin-interface.md)。它提供可浏览内容入口、分页目录、实际音频描述和读取，并独立声明配置与认证能力；不规定统一的歌曲模型或全局音质枚举。

`library` 向 DAV 提供 `list/stat/open`，路径解析后得到属于某实例、目录快照及实际文件的引用。`stat` 可接收路径或本次 `list` 返回的条目；library 用内部 WeakMap 复用条目已解析的目标，避免逐文件重读和命名整个父目录。条目序列化后回退普通路径解析；私有目标不进入 JSON，描述前仍检查来源代际。名称仅在实际冲突时计算稳定散列，不引入跨请求路径缓存。`open` 接收期望内容身份和范围，返回同一份实际音频的元数据与原生 Web Stream；协议层不再自己解析来源 URL。慢请求在存储事务外执行，只在发布结果时做条件提交。

`sources` 统一捕获实例上下文，检查安装状态，传入配置、私有状态快照和取消信号，调用插件，再条件接受返回的状态变化。插件通过公开结果提出新私有状态，不获得裸 SQLite/D1 句柄。平台库 Cookie 全局变量、直接落盘及全局会话刷新必须在插件内部适配，不允许核心为某个平台补专用分支。

代码准备留在真实宿主 seam：桌面 Adapter 写暂存包并加载不可变修订，Worker Adapter 组装预构建模块并用官方 SDK 发布/核对。`application/change-plugin.ts` 声明持久变更的存储合同，协调 `sources.preparePluginMigration` 与整体激活，不读取 Cookie 或音质配置的内部含义。代码集合、数据库和外部部署之间不存在全局事务；SDK 返回成功不等于业务已激活。

桌面与 Worker 共用该用例及 `plugin-change-sql.ts` 的条件提交计划。操作头、一次冻结的实例输入及逐实例候选保存在 SQLite/D1；Worker 专有代码块仍由其宿主管理。Worker 重读 registry 确认代码后，由含精确候选模块的新调用接棒，每次最多准备一个实例，另一步才整体激活。桌面使用同一个后台循环依次处理迁移和目录刷新，不增加第二套调度器。现已有[正式桌面/真实本地 D1 测试](../verification/p2-plugin-migration.md)；真实云端边界见 [ADR 0006](../adr/0006-worker-code-publication.md)。

## 配置与认证

插件声明 JSON Schema draft-07 和有限可序列化 UI 提示，实例保存自己的配置。前端采用 RJSF Ant Design 主题生成普通表单，Query 管理请求、轮询和草稿提交；核心用通用二维码、链接、验证码与输入步骤承载认证，不执行任意插件前端代码。

来源 Schema 不传 Zod/Ajv 实例、React 组件或任意回调。核心静态管理输入用 Zod；官方插件工具链优先在作者构建时用 Ajv standalone 生成 ESM 结构校验，后台调用其入口并归一化字段错误。第三方插件可自选内部校验库，满足同一 JSON Schema 与校验结果合同即可。来源可达性、当前账号能力及其他语义校验仍由插件执行。

这一区分避免 Worker 在运行时对新 Schema 执行动态代码编译。Ajv 的生成文件及 runtime 依赖需打包；前后端使用同一 Schema 并验证允许关键字的一致性，不能只凭表单通过就保存配置。[RJSF 主题](https://rjsf-team.github.io/react-jsonschema-form/docs/usage/themes/)、[Ajv standalone](https://ajv.js.org/standalone.html)

认证挑战由 `sources` 关联到实例与当前代际，插件解释下一步动作与结果。过期、取消、换号后到达的成功结果不能覆盖当前授权；凭据更新、业务配置和临时 UI 草稿分别保存，不把密钥回填到 Schema 默认值。

当前交互认证已持久化操作 ID、修订、步骤与来源戳。开始、取消和终态增加实例代际；完成同时提交私有状态，使等待期间的旧内容失效。取消先在 SQL 提交，再做来源清理。步骤与状态的接受由 SQLite/D1 同一条件写入完成，不用进程内锁代替跨请求一致性。管理界面只投影当前操作的公开步骤，配置变更清除交互记录。

两个示例在取得有效凭据后即返回complete，账号名称可省略；资料暂时失败归后续内容读取。网易云个人歌单首次需要UID时再查并保存，换号清旧UID。这样不会把有效凭据卡在已过期的二维码资料补全阶段，也不增加核心认证状态或放宽到期规则，见[正式入口验证](../verification/p2-session-lifecycle.md#后续收敛凭据保存即完成授权)。

## 状态、并发与持久化

| 逻辑记录 | 唯一写入所有者 | 必须保持的关系 |
|---|---|---|
| 安装记录与变更操作 | `extensions`；跨领域顺序由变更用例协调 | 不可变包身份、期望集合、实际运行集合与操作结果对应 |
| 实例配置、授权及插件私有状态 | `sources` | 实例身份稳定，删除/换号/配置变更使旧调用失效 |
| 内容快照与刷新进度 | `library` | 完整成功后发布；失败不覆盖最近成功内容 |
| 用户布局 | `library` | 来源刷新不写用户层级，缺失插件仍保留引用 |
| 桌面挂载状态 | `mounts` | 本次进程和真实挂载对应；关闭页面不等于卸载 |

表中是所有权，不固定为五张表。数据库操作按实际需要提供，例如读取实例快照、条件更新授权、暂存完整内容、条件切换快照；不建立通用 `Repository<T>`/多数据库插件框架。先用原生参数化 SQL 和官方 SQLite/D1 接口，事务与条件提交在各 Adapter 实测；查询与迁移显著增长时再评估 Drizzle。

会改变来源含义的配置、换号、退出或删除更新实例代际；授权续期的私有状态使用独立 CAS 版本，避免把普通 token 续期当作换号。目录刷新有自己的请求身份。发布结果须同时满足当前安装代际、实例代际与仍有效的刷新身份，条件检查与写入在数据库一侧完成；进程内锁和 `p-limit` 不提供跨 Worker isolate 保证。

刷新由 `library.refreshes` 统一编排：start 接收实例或单目录范围，step 至多调用一次插件分页，get/current 只投影公开进度，cancel 先持久化终态。每实例只有一个活动操作；普通缓存缺失复用有效操作，显式刷新替换旧操作。实例刷新先更新内容入口，再处理各入口及仍可达的已浏览子目录；`knownDirectoryRefs` 只提供已访问引用，新子目录首次浏览时再加载。遍历去重并有目录预算，每目录分别完整发布，部分失败记录明细并保留旧快照，布局不参与刷新写入。

分页条目按出现顺序暂存为行，游标和累计计数随检查点保存，最后一页成功才切换目录发布指针。慢来源请求在事务外执行；SQLite 事务与 D1 batch 执行同一组条件 SQL，提交必须匹配操作修订、租约、实例代际和安装代际。取消、替换、配置或插件变化后的迟到页不能发布。`snapshotHeader` 仅投影成功时间与计数，不拉回整份目录。旧 JSON 快照保持可读，不在升级时重写已有内容。

正式宿主使用延后准备：冷读取返回 `503 refresh_pending` 与原操作 ID，共用页面恢复进度并串行 POST step，桌面后台也会在页面关闭后续跑；若重启遇到尚未到期的旧租约，按持久租约最早到期时间唤醒，空闲时不设轮询。Worker 每次 HTTP 后台安排或定时调用最多推进一页，`waitUntil` 内不连续循环；每分钟 Cron 是无界面时的慢速续步。调用中断释放当前租约，操作可续跑；进程被终止时等待租约过期接管。兼容的内核同步辅助方法也调用同一检查点算法，不是另一套分页实现。取舍见 [ADR 0007](../adr/0007-durable-paged-refresh.md)。

真实网易云 4,158 曲需要 42 页，驱动了上述执行粒度调整。文件条目可提供完整可信的 `Entry.info`；library 在接受页面时校验，并随原条目暂存、完整发布。DAV 已列条目的 `statMany` 使用该快照元数据，按不同来源代际在批量前后检查，避免这条路径的逐文件来源调用与 D1 检查。旧插件缺 info 时仍保留实时 stat，不能获得同样的批量性能保证；单页插件成本和整目录描述、XML 生成的 CPU 仍需独立验证，不等于真实免费 Worker 验收。

分页统计与完整内容是同一快照：插件声明显示标签，并在每页报告增量计数，`library` 校验并汇总，失败保留旧内容及计数。QQ 和网易云使用它区分曲目和实际文件、隐藏/回退/合并版本；核心和 WebUI 不拥有这些字段的音乐含义。页面明确区分暂存进度和最近成功结果；`directoryStatus` 只投影当前有效快照的时间与计数，不触发来源读取，旧快照无统计时保持未知。统计保存在快照头，合同见 [0.1.2 统计语义](plugin-interface.md#稳定身份分页与目录)。

按需会话续期已由 `sources/renewal` 协调：插件先纯本地判断，必要时取得实例短租约并预留状态修订；SQLite/D1 使用共同SQL计划提交凭据及短期失败结果，防止跨控制器重复续期和旧完整状态抢写。续期完成后释放租约，内容操作和音频流继续并发；不把每次来源调用排进串行队列。有效期、登录渠道和下次检查时间归插件，核心不建定时登录。限定证据见[会话记录](../verification/p2-session-lifecycle.md)。

同步 SQL 不跨网络等待，Worker 的 `waitUntil` 不承担无限任务。没有测得普通读取需要额外并发控制前，不引入全局 `p-limit`。缓存使用实例、插件版本与实际内容身份，持久状态不依赖 Worker 内存，音频流不存入可共享的元数据缓存。

## 安装、更新与失败恢复

宿主通过 `extensions` 检查包/安装策略并准备确定的候选代码。结构升级用例一次冻结全部实例输入；代码就绪后通过 `sources` 转换/验证候选，逐实例暂存，再整体条件激活。无法确认外部发布结果时记为核对中，查询实际结果，不盲目重复部署或先报告成功。操作顺序与所有者见 [插件变更时序](diagrams.md#插件变更)。

桌面暂存新旧代码；Worker 候选集合保留当前活动修订与新修订，使新部署能在数据库切换前服务旧安装。每次调用核对自身可执行注册集合与安装记录；旧 isolate 缺少新修订时返回明确不可用结果，不改用其他版本。迁移激活要求冻结集合与当前实例双向一致，逐个匹配 ID、代际、状态修订，并匹配安装代际；新增/删除/修改任一实例都使整个切换失败。安装、全部候选配置/私有状态及 completed 在一个 SQLite 事务或 D1 batch 内切换，终态同时清除候选行及 Worker 暂存块。没有网络请求跨在此事务内。

绑定保留、部署已成功而数据库确认失败、数据库已记录候选而部署失败，都由原安装操作负责核对和恢复；清理当前/上一个必要修订也由其宿主执行侧负责，不让每个请求自行清理。副本切换和在途读取的实际影响仍属于 P0，不承诺这一设计已经实现零中断。

不能仅回退代码而假定已经变更的状态也能回退。首版要求更新失败保留可用版本，因此候选迁移须可暂存、保留旧状态或采用兼容数据演进；做不到时应在切换前明确拒绝该更新，而不是损坏现有实例。具体发布协议在 P0 验证，设计不承诺跨 Cloudflare 发布与 SQL 的原子提交。

移除先使该插件新的调用与提交失效，取消相关任务并按实际宿主清理代码；已有实例与布局仍保留。正在读取的流能否继续、何时结束由 P0 测量并说明，但不能在一条响应中拼接另一版本的字节。重装兼容版本重新验证状态后恢复，单独删除实例不会被旧任务复活。

## 音频与 DAV

目录条目提供稳定出现身份，实际文件另有内容身份；同曲重复位置不因音频去重丢失。列表可携带 `Entry.info`，其内容身份、大小和类型必须完整且对应确切字节，不是大小提示或临时地址；未知值不能伪造为 0。旧插件可省略 info 并保留实时 stat，不新增核心元数据准备阶段。单文件 HEAD/GET 的 stat 仍获取当前实际描述，GET 随后继续核对期望内容身份和真实字节。

插件负责来源定位、必要请求头、临时 URL 续期和范围取流。核心检验内容身份、总长度和实际返回范围，使用 Web Streams 的背压与取消，不缓冲完整歌曲。上游返回完整文件时不得伪装部分响应；DAV 库必须能接收该事实或返回明确结果。

Nephele 的固定版本 PoC 已执行：Bun 基础读取可用，本地 Worker 的 Node 桥接完整取流失败。按原备选收敛为一套共用 Fetch 只读 DAV，复用 xmldom 和 range-parser，不复制完整 DAV/文件系统。标准属性、HTTP 输入和错误映射留在 Adapter；PROPFIND 的子项只在实际请求 etag、大小、类型或 allprop 时懒调用一次 `statMany`，名称/类型标记/日期和 propname 直接使用目录视图。批量复用本次已列对象的私有解析目标和快照 info，缺 info 的旧条目才逐项回退实时 stat；全部描述完成后再核对各来源代际，变化的来源整组返回错误。父项仍先 stat；单文件 HEAD/GET 不走该批量捷径。本次不声称已解决所有大目录云端预算。Worker 使用官方 FixedLengthStream，Bun 可采用合法 chunked framing。具体方法范围、候选证据及取舍见 [ADR 0004](../adr/0004-shared-fetch-readonly-dav.md)。来源插件不导入任何 DAV 框架。

## 验证与实施约束

接口测试从调用者实际使用的 seam 进入：真实 SQLite/本地 D1 验证条件提交，标准流和固定字节验证读取，最小插件验证公共合同，外部平台测试验证真实接口。模拟平台响应可验证本地业务，但不证明扫码或 CF 出口可用。

dependency-cruiser 在首轮源码建立后检查循环、跨层及 Worker 的间接桌面依赖；两宿主实际构建检查动态加载和打包结果。规则不替代运行，也不把依赖图工具当插件沙箱。每个新增通用机制先核查现有库；适配失败时定位缺失合同，比较修正或替换依赖的整体成本，避免在路由、实例和插件中重复打补丁。
