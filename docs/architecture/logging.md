# 日志与 IO 诊断

[English](../en/logging.md)

日志用于解释 WebDAV 访问和核心上下游 IO：播放器请求是否到达、耗时发生在哪一层、缓存是否请求来源字节、音频在何处中断。持久刷新和插件任务仍以已有操作记录为准，日志不建立另一套任务数据库。

## 位置与默认行为

| 范围 | 位置 | 默认记录 |
|---|---|---|
| 桌面应用 | 数据目录 `logs/musicfs.log` | 默认 info：启动、配置及刷新终态；2 MiB 轮转，保留 3 份备份 |
| rclone 挂载及远程 WebDAV | 数据目录 `mounts/rclone.log` | 原生 JSON ERROR 日志，2 MiB 轮转，保留 3 份备份 |
| 进程启动失败 | 原有 `startup.log`、`launcher.log` | 启动器提示、运行时崩溃输出；与应用 IO 日志分开 |
| Worker | Cloudflare Worker 的 Observability | 应用警告、错误和未捕获异常；模板关闭逐次调用日志和 traces |

桌面在「设置 → 日志与诊断」分别调整应用和挂载/缓存日志，立即生效并保存，无需退出后台或重新挂载。应用默认 `info`，正常访问仍只在 `debug` 记录；rclone 默认 `ERROR`。rclone 使用官方 `options/set` 更新已有进程，尚未使用时只保存设置，不为日志启动原生服务。

复现问题前选择「详细」，之后点击「下载日志」。ZIP 包含应用、MusicFS 管理的 rclone、启动器日志及版本、构建修订、进程号、启动时间、实际设置和网络环境摘要；网络摘要记录 Bun 版本、系统与架构、代理主机及端口、是否配置绕过规则，不包含代理凭据或完整绕过名单。它不包含账号配置、数据库或授权状态。应用及 rclone 各取当前日志与最多三份备份，每个文件最多取末尾 2 MiB，摘要标明截取项。

无已保存设置时，桌面仍可通过 `MUSICFS_LOG_LEVEL` 选择启动级别；页面保存的设置在后续启动优先使用。Worker 继续通过同名运行变量配置，未设置时为 `warning`，在 Cloudflare 修改变量后部署生效；不新增 D1 配置轮询或云端日志存储。

源码开发服务复用相同日志装配。文件日志不可写时回退到进程输出，不让诊断功能阻塞服务启动。

IO 类别按事件、错误代码、来源故障及处理阶段区分；出站请求还区分目标主机与方法，使 API 故障不挤占 CDN 的样本。同类记录每分钟最多保留 20 条，超出部分由 LogTape 汇总被抑制数量；最多追踪 128 种事件键。请求编号、资源键和 Range 不进入限流键。正常请求只在 debug 记录，不逐歌曲、逐 SQL、逐音频块写日志。请求计时表示响应头就绪，音频流计时才表示消费结束，二者不互相替代。

## 关联链路

```mermaid
flowchart LR
  Client[播放器 / 挂载] --> DAV[WebDAV 请求 ID]
  DAV --> Library[目录与文件视图]
  Library --> Source[来源操作与实例 ID]
  Source --> Fetch[来源 API / 媒体连接\n出站 ID、目标、代理摘要]
  DAV --> Cache[桌面共享缓存]
  Cache --> Native[rclone VFS]
  Native --> Back[内部 DAV 与资源键]
  Back --> Library
  DAV --> End[完成 / 取消 / 流中断与字节数]
```

Hono 负责请求 ID，LogTape 的异步上下文关联同一次调用内的来源操作和上游连接。共享缓存跨原生进程后以不可变资源键辅助关联。`source`、`cache`、`rclone`、`dav` 类别区分平台请求、本机缓存连接、挂载控制和对播放器的输出。

每次出站调用有独立的 `upstreamRequestId`，debug 记录开始与响应头就绪；连接失败在默认级别记录。字段包含目标协议、主机、端口、请求 Range、最终响应主机及重定向标志、声明长度、Content-Range、媒体类型和可用的 Retry-After 秒数。响应对象和正文保持原样；成功响应的附加字段按 LogTape 级别延迟计算。

桌面另外记录代理模式：环境配置、显式代理、显式禁用、会话或 Unix socket。代理环境只保留两种大小写的配置名与主机/端口；`NO_PROXY` 仅记录是否配置，实际优先级和绕过匹配仍由 Bun 决定，不在诊断中复制代理规则。Worker 保持平台模式，不读取桌面环境变量。

连接错误按已有错误代码区分 DNS、连接建立、代理、TLS、网络超时与连接重置；`request` 表示尚不能细分。`ioStage: headers` 表示请求至响应头这一阶段，该阶段连接失败时尚未取得响应头；它不是 DNS/TCP/TLS 分段计时。`timedOut` 表示调用信号触发的超时；底层 ETIMEDOUT 等通过 `connectionFailure` 单独表达。存在时保留系统错误号、syscall、目标地址和端口；cause 与 AggregateError 子错误有界展开，便于看出 IPv4/IPv6 等多个连接尝试，不记录原始错误消息。

缓存链路记录 `native` 或 `bypass`、文件大小、实际请求区段和字节数；内部回源事件表示缓存确实请求了来源字节，不把“经过 VFS”伪称为缓存命中。外层与回源区段可以通过资源键比较。命中率和原生缓存容量仍查询 rclone 已有状态接口，不为日志追加查询。

DAV 的 5xx 默认记录，包括等待文件准备的 503。记录中带请求 ID、HTTP 方法、Range、发生阶段和可用的准备任务编号；正常等待使用独立事件，不挤占其它故障的样本。

来源操作同时观察 HTTP 连接与插件返回结果。即使上游 HTTP 为 200，插件返回限流、认证或暂时故障时也记录其类型和冷却时间；后台刷新记录终态和失败摘要，详细模式增加检查点。

音频流只在 EOF、取消或错误时记录一次结果，包含预期/实际字节、读取范围、内容身份、耗时及末次数据间隔；`firstReadWaitMs` 和 `maxReadWaitMs` 分别记录首次与最长一次 `reader.read()` 的等待，不把消费者两次拉取之间的停顿计入读取等待。区分提前 EOF、流错误和请求/消费者取消。背压和取消继续传递，正常 seek 取消不作为警告，超时仍记为警告。HTTP 500 返回可复制的错误编号，重复事件按 IO 类别限量。

DAV 在响应头返回前遇到已取消的请求时，以 499 结束处理，仅记录 debug 级取消事件；客户端通常已断开，不依赖它接收此状态。判断以请求 signal 为准，不把任意名为 AbortError 的异常视为正常取消。TimeoutError 仍进入故障日志；响应头后的流完成、取消与中断由流观察器记录。

## 职责与依赖

采用 [LogTape](https://logtape.org/manual/start) 管理级别、上下文、结构化记录和高频限量；桌面轮转交给 `@logtape/file`，rclone 使用自身轮转参数。它支持 Bun 与边缘运行时，核心包没有传递依赖，避免为 Worker 引入桌面文件日志或另外一套日志实现。Pino、Winston 更适合已有 Node 日志栈的项目，本项目优先统一两宿主。

桌面诊断控制器拥有日志输出和 `diagnostics.json`，通过 LogTape 过滤器和 rclone 控制口应用级别；配置不进入音乐核心、来源设置或音频缓存身份。

日志装配归宿主，采集归传输和 IO 适配边界。领域层不导入日志库；来源异常使用标准 Error cause 保留诊断关系，面向用户的错误语义不变。不会读取响应正文来记录日志，也不会因为观测产生额外平台请求。

应用日志选择请求/操作 ID、目标主机与端口、路由模板、状态、耗时、字节数、错误类型/代码与栈位置；不传入完整 URL、查询参数、凭据、Cookie、请求正文、音乐路径或原始上游错误消息。原生工具日志由工具管理，公开问题记录只保留必要且去标识的信息。

Cloudflare 默认记录应用事件、关闭每次访问的 invocation log，减少扫描和 Range 请求的记录量；没有额外日志服务、Tail Worker 或日志数据库。现有部署自定义配置继续保留。[Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)、[rclone 日志](https://rclone.org/docs/#logging)
