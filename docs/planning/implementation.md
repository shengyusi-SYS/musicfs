# MusicFS 实施与交付计划

当前能力见[统一需求](../requirements.md)和[架构](../architecture/README.md)，当前产物见[发行页](../release.md)，实际验证范围见[验收台账](../verification.md)。本页只维护后续取舍，不重复逐版本进度和已完成工作量。

## 当前结论

性能主线已按[Codex 完成标准](../codex-goal.md)收口，现有证据下没有待执行的高 ROI 优化项。来源请求减法、按需文件表示、分层缓存、共享读取和小幅更新复用均已接入各自所有者模块；实际场景比较与停止依据见[性能复评](performance-review.md#当前roi停止决定)。

自动更新和文件名模板的现行合同归[调度与命名](../architecture/updates-and-naming.md)，桌面常驻与管理登录归[桌面指南](../desktop.md)和[管理访问](../architecture/management-access.md)。已完成的中间方案和旧工期从 Git 历史追溯。

## 保留的优化候选

| 候选 | 当前决定 | 重开依据 |
|---|---|---|
| 网易云跨读取地址复用 | 延后，保留同表示内容核对 | 有方案能保留核对且实际减少来源请求 |
| 跨插件升级保留资料和计划 | 不建设通用迁移框架 | 升级后的冷重建成为主要瓶颈，作者能声明兼容范围 |
| QQ 大封面存储格式 | 保留现状，热路径已减少反复读取 | 真实容量或冷计划读写成为瓶颈 |
| XML 库或完整响应缓存 | 保留现有依赖 | 描述复用后 XML 仍造成可见等待或资源超额 |
| 增大来源批量 | 保持已验证默认 | 上游完整性和支持范围有新证据，不反复试探阈值 |
| 更多缓存引擎和预读参数 | 当前停止 | 出现[具体缓存缺口](cache-optimization.md#剩余风险与重开条件) |

## 新任务如何进入主线

1. 沿实际入口分清目录枚举、文件属性、标签准备、播放器扫描和音频下载，先取得能改变判断的样本。
2. 优先在已有所有者模块减少重复工作；未知方案用有停止条件的小样本比较，不同时建设多套机制。
3. 按用户收益估定位、实现、受影响验证和交付成本；已完成路径不重复计入，互斥方案不相加，环境等待与开发时间分开。
4. 按行为提交，集中构建所需目标，产物保存在 `dist/releases/<版本>/`；文档整理本身不要求重建旧发行物。

原生系统全矩阵、免费云端额度及自然续期等未验范围只在验收台账保留，待实际变更需要或用户安排时再执行。
