# MusicFS 使用说明

本包是开发预览，提供插件式只读音乐文件服务。Linux 已有原生运行与挂载证据；Windows、两种 macOS 及真实 Cloudflare 仍需对应环境验收。构建成功不代表这些环境已通过。

下列文件路径均相对解压后的发行目录。普通桌面使用不需要安装 Bun、Node.js 或 rclone；rclone 已随包提供。

## 启动桌面服务

1. 解压对应系统的完整 ZIP。保留程序、`resources` 和其他随包文件的位置；macOS 保留完整的 `MusicFS.app`。
2. Linux 打开 `musicfs`，Windows 打开 `MusicFS.exe`，macOS 打开 `MusicFS.app`。程序启动后台，并在默认浏览器打开管理页面。
3. 再次打开程序会回到已有后台。关闭浏览器页面后服务和挂载继续运行；需要停止时，在“服务连接”点击“退出 MusicFS”。有文件正在占用挂载时，先关闭该文件，再重试。

配置、授权、布局与挂载定义保存在当前用户的 MusicFS 数据目录，不在解压目录。更新时正常退出后台，换用完整的新发行目录，再启动；保留用户数据目录。发行包不含任何账号或默认管理密码，启动器会生成当前本机凭据。

## 安装插件并建立来源

1. 在“插件 → 安装插件”选择作者的 ZIP，或填写可直接下载 ZIP 的发布地址。先检查插件身份、版本、接口和宿主兼容性，再点击安装。
2. 桌面发行目录 `plugins/`、Worker发行目录 `plugin-packages/` 提供最小来源、QQ、网易云三个独立插件包。它们没有自动激活，按需安装；示例平台能力不影响其他来源接入。
3. 在“数据源 → 添加数据源”创建实例并填写配置。一个插件可以创建多个实例，各自保存配置、认证和内容。需要登录时按页面扫码或执行该插件声明的步骤。
4. QQ 和微信登录可能对应不同音乐账号。“收藏歌单”是整张歌单，不包含专辑或歌手收藏；曲目数量与可导出的实际文件数量分别显示。

更新插件时选择新 ZIP 或发布地址。更新失败保留当前可用版本；移除插件保留实例及布局引用，重装兼容插件后可恢复。删除实例数据是独立操作。

需要清除此实例的登录时，点击实例行的“退出授权”并确认。配置和目录布局保留，后续读取需重新授权；其他实例不受影响。这只清除 MusicFS 保存的授权，不会退出手机上的音乐 App。

## 准备和组织目录

在实例的“内容源”刷新需要的入口，等待显示完成；然后到“目录布局”添加来源、安排分组并保存发布。新歌单等子目录可在已发布目录预览中打开并准备。

桌面后台会继续准备，Worker 在关闭页面后由定时步骤慢速续跑；重新打开页面可以查看同一操作。大集合留在页面中推进会更快。失败刷新保留最近成功内容，网络或限流问题可稍后重试。

如果来源明确提示授权失效，点击错误旁的“重新授权”，按插件步骤完成登录后再次读取。授权窗口中的“上次授权流程已完成”是历史操作记录；来源要求重新授权时，以当前错误提示为准。重新登录保留实例配置和目录布局。

首次从读取客户端进入尚未准备的目录，可能得到503；回到管理页完成准备后重试。布局名称由用户保存，来源刷新不覆盖它。

## 连接客户端和挂载

在“服务连接”复制 WebDAV 地址、读取用户名和读取密码，填入支持 WebDAV 的播放器。管理令牌用于管理页面，读取密码用于客户端。

桌面默认只允许本机访问。要让同一局域网中的设备连接，在“服务连接 → 桌面网络”选择“局域网设备”，设置端口并保存；正常退出后台后，重新点击启动器。启用后页面列出可复制的局域网 DAV 地址。端口 `0` 表示自动分配；固定端口便于客户端保存连接。端口占用时后台会改用可用端口，以页面实际地址为准。此设置不配置路由器或公网转发。

OpenList 选择 WebDAV 驱动，地址使用完整 DAV 地址，根文件夹填 `/`，供应商选“其他”，开启“网页代理”，WebDAV策略保持本机代理。MusicFS 刷新后若仍显示旧内容，再使用 OpenList 自身的目录刷新。另一台机器或容器内的 `127.0.0.1` 指向它自己，填写该环境实际可访问的服务地址。

桌面页面可挂载本地 MusicFS 或远程 DAV。远程连接分别填写 DAV 地址、用户名和密码，本地无需再次登录远端音乐平台。需要系统提供以下挂载能力：

| 系统 | 挂载条件 |
|---|---|
| Linux | FUSE、`fusermount3`或`fusermount`及当前用户使用权限，选择空目录 |
| Windows | WinFsp，选择空闲盘符或未存在的目录挂载点 |
| macOS | 系统NFS挂载工具与相应权限；当前路线仍待原生验收 |

挂载、卸载或启动失败时，页面或启动提示提供原因和日志位置。先处理实际报错，例如驱动缺失、目录占用或来源需要认证。

## 独立部署 Worker

Worker ZIP 包含共用页面、模块、插件注册表、D1迁移和 `wrangler.jsonc`。首次部署需要自己的 Cloudflare 账号及官方 Wrangler 工具；真实免费计划及云出口尚未验收。

在 Worker 解压目录执行，按命令输出填写自己的 D1 ID及账号配置：

```sh
bunx wrangler d1 create musicfs
# 编辑 wrangler.jsonc 中的D1 ID、CF_ACCOUNT_ID和Worker名称。
bunx wrangler d1 migrations apply musicfs --remote
bunx wrangler secret put ADMIN_TOKEN
bunx wrangler secret put DAV_USERNAME
bunx wrangler secret put DAV_PASSWORD
bunx wrangler secret put CF_API_TOKEN
bunx wrangler deploy
```

部署后打开 Worker 地址并输入管理令牌。注册表内的代码不会自行激活插件；从WebUI上传本发行目录`plugin-packages/`中的ZIP或填写作者发布地址，后台自动组装发布，等操作显示完成。`plugins/`中的展开模块由部署使用，不是安装包。后续安装插件无需重新编译核心或页面。发布Token由Worker保存；它必须具备对应账号与Worker的读取及编辑能力。

修改核心版本前先按新包迁移数据库，再部署对应模块；保留已有D1和Secrets。用户配置和授权在D1中，不在插件模块中。当前自动发布的真实配置保留、切换影响及免费资源仍待云端验收。

## 随包资料

`release.json`或`bundle.json`记录当前构建身份；发行目录外的 `release-manifest.json` 和 `SHA256SUMS`用于核对归档与插件包。`licenses/`保存实际构建依赖的许可资料，桌面还包含固定Bun运行时说明和rclone原始README；插件ZIP保留各自许可。插件作者使用独立的 `plugin-author-kit`，按其README构建自己的来源。

MusicFS自行编写的代码、公开接口、工具及示例插件采用GPL-3.0-only，正文见随包`LICENSE`；第三方与另行标注文件保留各自许可。同次发行的`source.zip`包含项目源码、锁文件、测试和构建说明，开发复现入口为其中的`SOURCE.md`。
