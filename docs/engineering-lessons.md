# MusicFS 可复用工程经验

只记录本项目已经得到依据、以后仍有助于决策的结论。当前能力查[架构](architecture/README.md)，版本和实测查[验收台账](verification.md)；这里不保存任务进度、运行日志或临时环境信息，也不引入其他项目的规则。

## 从用户结果划分职责

- **插件能力与核心能力分开。** 来源认证、分类、音质、权益和资料映射由插件解释；核心管理安装、实例、快照、布局和文件访问。示例插件可用，不代表其平台特性应成为所有插件的必选合同。
- **先区分对象，再判断故障。** 登录渠道可能对应不同音乐账号，收藏专辑与收藏歌单也不同。返回空列表时先核对账号、内容对象和可导出文件，不直接归因为缓存、权限或接口失败。
- **歌曲、出现位置、实际媒体与最终文件表示分别建模。** 同曲可在歌单重复出现，也可对应多个音质或容器；补标签又会改变最终字节。按歌曲 ID 去重不能代替文件表示去重。
- **音乐资料补全是插件的可选实现。** 可透传、自带补标签或复用格式工具；核心只要求最终大小、身份与读取字节一致。仅覆盖来源实际提供的格式，不因某个库支持就增加产品范围。
- **资料存在、标签写入与播放器展示分开。** 来源缺失字段不猜测，已有歌词时间轴、译文和罗马音保留；不为补标签转码或跨平台搜配。成功内嵌不证明播放器会显示多位歌手或逐行歌词，兼容结论须对应实际字段和消费者。
- **凭据就绪与资料齐全分开。** 有效授权不应因昵称等补充资料暂时失败而卡在二维码过期状态；后续需要资料时再补齐。SDK 能轮换凭据，也不代表宿主已经保存轮换结果。

## 性能：减少必要路径上的工作

- **沿真实消费者追踪。** 目录枚举成功只证明清单路径；资源管理器和播放器还会打开文件读取标签、时长及码率。探针若禁止文件读取，就不能解释实际入库或重进目录的耗时。
- **先拆等待，再选异步。** 清单发布、准确文件属性、标签构造和音频读取是不同成本。延后非必要工作能缩短首次可用等待；后台跑同样的全库工作并不会自动减少成本。
- **入队与执行唤醒分别接通。** 常驻宿主在持久任务写入成功后统一通知执行器，独立监听器和内部读取入口不依赖管理页面推进。沿实际消费者验证空缓存访问能自行续步、发布并恢复响应，而不只验证任务已写入数据库；分页让步也应包含其他排队任务，不能只向前台 I/O 让步后继续独占全部页。
- **懒加载仍须兑现文件合同。** 客户端需要准确大小时，不能先报零或原文件大小再追加标签。固定预算与格式合法填充是有条件的办法，其代价是最终文件变大、超预算需要换表示；并非所有来源或格式都应采用。
- **优化要追到 SDK。** 完整歌单可能只有完整 ID 名单，SDK 的便捷方法也可能继续逐项请求。区分真正批量、重复拉名单和仅将多项业务包装成一次 HTTP；批量结果要核对 ID 完整性，HTTP 200 不证明未截断。
- **批次以实际工作预算决定。** 统一分页算法，按缓存冷热、来源请求、存储和运行时预算调整工作量。免费 Worker 不意味着每页固定极小，也不意味着能在一次后台调用跑完整库。
- **先找重复工作与放大点。** 复用已发布描述和路径索引、改善 SQL 查询计划、批量保存、减少重复图片与标签计划，比单纯加并发更直接。并发限制不等于平台 QPS 限流。
- **先核对现成的信任与复用合同。** 同一所有者的另一条生产路径可能已验证、保存并使用所需数据；应核对其身份、新鲜度与宿主成本，再决定复用，不因尚未另建一套机制就认定合同不存在。

## 缓存：明确缓存了什么

- **目录、资料、表示计划、临时地址与已读字节分别处理。** 延长目录 TTL 不会缓存音频；标签计划命中也不代表正文不回源。状态与配置应说明具体对象、实际模式及失效条件。
- **缓存命中依据最终表示身份。** 路径、文件大小、修改时间或临时 CDN URL 都不能单独识别所有更新。共享读取还须保留实例代际与插件修订检查，不能为命中而复用已退出账号的旧字节。
- **表示稳定与路径稳定分别判断。** 不变资料因刷新代次或SDK记账字段改变身份，也会触发额外工作；序号改名则影响按路径同步的消费者。减少前者不等于已解决后者，未准备索引也不能冒充已经固定的计划。
- **已发布字节保持稳定。** 资料 TTL 只影响后续准备或刷新；同一公开引用不能因为资料过期悄悄返回不同标签。按需首次构造须原子固定获胜计划，不能把可变的“最新计划”当不可变表示。
- **读取范围与缓存范围分开。** HTTP Range 只限制响应，不自动保存字节；条件请求依赖客户端参与。开放 GET 提前取消与完整短 Range 的缓存需求不同，后者命中不能证明前者已解决。
- **容量按工作集评估。** 长保留期不能阻止容量淘汰；扫描工作集放不下时可循环回源。稀疏文件的逻辑全长不等于实际占用，原生统计也可能滞后。
- **看实际运行值与持久复用。** 设计推荐开启不代表 VFS 实际启用；一次热读可能只命中句柄或系统页缓存。需要持久复用承诺时，正常重挂或重启后的同范围读取更有判别力。
- **共享缓存协调落盘所有权。** 同一次本机挂载读取避免再写一层服务端缓存；不同入口仍可有不同工作集。管理页查询、未使用功能的关闭，不应为了显示状态启动原生服务或遍历磁盘。
- **预读同时看字节、请求与等待。** 小缓冲可减少扫描放大，也可能增加 SDK/CDN 调用和播放等待。保留连续读取的合并或递增能力；没有净收益的调参应停止。一次重复打开可能读到新范围，不能承诺任意重开都零网络。

## 复用依赖与管理生命周期

- **先比较能力合同，再比较依赖名称。** HTTP 缓存策略、字节存储、范围协调与容量回收是不同能力。现有原生 VFS 可承担桌面片段缓存；缺少合适的 JavaScript 库，不等于必须自制完整缓存引擎。
- **共用语义，按宿主适配机制。** 桌面磁盘缓存与 Worker 流式读取可以共用文件和 DAV 合同；不为形式统一增加音频数据库、云存储或第二套领域算法。
- **资源所有权必须贯穿退出。** 多个功能复用原生进程时，由装配层安排卸载、停服务和关进程。停止接收新读取与正常退出属于同一流程；失败时恢复可操作状态，仅在退出前检查一次“空闲”仍可能留下窗口。
- **复用原业务协调，避免叠加重试。** 平台冷却、凭据轮换、刷新续步各由原所有者处理。网络等待不跨 SQL 事务，传输层不再无意叠加多轮重试，也不为新增入口复制一套队列。
- **系统限制放在宿主边界。** WinFsp 挂载与 Windows WebClient 原生映射是不同路径；认证、TLS、单文件上限分别定位。需要修改系统设置时保留实际原值和恢复归属，不能当作 WebDAV 版本问题统一处理。

- **检查依赖最终写出的系统格式。** 接受参数数组不证明注册命令正确编码；普通的空格、中文和特殊字符路径属于日常场景。复用现有库时核对序列化和实际用户范围，再决定最薄的平台适配。
- **区分可逆退出准备与永久关闭。** 正常退出可能因活动挂载被拒绝；先暂停并保留恢复函数，真正成功后再终结协调器。浏览器退出登录也应保留当前登录状态查询的订阅，避免移除缓存后界面仍观察旧对象。

## 验证与交付的适当粒度

- **证据不互相升级。** 源码测试、实际打包 SDK、本地 workerd、目标二进制、真实平台和消费客户端各证明一层；生成有效音频可验证解码与范围，不能替代真实平台延迟、整库 GUI 耗时或主观听感。
- **选择能改变决定的探针。** 优先正常用户旅程和本次变更涉及的更新、取消、缓存清理或退出边界。复用已有证据，不自动展开账号、格式、系统和故障的全排列；低 ROI 负结果同样可作为停止依据。
- **环境故障不直接修进产品。** 回环权限、VM 可达性与产品行为分开判断。仅使用已授权环境；禁止宿主操作时不跨越边界，也不因测试环境暂不可达而无限扩大网络排查。
- **远程命令与图形输入分别核实。** SSH 成功、helper 就绪、系统能发现图标，不等于输入桌面可用或菜单动作已完成。图形探针按控件类型和所属区域定位；环境限制时保留已完成的证据，必要时用一次实际操作补齐，不持续扩充测试框架。
- **工具返回句柄不等于执行完成。** 依赖文件传输、构建或服务启动的后续操作，应先等待对应会话结束或取得明确就绪结果。
- **发行围绕一致输入。** 源码、页面、插件和二进制身份需要匹配，按版本存放产物；目标系统证据对应实际被测构建。相邻小改动集中打包，纯文档整理不要求重建历史发行物。
- **每类事实只维护一个主入口。** 需求写用户结果，术语只写定义，架构写现行合同，计划写决定与重开条件，验证写有范围的证据，发行页写产物。旧结论被替代时重写当前说明，历史回到验证记录或 Git，不反复追加相互矛盾的“当前状态”。
