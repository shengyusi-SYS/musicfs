# QQ 原始分类、推荐歌单与内容分页

日期：2026-10-20。承接 [alpha.2 真实授权/音频记录](p1-qq-source.md)。本阶段插件为 `org.musicfs.qq@0.1.0-alpha.3`，SDK 固定 3.3.3，合同/配置/私有状态版本不变。后续 alpha.5 的音质、批量、计数和实际字节见[新记录](p2-qq-quality.md)。

## 实现与范围

通过 SDK 的 sealed resolver 和 session Musicu 客户端读取两个原始集合；生成的插件内部导出入口及升级约束见 [ADR 0005](../adr/0005-pinned-qq-sdk-read-adapter.md)。签名、加密、设备与传输继续复用依赖；没有修改 SDK 源码或新增核心/前端的 QQ 分支。

| 路径 | 当前行为 |
|---|---|
| 自建歌单 | `PlaylistBaseRead/GetPlaylistByUin` 原始集合；核对原始总数与完成标志，再按原生目录 ID 排除系统目录；不按歌单名判断 |
| 收藏歌单 | `PlaylistFavRead/CgiGetPlaylistFavInfo`，每次请求 size 100，以实际返回条数推进 offset；核对总数、空中断及后续总数变化 |
| 自建歌单内容 | 带当前账号凭据的 `DissInfo/CgiGetDiss`；保留 tid、dirId 与账号上下文，可读取本人的私有歌单 |
| 收藏/推荐歌单内容 | 带凭据的 `aiDissInfo/uniform_get_Dissinfo`，按明确总数完整续读；与 SDK 一致，不把读满总数后的不可靠 hasmore 当成新内容 |
| 推荐歌单 | SDK 公共推荐接口取 limit 25，作为有限目录快照；其 more 不表示 MusicFS 要无限续读推荐流 |
| 分页与引用 | 游标绑定目录；歌单引用包含角色和稳定来源身份，同一歌单可同时在自建/收藏中出现；曲序与重复位置保留 |
| 取消/错误 | 新原始读取路径通过 SDK 的 execution signal 传递宿主取消；凭据拒绝清除本实例候选会话，限流与临时失败分别返回 |

喜欢、每日推荐、认证和媒体链接仍有部分调用经 SDK 公共 facade；不能据此宣称所有 SDK 内部网络请求均已接入宿主取消。固定 128k 与音质/续期缺口也继续保留。

## 真实结果

- 经正式安装 API 将 alpha.2 更新到 alpha.3，原实例沿用已保存会话。正式刷新 API 取得五个内容源，共用页面的“内容源”面板及“刷新内容源”按钮也已验证；自建 0、收藏 0、推荐 25，均成功写入完整快照。
- 用户要求“刷新重试”后，再次强制刷新内容源、喜欢、自建和收藏，全部 HTTP 200 并生成新快照，三个账号集合仍为 0。进一步对照原始接口：自建原始总数 1，仅系统目录 201；该目录 songNum 为 0；喜欢接口 total 为 0；收藏 total 为 0。系统目录所属账号标识与当前凭据一致。这里只记录当前会话返回事实，不推断用户其他登录账号的内容。
- 发现真实边界并修复：空账号的系统目录可以带 `tid=0`。必须先根据有效系统目录 ID 排除，再校验普通歌单的 tid/名称；否则会错误拒绝整个自建集合。回归固定了这一情形。
- 非空推荐歌单内容首次读取取得 100 首和续读游标。随后选择一张 102 首的真实推荐歌单，经正式刷新 API 完整成功发布 29 个当前可读取的 128k 文件，约耗时 9.55 秒。不能把歌曲数与导出文件数混用。
- 实际安装 ESM 在本地 workerd/D1 无 Node 兼容开关运行：恢复真实会话，账号校验成功，每日推荐 5 个文件、自建 0、收藏 0、推荐 25。临时 D1 正常清理；没有执行云部署或 Worker 实播。

上述接口未修改 QQ 云端内容。账号、歌单 ID/名称、私有响应、二维码和临时音频均不进入本仓库证据。

## 微信登录与数据核对

用户确认新增数据在微信登录账号中。因此保留原手机 QQ 实例，另建独立微信实例，经共用二维码界面由用户扫码并确认。授权完成状态持久化；服务重启后无需再次扫码即可通过账号校验和正式目录刷新。

- 喜欢原始 total 为 1，原始自建集合 total 为 2，其中系统目录 201 有 1 首、普通自建歌单 1 张；系统所属账号与当前凭据一致。
- 正式刷新喜欢目录得到 0 个文件，自建目录得到 1 张歌单；自建内容通过带账号上下文的原始 owner 接口取得 1 首歌曲、0 个文件。两处当前都未获得完整 128k 地址。响应为明确无链接，SDK 提示“可能需要会员”，不能提升为已经证实的会员/地区原因，也不能用试听替代完整文件。
- 收藏歌单原始 total、条目数均为 0，未报告隐藏、失败或删除项。用户随后确认新增的是**专辑收藏**，与歌单收藏属于不同集合。该次报告没有证明目录缓存丢数据；前后账号不同和收藏对象类型足以解释所观察数量。没有为此加入错误回退或合并类别。
- 同一实际安装 ESM 在本地 workerd/D1 恢复微信会话并通过账号校验；每日推荐 2 个文件，自建 1 张、收藏歌单 0 张、推荐歌单 25 张。这里只验证了会话恢复与读取，没有 Worker 内真实扫码或云部署。

独立发现的刷新按钮范围问题及修复见[实例刷新记录](p1-instance-refresh.md)。本阶段统计仅由插件返回，不能把“0 个导出文件”标作“0 首歌曲”；后续已通过[通用计数持久化和共用界面](p2-qq-quality.md)补齐。
