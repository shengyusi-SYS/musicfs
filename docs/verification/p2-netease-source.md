## 喜欢目录失败的根因与修正

原 alpha.1 将播放信息按歌曲 ID 判重。真实第一页 100 ID/100 行，第二页 100 ID/102 行；多出的两组分别含同曲 `standard/MP3` 与 `lossless/FLAC`，大小和 MD5 不同。这是不同实际表示，不是缓存或不完整列表。

alpha.2 先确认响应 ID 集合与请求完整一致，再按目标 level、完整非试听选择候选；格式仅归一大小写。同目标 level 的实际引用一致时允许临时地址不同，冲突仍失败。未知/缺少 ID 仍拒绝，不因此默默降级。真实形状的 100/102 回归在已锁定 alpha.1 产物复现原错误，修正后通过；整个喜欢列表随后正式刷新成功。

## 必须继续的工作

alpha.2 的喜欢每页请求歌单列表、完整曲目 ID、歌曲详情和播放版本，42 页约 168 次来源请求。这足以证明一次 HTTP 读完不符合当前免费 Worker 的 50 外部子请求预算，每日小集合 workerd 通过不能替代。后续 alpha.4 减少重复定位，核心改为[持久分页](p2-durable-refresh.md)；每页完整 ID 和序列摘要检查仍保留，单页 CPU、真实云端及 DAV 元数据预算仍须独立测量。[官方 Worker 限额](https://developers.cloudflare.com/workers/platform/limits/)

其余真实格式、会话续期/失效重登、真实云端和播放器仍分别收口；非空自建/收藏及推荐歌单的后续限定结果见文末。4,158曲的本地成功不表示其他义务已完成。
