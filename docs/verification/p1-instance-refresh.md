# 实例刷新与单目录刷新

日期：2026-10-20。共用核心/HTTP/WebUI 的正式实现；本阶段 QQ 插件为 alpha.3，没有为刷新增加平台分支。后续分页计数、最近成功时间和音质结果见[alpha.5 记录](p2-qq-quality.md)。

## 复现与修复

原按钮“刷新内容源”调用 `createApi.refresh → POST {}`，只更新内容入口列表。歌曲目录已有有效快照时，下一次浏览仍使用旧内容。`bun test tests/instance-refresh.test.ts` 的首项通过真实 WebUI API 客户端、Hono、library 与 SQLite 复现：来源从 `old.wav` 改为 `new.wav` 后刷新，实际仍为 `old.wav`，断言失败。相同断言在修复后通过。API 客户端的 Fetch 依赖可注入，测试没有替换全局网络对象。

当前“刷新实例内容”发送 `{scope:"instance"}`，由 library 刷新入口、各入口目录及仍可达的已浏览子目录。新子树首次打开时加载。指定入口有“刷新目录”；保留原 `{}` 的仅入口语义，避免改变脚本已有调用。每目录独立完整发布，部分失败明确汇总并保留失败目录上次完整内容；布局不写入。取消或实例/插件代际变化停止后续操作，旧结果不能发布。遍历去重并默认限制 1000 个目录；不是长期后台任务或全部子树预读。

## 验证

- 6 项回归、23 次断言覆盖：页面刷新调用更新缓存叶目录、新子目录惰性读取、部分失败及恢复、用户布局保留、不可达旧引用、双实例隔离、目录循环、单目录/兼容空请求、输入互斥、配置变更、取消和目录预算。
- 完整测试 **88 项、373 次断言**通过。默认沙箱禁止测试监听 localhost，HTTP/DAV 全集在允许本地监听的环境重跑通过；三组类型检查与 **89 模块/257 依赖**检查通过。Web 构建通过，Schema 表单既有约 558 kB 分块警告保留。
- `bun run probe:worker:dav` 使用本地 workerd、真实 D1 适配器和共用管理路由；实例刷新返回 1 个目录成功，D1 中目录请求身份确实变化；原 HEAD、完整 WAV 与范围字节验证继续通过。没有真实 Cloudflare 部署。
- 共用浏览器页面从微信实例执行“刷新实例内容”，稳定显示 **6 个目录成功**：五个入口目录和已缓存的自建歌单内容。服务重启后沿用会话，页面可用。截图仅放在临时验证目录，不收录账号界面到仓库。

真实微信账号的数据核对见 [QQ 分类记录](p2-qq-catalog.md)：登录账号与收藏对象类型解释了本次用户报告，不能把独立发现的按钮范围修复当作该报告的已证实根因。完整树后台进度、失败目录的最近成功时间展示、云端大集合预算及全部 FR13 验收仍需继续。
