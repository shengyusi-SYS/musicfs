# 实例刷新与单目录刷新

日期：2026-10-20。共用核心/HTTP/WebUI 的正式实现；本阶段 QQ 插件为 alpha.3，没有为刷新增加平台分支。后续分页计数、最近成功时间和音质结果见[alpha.5 记录](p2-qq-quality.md)。

## 复现与修复

原按钮“刷新内容源”调用 `createApi.refresh → POST {}`，只更新内容入口列表。歌曲目录已有有效快照时，下一次浏览仍使用旧内容。`bun test tests/instance-refresh.test.ts` 的首项通过真实 WebUI API 客户端、Hono、library 与 SQLite 复现：来源从 `old.wav` 改为 `new.wav` 后刷新，实际仍为 `old.wav`，断言失败。相同断言在修复后通过。API 客户端的 Fetch 依赖可注入，测试没有替换全局网络对象。

“刷新实例内容”发送 `{scope:"instance"}`，由 library 刷新入口、各入口目录及仍可达的已浏览子目录。新子树首次打开时加载。指定入口有“刷新目录”；`{}` 保留仅入口语义。每目录独立完整发布，部分失败明确汇总并保留旧内容；布局不写入。遍历去重并默认限制 1000 个目录，不预读全部子树。后续已改成 `202 + operationId` 的持久分页和后台续步，当前接口及证据以[分页刷新记录](p2-durable-refresh.md)为准；下列首轮数字是当时基线。

## 验证

- 6 项回归、23 次断言覆盖：页面刷新调用更新缓存叶目录、新子目录惰性读取、部分失败及恢复、用户布局保留、不可达旧引用、双实例隔离、目录循环、单目录/兼容空请求、输入互斥、配置变更、取消和目录预算。
- 完整测试 **88 项、373 次断言**通过。默认沙箱禁止测试监听 localhost，HTTP/DAV 全集在允许本地监听的环境重跑通过；三组类型检查与 **89 模块/257 依赖**检查通过。Web 构建通过，Schema 表单既有约 558 kB 分块警告保留。
- `bun run probe:worker:dav` 使用本地 workerd、真实 D1 适配器和共用管理路由；实例刷新返回 1 个目录成功，D1 中目录请求身份确实变化；原 HEAD、完整 WAV 与范围字节验证继续通过。没有真实 Cloudflare 部署。
- 共用浏览器页面从微信实例执行“刷新实例内容”，稳定显示 **6 个目录成功**：五个入口目录和已缓存的自建歌单内容。服务重启后沿用会话，页面可用。截图仅放在临时验证目录，不收录账号界面到仓库。

## 目录失败标记的持久展示

2026-10-20复盘发现：失败保留内容已正确写入，但snapshotHeader查询只投影成功元数据，DirectoryStatus和页面无法恢复该目录独立error；另一个目录成功替换当前任务后，旧目录看起来一直成功。现将已有directory_snapshots.error经共同SQL投影到管理DTO，页面明确显示“刷新失败，保留最近成功内容”。任务失败时失效目录状态查询，不自动重新触发失败的roots准备；不增加数据库字段、任务或插件API。

正式HTTP/前端Api回归：A失败后仍读old.wav → B成功且成为当前任务 → 重建library/HTTP后A仍error=temporary且旧内容可读 → A成功后error=null并读新内容。SQLite和实际本地D1各在重新打开Adapter后核对error投影与保留。41项定向测试、821次断言及三组类型检查通过。完整检查与最终产物见[总台账](../verification.md)；这条证据不是实际浏览器或云端运行。

真实微信账号的数据核对见 [QQ 分类记录](p2-qq-catalog.md)：登录账号与收藏对象类型解释了本次用户报告，不能把独立发现的按钮范围修复当作该报告的已证实根因。后台页进度与最近成功统计后续已接线；真实云端预算及全部 FR13 验收仍需继续。
