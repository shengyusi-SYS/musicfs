2026-10-24，dev.29 使用独立管理与 WebDAV 端口，dev.30 核查消费链路并统一扫码地址选择；dev.27/dev.28 的共享监听记录作为历史保留。现行设计见[管理访问](../architecture/management-access.md#桌面访问范围)。Worker 的域名访问、插件、读取凭据和管理登录机制保持原合同。

## dev.30 消费链路核查

| 链路 | 地址所有者与核对结果 |
|---|---|
| 启动器、托盘与手机管理扫码 | 启动器读经认证的管理运行记录，托盘使用当前管理入口；手机二维码取 `managementUrls`。扩展既有网络用例，通过实际管理地址兑换 ticket，再用 Cookie 读取管理状态成功 |
| 播放器连接与导入二维码 | 复制地址与二维码都取实际 `davUrls`。修复连接页选择网卡后，扫码窗口重新选择第一张网卡的问题；两处共用选择。打开扫码时读取最新本机网络信息，再展示二维码 |
| App 本机挂载 | 使用内部回环 `readCache.mountConnection` 和独立凭据，公开 HTTP 端口变化不触发重挂载、不改变该连接 |
| 自动挂载 | 两个公开监听器就绪后启动恢复；持久配置保存 `source.kind=local`，重新挂载时取本轮内部地址。本次用例验证正常退出/重启后的自动恢复仍通过当前内部 DAV 列表检查 |
| Windows 原生 HTTPS 映射 | 使用 HTTPS 模块的独立回环端口与公开 DAV 凭据，路由只装配 DAV；两项 HTTP 端口不改变该地址。本轮为代码核查，运行证据沿用既有 HTTPS/Windows 记录 |
| 远程 WebDAV 挂载 | 保留用户填写的完整 URL 和凭据，不从本机管理地址推导端口；本轮为代码核查，沿用既有挂载生命周期证据 |

本轮只定向运行新增的本机挂载/自动恢复用例及扩展后的既有网络用例，两项均通过。前者使用正式服务、实际内部 HTTP DAV、挂载管理器与启动恢复，原生挂盘调用由替身接管；因此不作为新的 Windows/FUSE 实机结论。三套类型检查及正式页面构建通过，dev.29 的其余端口检查未重复执行。

内置浏览器在独立空白实例选择另一网卡，确认播放器导入沿用该地址与 DAV 端口；管理「手机访问」显示管理端口。仅验证地址选择，没有向该网卡地址发起播放或连通测试。没有访问音乐平台、调用 Windows 宿主或重复云端验证。

## dev.29 独立监听端口

| 用户结果 | 必要核对 |
|---|---|
| 管理与 WebDAV 端口不同 | 正式监听模块与桌面装配均验证两个实际端口；管理端口拒绝 DAV 路径，DAV 端口拒绝管理页面、API、ticket 和启动器身份路径 |
| 修改一项不影响另一项 | 单独换端口与访问范围、部分保存、同端口冲突、修改失败恢复已有入口；已有音频响应在 DAV 范围切换后读完 |
| 重启保留播放器地址 | 自动分配端口写入私有配置，正常退出重启后复用；某一指定端口被占用时只移动该项，保留另一项入口和原凭据 |
| 旧版升级保留读取入口 | 两种旧配置的访问范围分别保留，共享端口转为 DAV 端口；旧自动端口从同实例运行记录恢复，新管理端口单独分配 |
| 页面按实际端口工作 | 内置浏览器保存管理端口后跳转并保留登录；DAV 地址不随之改变。再保存 DAV 端口后管理地址不变，地址选择与导入二维码使用新 DAV 端口 |

监听模块、网络装配、读取缓存 HTTP 和两项启动器用例共13项定向检查通过；跳过长时间强杀/锁等待用例。三套类型、模块边界及正式页面构建通过。本机 HTTPS 改为直接装配 DAV 路由，App 本机挂载保留内部读取连接，公开 DAV 回退地址使用独立 DAV 端口。

内置浏览器使用独立空白桌面实例，系统集成关闭，未触及用户数据或真实音乐平台；截图见[WebDAV 独立端口](images/network-access-ports.jpg)。没有新增 Windows 原生挂载、Windows GUI 或云端运行证据。

## dev.27 访问范围（历史）

| 用户结果 | 证据 |
|---|---|
| 只开放 WebDAV，管理仍限本机 | 真实桌面后台通过 WSL 非回环地址读取 DAV；无凭据被拒，有读取凭据返回207。页面、登录/ticket、管理API及启动器身份端点返回403，即使携带有效管理凭据 |
| 只开放管理，WebDAV 仍限本机 | 同一端口切换后，管理凭据读取管理状态成功，读取凭据不能管理；非回环 DAV 返回403，本机 DAV 仍返回207 |
| 不信任请求头的本机身份 | 非回环 TCP 连接携带回环 Host 和转发头仍返回403；测试客户端的真实连接目标已核对 |
| 设置立即生效、重启保留 | 独立范围和固定端口保存、重启、私有文件权限、原凭据保留均通过；端口占用回退仍有管理入口 |
| 旧配置保持原范围 | 缺省两项仅本机；旧本机/局域网设置分别映射到两个入口，新字段独立读回 |
| 正在读取的响应完成 | 切换监听范围时已有响应读完；监听端口变化及失败保留既有回归通过 |
| 设置和二维码按用途呈现 | 内置浏览器保存管理本机、WebDAV局域网；管理扫码提示开启管理范围，播放器导入仍可选择局域网地址 |

9项定向测试、74个断言通过，范围为 `desktop-listener`、`desktop-network`、`desktop-read-cache-http`。类型检查、正式页面构建及依赖边界通过；302模块、1269依赖无违规。未新增依赖。

界面使用独立空白桌面后台，系统集成关闭，未操作用户现有数据。内置浏览器无法直连 WSL 的非回环地址，因此远程管理页主动关闭自身访问的结果提示、远程页的本机 DAV 地址展示没有额外浏览器通过结论；后端范围及鉴权已由真实非回环请求核对。本轮未进行 Windows、音乐平台或云端测试。

## dev.28 入口拆分

「设置 → 管理页面访问」只显示管理范围；WebDAV 的访问范围、地址选择、端口、凭据和扫码都在「连接与挂载 → WebDAV 播放器」，移除跳回管理设置的入口。共用 HTTP 监听端口及已有访问范围保持原合同，端口变更的影响在 WebDAV 页说明。

桌面网络 HTTP 与读取缓存的7项定向检查通过；浏览器 API 的部分保存覆盖单项修改和同时保存，确认另一项范围与端口保留。三套类型检查与正式页面构建通过。

内置浏览器使用独立空白桌面实例，确认设置页无 WebDAV 控件、播放器页保存后提供局域网地址选择与导入二维码，再返回设置确认管理仍为仅本机。截图见[管理访问独立入口](images/network-access-management.jpg)。系统集成关闭，没有访问真实音乐平台或用户数据，也未新增 Windows、云端或其他尺寸的验收。
