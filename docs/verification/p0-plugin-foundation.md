### 状态与取消反例

SQLite 接口测试使用可控制完成顺序的插件调用，验证：

- 某次目录调用失败时仍能保存已确认的授权状态续期，业务结果继续为失败。
- 配置变更、实例删除和插件移除后，旧调用的结果与私有状态写入均被拒绝。
- 同一状态修订上的并发提交只有一个成功；过期写入无法覆盖较新的状态。
- 配置校验可显式返回 `null` 清空私有状态。
- 即使插件忽略取消信号，已取消调用也不能提交状态。
- 过期调用返回的音频流在交给调用方之前被取消。

本地 workerd/D1 探针沿实际 SQL 验证：首次 CAS 成功、旧状态 CAS 失败、配置切换成功、旧 epoch 写入失败、移除后写入失败且两个实例保留。Worker 已部署注册集合缺少数据库当前修订时明确拒绝执行，未静默替换版本。重启本地 Worker 后再次读取配置和 WAV 头成功。

### 包与加载

最小插件只引用公开类型与自己的内部校验，输出一秒 8 kHz、16-bit mono WAV，共 16,044 字节；样本使用整数计算保证两宿主字节确定。它没有认证、歌单或音质概念。桌面探针检查 `RIFF` 头和末尾 16 字节在重启前后的摘要一致。

ZIP 解析使用 zip.js native 入口，关闭 Web Workers 和 CompressionStream，启用严格归档、CRC 与重叠检查；实际解压输出计数。当前初始预算为压缩 8 MiB、总解压 32 MiB、单文件 16 MiB、256 个条目，可由调用者调整，尚未经免费 Worker 资源验证。

zip.js 内部保留可选 codec 的动态导入，Miniflare 的自动模块发现因此拒绝该包。探针改用公开支持的显式 ESM 模块清单后实际执行通过，无需修改库内部源码。其余压缩格式和动态 codec 不在插件包的当前验证范围内。归档库的最终取舍仍需同规模资源验证，当前 zip.js 是已跑通的实现候选。
