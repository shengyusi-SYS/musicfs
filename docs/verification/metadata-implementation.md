# 示例插件的音乐资料补全与读取

日期：2026-10-21。实现提交：`d339213`。当前源码已实现，QQ `0.1.0-alpha.11`、网易云 `0.1.0-alpha.9` 开发包已构建。公开 API 为 `0.1.6`，数据库迁移至 schema 8。本记录接续[前期可行性实验](metadata-tagging-feasibility.md)，不改写已冻结的旧发行包或现有云端部署。

## 已交付的行为

两个示例插件在目录分页准备时取得来源资料，将歌名、多位歌手、专辑、专辑艺术家、发行日期、原专辑曲号/碟号、封面及歌词写入最终音频表示。保留来源已有时间轴、译文与罗马音；缺少资料时不生成或跨平台搜索。音频编码和音质不变。

来源字段映射、获取与更新由插件负责；[可选音频工具](../../packages/audio-tags/README.md)只负责格式标签及字节区段。其他插件可以自行补标签或直接透传，核心没有强制音乐处理阶段。最终大小、内容身份和 Range 均对应补标签后的字节，见[架构](../architecture/audio-tags.md)和[流程图](../architecture/diagrams.md#可选标签处理设计)。

通用 `Context.cache?` 复用 SQLite/D1，只有 JSON `get/put`。示例按歌曲/专辑缓存资料 24 小时，按内容身份保存最终表示计划；计划不保存临时媒体 URL。实例、代际和插件修订隔离缓存。`stat` 读取已准备的最终描述，`open` 在本次调用内取得新媒体地址，再流式组合原音频区段和小标签区段。没有新增整曲缓存、R2 或调度器。

新文件引用为 `version:2`，旧 `version:1` 仍按旧表示透传。安装新示例包前先升级核心/API 与迁移；刷新目录后生成新的补标签引用。不能在旧引用的原大小和内容身份下悄悄替换字节。

## 格式及 M4A 方案

| 格式 | 实现 | 当前验证边界 |
|---|---|---|
| MP3 | 现成库生成 ID3v2.3/UTF-16 标签，再接原音频区段 | 合成样本和两个来源各一首真实歌曲；完整日期写入 TYER/TDAT，独立解析的统一字段只显示年份 |
| FLAC | 现成库生成注释/图片块，保留原音频帧 | 离线合成样本及范围读取；本轮不另取真实歌曲 |
| APE | 生成 APEv2 尾标签，保留原媒体区段 | 结构夹具和此前官方小样本；QQ SDK 支持该格式，但尚无真实 QQ APE 读取证据；网易云不增加 APE |
| M4A | 只读写容器元数据，保持 `mdat` 原位置和字节 | 普通前置/后置 `moov`、无原音乐标签及实际 workerd/DAV；不覆盖分片 MP4 等特殊布局 |

M4A 没有套用 MP3 前缀。旧 `moov` 原位变为等长 `free`，更新后的 `moov` 追加在尾部，音频的绝对偏移保持不变，因此不需要重写 `stco/co64` 或下载整曲。标签编码仍用固定版本 `node-taglib-sharp 6.0.3`，不是自行实现 MP4 编辑器。

| 比较路线 | 结论 |
|---|---|
| 通用整文件 buffer 保存 | 标签可写，但整曲等待和内存没有必要，因此未采用 |
| MP4Box.js 等容器库 | 提供解析/重封装能力，仍需适配标签编辑和最终区段；当前没有引入另一套容器依赖的收益。参见[官方说明](https://github.com/gpac/mp4box.js/blob/main/README.md) |
| 原位置保留音频、尾部追加元数据 | 已实现；处理范围小，播放器需支持普通文件定位/Range |

一秒合成 M4A 的前后两种布局，各只读取 **1,002 字节元数据、6 个小范围**，准备时未读取 `mdat` 音频载荷。生成后独立解析的字段、封面和歌词正确，抽取的音频 payload SHA-256 相同，首尾范围与最终文件一致。不是用这个小样本外推整曲 CPU 或内存；异常大的 `moov` 仍消耗对应的元数据内存。不支持的结构明确报错，不隐式整曲缓冲或转码。

## 已执行的必要验证

### 自动回归与构建

- 全套 `bun test` 覆盖 253 项：首次 252 通过，唯一失败是 QQ APE 测试仍期待旧 MIME `audio/ape`；实现沿用项目的 `audio/x-ape`，修正预期后该文件 5 项全部通过。没有为此重跑整套。
- 随后网易云 JPEG 响应别名修复经该插件 24 项、203 次断言通过。三组 TypeScript 检查通过；新增可选工具依赖边界检查通过。QQ、网易云独立 ZIP 均构建成功。
- 音频工具覆盖四格式标签、音频区段保持、跨区段 Range、取消、已有标签/无标签及多语言歌词；缓存覆盖真实 SQLite 与 Miniflare D1、失效/隔离和持久恢复。没有增加平台压力测试或反例全排列。

### 正式本地 workerd / D1 / DAV

可复用入口为 `bun scripts/probe-worker-audio-metadata.ts`，使用自有合成文件和隔离持久 D1，没有外部请求。

| 检查 | 实际结果 |
|---|---|
| 正式 sources → library → DAV | PROPFIND 207；HEAD 返回最终大小和媒体类型 |
| M4A 完整 GET | 原 17,336 字节，最终 20,961 字节；独立读回两位歌手、专辑、专辑艺术家、完整日期、3/12 曲号、2/2 碟号及封面 |
| 歌词 | 原文 0/500 ms 同步点、译文和罗马音保留 |
| 范围读取 | 元数据边界 16 字节与尾部 32 字节均为正确 206/Content-Range |
| workerd/D1 重建 | 复用计划，准备次数为 0；最终字节与 ETag 不变 |
| 实际 QQ/网易云构建模块 | 均在 `nodejs_compat` 独立 ESM 中初始化并读取配置，外部请求为 0 |

### 两个真实来源各一首

从现有已发布快照选择已知 MP3；既有本地数据库只读打开，会话只在内存使用。只取资料、封面和小音频范围，没有重刷账号目录、重新授权、下载完整歌曲或调用云端来源。

| 来源 | 实际输出 | 独立读回 |
|---|---|---|
| QQ | 最终 5,234,227 字节；本次读取 20,376 字节前缀 | 歌名、歌手、专辑、封面、原文时间歌词一致；来源未给碟号，不补造 |
| 网易云 | 最终 7,782,559 字节；本次读取 48,863 字节前缀 | 歌名、两位歌手、专辑、封面、原文时间歌词一致；来源给出原曲号/碟号 |

QQ 一次检查 13 个串行请求。网易云首次因实际 JPEG 被标成 `image/jpg` 失败，定向诊断并规范化该来源别名；修复后同一歌曲 10 个串行请求通过。没有扩大样本。两首均未返回译文/罗马音，这部分沿用受控夹具验证，不能写成真实账号已有这些资料。

## 成本与剩余边界

首次冷目录准备确实增加详情、封面、歌词和原文件头尾范围请求；小页和资料复用降低重复成本，不能宣称列目录无代价。已有计划的 `stat` 不重取音乐资料，`open` 不重复准备标签。本轮未扫描网易云大账号，也未以小样本给出免费 Worker 预算或吞吐承诺。

字段与歌词时间轴已内嵌，不代表所有播放器都会显示译文、封面或逐行滚动；本轮没有新增播放器 GUI 兼容矩阵。Windows 本机 MusicFS 挂载和原生 HTTPS 目录映射已另行验证，见[Windows 记录](p2-windows-mount.md)，不混同为播放器标签展示通过。

现有付费 Worker 和冻结发行归档未部署/重打包本次变更。双宿主代码、开发插件包和本地实际 workerd 链路已完成；真云升级或发行新版时需一并带入 API 0.1.6、schema 8 与新插件版本。
