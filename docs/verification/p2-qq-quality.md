# QQ 实例音质、实际文件与目录统计

日期：2026-10-20。当前包 `org.musicfs.qq@0.1.0-alpha.5`，合同 `>=0.1.2 <0.2.0`，配置/私有状态版本仍为 1。承接 [QQ 分类与微信验证](p2-qq-catalog.md)。这是已接线能力与限定实测，不代表双示例、云端或发布验收完成。

## 实现

| 职责 | 当前行为 |
|---|---|
| 实例配置 | 单版本恰好一档，多版本至少一档；支持 M4A、128k MP3、320k MP3、FLAC、APE。默认单版本 128k、隐藏；旧配置缺少 audio 时沿用该默认值。默认数组按每次校验复制，避免实例间共享可变配置 |
| 隐藏/回退 | 隐藏仅保留所选可用版本；回退在同曲同实例内向下查找。FLAC/APE 为同级格式，各自向 320k MP3 → 128k MP3 → M4A 回退，不互相当作较低一级 |
| 实际文件 | 以实际文件名/格式标注；多个目标落到同一实际文件时合并，歌单中的重复出现仍各自保留曲序。读取已发布 fileRef 时只请求该实际版本，不临时改为别的编码 |
| 解析与错误 | 原生 UrlGetVkey 通过固定 SDK 的 session Musicu 客户端批量执行。拒绝截断/错误关联/未知格式，排除 RS02 试听；认证、限流、网络和异常响应不通过回退掩盖 |
| APE | 复用 SDK 的文件存在规则；明确 size_ape 为 0 可视为缺失，资料未知时补读详情，仍不能确认则失败。避免把平台可能返回的无实际文件链接当作 APE 可用 |
| 范围与分发 | 复用 SDK StreamCdnSelector，调用内选择 CDN；探测限定为 1 字节并取消流。媒体仍校验实际大小、版本、范围、长度和取消 |
| 计数 | 插件报告每页曲目、文件、未导出曲目、缺失目标、回退目标与合并版本。核心只汇总通用整数计数并与完整目录一起发布，失败保留旧计数；统计名称由插件声明，共用前端不认识 QQ 音质枚举 |

`configuration` 管理默认值与 Schema；`catalog` 保留来源分类、分页和出现位置；`playback` 处理目标到实际版本、批量解析、文件引用和 CDN；`media` 处理字节描述与流；`client.rpcBatch` 复用 SDK 会话、认证头、错误和取消。SDK 仍固定 3.3.3，不改依赖源码、不替换全局 Fetch、不重写签名或加密。作者导出约束见 [ADR 0005](../adr/0005-pinned-qq-sdk-read-adapter.md)。

真实原生响应揭示了需要保留的关联：请求 filename 使用 songmid + media_mid，响应条目的 filename/songmid 仍绑定该请求，而 purl 的实际路径可规范化成单个 media_mid。先通过公开插件测试复现拒绝，再加入规范化路径的正例及无关文件的反例；文件引用保存规范化后的实际身份，没有私有 URL 或 vkey。

## 真实账号结果

同一次 30 首每日推荐，未改 QQ 云端内容：

| 目标与策略 | 实际输出 | 本次宿主 Fetch / SDK 内容调用 | 解析耗时 |
|---|---|---|---|
| 单版本 128k，隐藏 | 5 个 MP3，25 首未导出 | 1 / 1 | 约 425 ms |
| 多版本 FLAC、320k、128k、M4A，隐藏 | 5 个 MP3 + 5 个 M4A，25 首未导出，110 个目标版本缺失 | 1 / 1 | 约 318 ms |
| 单版本 FLAC，回退 | 5 个实际 128k 文件，5 个目标发生回退，25 首未导出 | 4 / 1 | 约 542 ms |

这里的宿主 Fetch 计数仅覆盖新原生批量路径；SDK 内容 facade 的内部网络未纳入该计数，因此单独列出 1 次 SDK 调用。它不是整个来源端的总网络请求数或云端 CPU 测量。每个原生描述符最多 50 个文件，每次 transport 最多 10 个描述符；相同曲目/媒体/档位只在本次调用内复用，列表阶段不逐曲下载或探测 CDN。

共用 RJSF 页面保存 QQ 测试实例的多版本 `[128,m4a]`，正式刷新显示 **30 首、10 个文件、25 首未导出、50 个目标版本缺失**。另一个微信实例仍为单版本默认值；共用页面显示 **喜欢 1 首、0 个文件**，每日推荐 30 首、2 个文件。目录与统计均有最近成功时间，读取统计不会再调用来源。截图、账号与歌曲标识仅保留于开发数据或 `/tmp`。

实际安装 ESM 在本地 workerd/D1、无 Node 兼容开关下恢复两种真实会话。原手机 QQ 会话多版本快照为 30 首/10 文件，微信会话为 30 首/4 文件；两者的 D1 统计与快照一致。没有 Worker 内真实扫码、云部署或免费计划配额实测。

## 字节证据

- MP3：2,570,671 字节，`audio/mpeg`，SHA-256 `df13ddcb250d1d644fe766deb9d8cbe807ee7b0111924cfd9e240d944baef700`；新解析路径的完整读取与首中尾范围通过。
- M4A：1,956,429 字节，`audio/mp4`，SHA-256 `1f3c0f231ef6189865eae6b815d78e5aace02f84d9f3b9c767ac2e148f031818`；ffprobe 确认 AAC、44.1 kHz、双声道，约 160.636 秒。
- M4A 经正式 WebDAV 执行 HEAD、完整 GET、五种范围与 416；范围字节与完整文件对应位置一致。官方 rclone 1.75.2 完成列表、完整下载与五个前后偏移，结果一致。命令沿用 `scripts/probe-real-dav.ts --path-file <临时路径文件>`，凭据由环境传入。

没有把受控字节、解码器识别或 rclone 读取当作普通播放器出声、系统挂载、FLAC/APE 真实可读或真实云端验收。

`bun run build:web` 通过；约 558 kB Schema 分块警告仍在。最终 ZIP **132,045 字节**，SHA-256 `6efc9ed3535dba42768af02d7407a928b717ea5dd3fb565eba82acba08e1ff82`。alpha.4 为本轮中间安装验证包；默认配置数组隔离修复后递增为 alpha.5，没有同版本覆盖不同摘要。
