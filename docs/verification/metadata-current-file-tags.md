## 方法

- 在 WSL 中使用当前已安装的 QQ alpha.10、网易云 alpha.8 插件及当前已授权会话，各重新读取一首此前已发布的 MP3；未改配置、布局或授权，未刷新目录或扫描账号。
- 重新授权已使旧快照的来源代际失效；本次仅复用其文件引用选择样本，由插件 `stat/open` 重新确认实际文件身份、读取完整音频并核对大小，不把旧快照当作当前有效目录的证据。
- 当前两插件均原样返回上游音频流，检查对象未经过 MusicFS 补标签处理。
- 使用已安装的 `ffprobe 8.0.1-3ubuntu2` 解析完整本地文件的格式标签、音频流标签及封面流，而非仅检查文件头。读取完整文件也覆盖文件尾部。
- QQ 的包装 `fetch` 观察到 3 次调用，网易云 2 次；该计数是本次注入接口的观察值，不扩展为所有 SDK 内部请求的审计结果。先前云端管理 GET 返回 403，未进入云端音频读取，随后使用本地实例；没有部署或新增云资源。
- 临时音频已删除；未安装新依赖。忽略目录中的安全摘要为 `.musicfs/cloud-acceptance/audio-tag-inspection-local.json`，不包含会话凭据、账号资料、文件引用、媒体地址或歌词正文。

## 对方案的影响

该结果支持按来源插件补足音乐资料，不支持建立所有来源必经的全局标签合并流程。现有文件协议仍可承载最终输出文件。
