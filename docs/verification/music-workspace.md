# 音乐库工作区与用户流程核对

2026-10-23，`0.1.0-dev.25`。现行设计见[共用管理界面](../architecture/web-ui.md)，本版归档入口见[发行页](../release.md)。下列浏览器与源码检查保留各自验证范围。

## 双侧栏整合

本轮仅调整音乐库呈现与交互，使用内置浏览器和现有独立演示服务。左侧主导航与来源树合并，中间浏览，右侧播放器目录按需展开；没有改变后台读取、来源配置或已保存目录。

| 用户路径 | 实际结果 |
|---|---|
| 桌面浏览 → 展开播放器目录 | 来源始终留在左栏，中间保持同一浏览器，右栏按需显示 |
| 调整右栏宽度 → 收起 → 再打开 | 实际指针调整成功，重新打开保留宽度 |
| 多选歌单 → 添加到… | 隐藏重复的整组添加按钮，目标沿用最近选择的播放器文件夹 |
| 合并左栏的来源项 / 歌单标题 → 目标文件夹 | 原生指针跨栏拖放成功，右栏底部出现保存和撤销；撤销与放弃恢复原布局 |
| 收起右栏 → 从内容列表发起改名 | 需要输入的播放器树自动展开并聚焦名称 |
| 设置页 → 返回音乐库 | 搜索、来源导航与播放器目录状态保留 |
| 主列表进入来源与嵌套歌单 | 修复两处缺少相同入口定位信息造成的节点身份差异，来源树自动展开并高亮当前目录 |
| 390px 来源抽屉 → 添加来源 | 来源导航先关闭，配置表单单独呈现 |
| 390px 播放器抽屉 → 新建改名 | 原位输入和固定底部保存操作可达；临时草稿已放弃 |

1440px 与390px视图没有页面横向溢出，主导航名称完整，控制台没有新增警告或错误。重构后的音乐库适配当前内置浏览器约622px窗口。走查没有保存临时目录变更。

本轮9项目录/导航回归通过、35个断言；三套类型、WebUI正式构建和模块边界通过，301模块、1267依赖无违规。复用 Ant Design Splitter、React Portal 和已有视图状态，没有新增依赖。

## 同版前阶段：接入与目录引用

使用内置浏览器和 WSL 独立 SQLite 演示服务：主工作区包含两个示例来源、三个内容入口、嵌套歌单和128个演示文件；另用临时空库走查首次接入。页面调用实际管理、认证和音乐库模块，来源数据与授权结果由本地演示插件提供。

| 用户路径 | 实际结果 |
|---|---|
| 空库添加来源 → 安装插件 | 安装后自动回到来源表单，无需再从插件列表点击添加 |
| 添加并登录 | 自动接续来源登录，演示账号显示登录完成与浏览入口 |
| 异步安装处理中 → 重载 | 使用本地202响应和持久操作查询模拟安装；重载后完成跟踪并自动打开来源表单，不调用 Cloudflare |
| 新建文件夹并改名 → 保存并连接 | 保存成功后进入连接页；返回仍在原来源目录，搜索内容保留 |
| 多选两张具体歌单 → 添加到文件夹 → 保存 | 两张歌单成为独立入口；原列表和勾选保持，打开新入口得到对应歌曲 |
| 单张歌单标题 → 拖入文件夹 | 使用真实指针拖放添加，保存后目录保留；未以脚本派发事件替代拖放 |
| 来源目录 → 连接页 → 返回 | 完整三层面包屑、搜索和播放器树展开保留 |
| 搜索 → 第二页 → 滚动 → 切页或重新进入 | 搜索、页码和列表滚动位置恢复；前进后退也回到原浏览状态 |
| 栏宽切换 / 导航抽屉关闭重开 | 树展开和筛选保留，已修复走查发现的重置问题 |
| 上下文设置 → 切换主页面 | 设置不会覆盖新页面；返回工作区仍可继续原上下文 |
| 保存的歌单入口 → 重载 | 仍能打开对应歌曲，不依赖未保存草稿 |

本轮界面未出现新的控制台警告或错误。首次接入截图见[来源表单](images/music-journey-onboarding.png)，单张歌单整理见[工作区](images/music-journey-playlists.png)。

### 底层与构建

- 六个相关测试文件共50项通过、436个断言：布局与导航、库视图、发布路径、管理接口。新增检查覆盖子目录直接引用、共享快照、仅访问所选目录、最终文件与 Range 合同；HTTP/DAV 链路包含保存引用后的读取与服务重启。
- 子目录发布路径同时包含原布局下的位置和独立歌单入口，不请求来源；整组入口继续使用 `sourceId` 定位插件当前根引用。
- 三套 TypeScript、正式 WebUI 构建、模块边界通过；301模块、1267依赖无违规。管理接口测试的回环监听在允许本地监听的执行环境中通过。
- 本轮复用已有 React Activity 与 lru-cache，没有新增依赖、插件协议版本或数据库迁移。
