# 音乐库分栏工作区核对

2026-10-23，`0.1.0-dev.25` 源码预览。浏览、添加和目录排列在同一个分栏工作区完成；现行设计见[共用管理界面](../architecture/web-ui.md)。已发布的 dev.24 归档保持原样。

## 内置浏览器

WSL 本地服务 `http://127.0.0.1:8787/`，独立 SQLite 演示数据包含两个明确标为示例的来源、入口与嵌套目录，以及128个演示文件。使用实际管理接口和库视图，不连接真实音乐平台或读取音频。

| 用户路径 | 结果 |
|---|---|
| 分隔线拖动 → 重载 | 实际改变来源/内容栏宽，重载后保留调整值 |
| 单入口标题、来源树 → 播放器文件夹 | 原生指针拖放添加成功，来源浏览位置保持 |
| 主列表多选两项 → 拖入目标 | 两项一次加入，一次撤销；原列表及勾选保持 |
| 多选 → 新建目标并改名 → 拖入 | 原位创建目标不清掉来源列表或勾选 |
| 布局入口 → 文件夹中部 | 移入文件夹；保存后打开该文件夹核实其直接子项 |
| 布局入口 → 上边缘 | 目录顺序立即改变，主列表同步，撤销恢复 |
| 来源内容与设置 | 128项清单、搜索与上下文设置继续共用原查询和表单 |
| 三栏 → 两栏 → 单栏 | 内容浏览器保持挂载，已有勾选和搜索保留 |
| 约390px窄屏 | 来源、播放器目录抽屉可用；目录栏可新建改名，再通过添加按钮放入内容；关闭后来源选择保持，无横向页面溢出 |

拖拽使用真实指针操作，未用脚本派发拖拽事件。分栏和目录拖拽分别验证；未将拖动分隔线当作拖拽内容的证据。目录移动由原生 Tree 的默认落点改为统一的“文件夹中部移入、边缘排序”，跨栏添加与布局移动复用同一拖拽模块。

列表高度随内容栏伸缩，各栏独立滚动，分页保持可达。拖拽和改名只展开必要父目录，不因显示移动结果去扫描该来源的歌曲。抽屉仍统一管理卸载；完成退出后检查后续操作，未出现新的控制台错误。已恢复正常窗口尺寸。
