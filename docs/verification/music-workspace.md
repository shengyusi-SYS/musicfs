# 音乐库统一工作区核对

2026-10-23，`0.1.0-dev.25` 源码预览。浏览与目录编辑使用同一棵树、同一个主列表；设计与模块分工见[共用管理界面](../architecture/web-ui.md)。已发布的 dev.24 归档保持原样。

## 内置浏览器

WSL 本地服务 `http://127.0.0.1:8787/`，使用独立 SQLite 演示数据：两个明确标为示例的来源、入口与嵌套目录，以及128个演示文件。使用实际管理接口和库视图，不连接真实音乐平台或读取音频。

| 用户路径 | 结果 |
|---|---|
| 来源树 → 喜欢的音乐 | 主区直接显示文件，歌曲不展开到树中 |
| 来源根目录多选 → 添加 | 原列表勾选两项，通过目标文件夹选择添加到草稿；取消添加保留勾选 |
| 未保存入口 → 浏览 → 改名 | 128个文件保持可见，标题随改名更新，无需先保存 |
| 新建文件夹 → 移动入口 | 原位改名后用节点菜单移动，面包屑随目录变化，歌曲继续可见 |
| 保存 → 重载 | 保持同一目录及其新位置，不返回根目录 |
| 新建、改名、连续撤销与重做 | 两次撤销回到原布局，保存恢复禁用；重做和放弃修改正常 |
| 来源/目录设置 | 同一侧栏提供来源设置、自动更新、文件命名；当前目录的范围正确 |
| 约390px窄屏 | 新建时打开同一棵树并进入改名；关闭抽屉后可连续撤销，无横向页面溢出 |

改名的 Enter 与失焦原先可能重复提交，现合并为一次结束操作。输入框聚焦事件不再冒泡到尚在挂载的树；窄屏新建、改名、关闭和连续撤销重走后没有新增控制台错误。树抽屉仍由 Drawer 管理卸载。临时视口已恢复，预览停留在正常工作区。

## 离线与构建

- `library.test.ts`、`layout-draft.test.ts`、`music-workspace.test.ts` 共32项通过，259个断言。
- 新增回归覆盖自动目录身份稳定、草稿分组无需目录请求、嵌套内容在改名和移动后仍按同一来源引用定位、来源与别名共享快照而分别生成面包屑、缺失入口不会误读账号根目录。
- 三套 TypeScript、正式 WebUI 构建与模块边界检查通过；299模块、1260依赖无违规。

本轮验证集中在目录草稿、来源查询与实际页面操作，没有重复平台、Windows虚拟机、Cloudflare或压力测试。
