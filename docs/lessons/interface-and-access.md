# MusicFS：交互、访问入口与国际化经验

只记录 MusicFS 已有依据的设计方法和教训。现行能力分别见[工作区](../architecture/web-ui.md)、[管理访问](../architecture/management-access.md)、[远程运行](../headless.md)和[国际化](../architecture/i18n.md)；版本、截图与验证范围归[验收台账](../verification.md)。

## 工作区围绕完整任务组织

- **入口合并不改变领域身份。** 来源与播放器目录可以同屏，但浏览来源不以先导出为前提，移除目录入口也不等于删除来源。草稿依赖稳定节点身份，来源子目录保留插件引用；读取、导航和失效同时识别该引用。
- **按任务衔接步骤。** 安装后继续添加来源，保存成功后再连接；只让已经成功的操作推进下一步，失败保留草稿与当前上下文。整理面板按需展开，发起编辑时显露输入位置，操作结果与保存入口一起呈现。能直接完成的任务不增加跳页、重复确认或长说明。
- **呈现位置不转移状态所有权。** Portal、分栏、抽屉负责布局，工作区负责选择、草稿和历史。来源树与列表共享快照和定位身份，各观察者生成自己的导航上下文；别把某个别名路径写入共用查询结果。页面保留复用成熟机制，隐藏页面停止订阅，有界视图缓存不另存一份音乐库。
- **展开、选择、编辑结束分别处理。** 展开树不应切换内容；切换页签或语言不应清空输入；拖动和改名只展开必要父目录。Enter 与失焦结束同一次编辑时只提交一次。浮层退出动画、焦点恢复与卸载由同一方协调，避免外层提前卸载后仍收到迟到事件。

## 独立入口沿整条消费链路兑现

- **分开设置不止分开开关。** 管理与读取的表单、凭据、端口、范围、路由和监听生命周期都要按各自职责核对。表单只提交自身字段，迁移优先保留播放器地址，自动分配地址也需考虑正常重启后的复用。
- **地址来自实际入口，并保留用户选择。** 管理二维码与播放器导入是不同任务；复制、二维码及重新打开窗口沿用同一所选地址，显示前更新本机连接信息，不为此请求音乐平台。本机挂载保存“读取本机”的意图，启动恢复时取得当前内部连接；远程挂载保留用户填写的地址。
- **远程页面要说清操作对象。** 浏览器所在设备、运行服务的机器和挂载目标可能不同。无桌面启动应交付实际地址、可用登录入口和重新获取方式，复用现有会话机制；服务托管与桌面自启各有启动所有者，自动挂载在监听就绪后后台恢复。代理发布端口不能按后台监听端口机械改写。
- **独立访问的证据来自真实连接。** 请求头不能证明本机身份；使用自定义 Host 的测试还应核对客户端实际连接目标。回环请求通过不能升级为局域网通过，模拟挂载恢复不能升级为目标系统已挂盘。环境排查继续遵守用户明确的宿主边界。

## 国际化只改变显示

- **显示语言有作用域。** 浏览器偏好归当前客户端，终端和托盘语言归运行机器；插件拥有自己的显示资料。翻译引擎放在显示边界，核心只传稳定错误语义和可选显示描述。插件命名空间优先处理自身文案，不能覆盖共用界面词典。
- **文字与数据按语义区分。** Schema 的标题和说明可翻译，默认值、枚举值、字段名、歌曲、用户名称和导出路径保持原样。不能对 JSON 中所有字符串递归翻译，也不能因一个字符串是中文就认定它是界面文案。语言不进入授权、快照或文件缓存身份。
- **动态消息保留可重渲染的信息。** 使用整句键与插值值，数量、日期、校验复用成熟库，不拼接片段。状态和错误保存后仍可能换语言，显示时再求值；模块级标签与 memoized 表单也要随语言更新。旧静态消息可用已知词典映射，未声明的第三方诊断保留原文。
- **独立实例也要隔离资源。** 共享词典定义可以复用，可变资源存储应独立，避免一个实例注册插件翻译后污染其他语言实例。切换语言只更新视图，不以重建整个应用代替订阅更新。
- **接入成熟库仍需核对外围。** 应用文案、组件库、表单控件、校验、日期和原生菜单分别接线。词典检查能发现键或插值遗漏，不能证明动态文案覆盖和英文布局可用；用一次含未保存输入、切换、重开、未登录入口和插件表单的有界旅程补齐。自动化工具遮蔽输入值时，以可见界面证据核实，不能把脱敏结果当成状态丢失。
- **独立交付物也要带齐新资源。** 仓库构建成功不证明插件作者包可用；新增词典等导入文件必须进入独立源码包，并用包自身的最小依赖完成构建。源码验证、生成开发产物与正式发行归档分别陈述，文档整理不重建历史发行物。
