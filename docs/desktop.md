# MusicFS 桌面后台与挂载

MusicFS 在本机运行后台，用浏览器提供管理页面；挂载、音乐来源和目录由同一个后台管理。日常操作见[使用指南](user-guide.md)，模块关系见[桌面挂载架构](architecture/desktop-mounts.md)。

## 打开、常驻和退出

解压完整发行目录后，Windows 打开 `MusicFS.exe`，Linux 运行 `musicfs`。默认打开管理页面并直接进入。关闭网页后，后台和挂载继续运行；再次启动程序会打开已有后台。

没有桌面或通过 SSH 启动时，终端改为显示地址、登录链接及远程访问方法，不尝试打开浏览器。NAS、SSH 转发和服务托管见[远程运行](headless.md)。

Windows 双击托盘图标打开管理页面，单击不打开。右键菜单提供「打开管理页面」「手机访问」「退出 MusicFS」。页面也可退出后台；文件仍被占用时会保留后台并显示原因，关闭使用文件的程序后再试。

「设置 → 启动与挂载」可分别调整：

| 设置 | 默认行为 |
|---|---|
| 登录系统后启动 MusicFS | 开启 |
| 手动启动时打开管理页面 | 开启 |
| 登录系统自启时打开管理页面 | 关闭，静默驻留托盘 |
| 启动时恢复自动挂载 | 开启 |
| 挂载暂时失败后自动重试 | 开启 |

每次从新发行目录启动时，自启入口会更新到当前程序位置。Linux 托盘需要桌面环境提供 StatusNotifier 支持。Windows/Linux 原生辅助程序已构建；macOS 的相同入口已实现并完成构建检查，Apple SDK 链接及实机运行仍待完成。

## 管理账号和手机访问

本机启动直接进入管理页面，账号密码可按需在「设置 → 登录账号」创建。以后也可使用用户名和密码登录，勾选「记住登录」使用 30 天会话；「退出登录」结束当前浏览器会话，后台、挂载和音乐来源授权继续保留。

手机先连接同一网络，在「设置 → 管理页面访问」选择「局域网设备」并保存，再点击页面或托盘的「手机访问」扫码。多网卡时可切换地址。二维码使用一次后需要重新获取；手机登录会话独立于电脑。也可以直接打开管理地址，用已设置的账号密码登录。

管理端口在「设置 → 管理页面访问」设置，WebDAV 的端口与访问设备在「连接与挂载 → WebDAV 播放器」设置，保存后立即生效。只让播放器连接时，仅开放 WebDAV 即可；管理页面和管理 API 仍限本机访问。新安装两项默认仅本机，端口填0自动选择并尽量在重启时复用。修改管理端口不影响播放；修改 WebDAV 端口后，播放器需要更新连接地址，正在传输的响应继续完成。

从共享端口的旧版升级时，原端口优先保留给 WebDAV，访问范围沿用旧设置；管理页面用 MusicFS 启动器重新打开。

管理账号、播放器的 WebDAV 读取凭据、网易云或 QQ 等来源登录分别设置。管理认证的实现见[管理访问架构](architecture/management-access.md)。

在「连接与挂载 → WebDAV 播放器」可修改用户名和密码，保存后立即生效并在重启后保留。手机播放器可点「扫码导入」，选择局域网地址；二维码明文包含读取凭据。已有播放器需更新新凭据，App 的本机挂载使用独立内部连接。

## 挂载到电脑

在「连接与挂载 → 磁盘挂载」添加当前 MusicFS，或填写其他 HTTP/HTTPS WebDAV 的地址和读取凭据。页面显示实际挂载的设备名称和系统。挂载发生在运行后台的电脑：浏览器打开 WSL 后台时，挂载也在 WSL；需要 Windows 盘符时运行 Windows 发行程序。

| 系统 | 挂载位置与依赖 |
|---|---|
| Windows | 空闲盘符，如 `M:`；留空可自动分配。需要 WinFsp，页面提供随包官方安装器入口 |
| Linux | 空目录；需要 `/dev/fuse`、`fusermount3` 或 `fusermount` 及对应权限 |
| macOS | 使用系统 NFS 挂载工具与权限；当前目标系统运行范围见[验收台账](verification.md) |

默认名称为 MusicFS，添加时可填写自己的名称。已有挂载可在更多菜单中「重命名」；已挂载时保存会正常重新挂载，保留缓存。

添加后默认在下次启动恢复，每个挂载项都有独立的自动挂载开关：

- 「卸载」只停止本次，保留定义、缓存和下次自动挂载设置。
- 「重新挂载」复用保存的地址、凭据和缓存设置。
- 「移除挂载」正常卸载后删除定义和所属缓存。

网络尚未就绪时，后台最多尝试 3 次，管理页面和托盘照常可用。缺少系统组件、磁盘已满或挂载被占用时，列表显示原因，处理后可手动重新挂载。全局恢复和后台重试均可在设置关闭。

挂载完成后即可交给播放器扫描、播放，或复制文件到本地。WinFsp 安装按需请求系统权限，MusicFS 后台继续以普通用户运行。

## 目录与读取缓存

本机挂载的目录清单默认保留一年，远程 WebDAV 挂载默认一个月；可在缓存设置选择一个月、一年、长期保留或自定义。本机目录内容有变化时主动更新挂载清单，内容未变则保留缓存；远程目录也可点击「刷新挂载目录」。

已读音频使用按需片段缓存。挂载缓存与直接连接本机 WebDAV 的共享读取缓存分别管理，容量和保留时间均可设置。卸载保留片段，移除挂载清理所属片段；活动挂载修改或清理缓存时会正常重新挂载。具体机制见[缓存策略](architecture/cache-policy.md)和[共享读取](architecture/shared-read-cache.md)。

两类音频缓存默认保留一年，每挂载8GiB、共享16GiB的容量上限不变。旧默认期限在升级后迁移一次，其他设置保留；挂载采用新参数需重挂。网易云与QQ的稳定音乐资料也默认保留一年，更新随包插件后生效。

## Windows 资源管理器原生映射

App 挂载与资源管理器的「映射网络驱动器」是两条入口。原生映射使用 Windows WebClient，在「连接与挂载 → WebDAV 播放器 → Windows 资源管理器原生映射」启用本机 HTTPS，再点击完成连接设置，将显示的 HTTPS 地址和读取凭据填入资源管理器。

连接设置会请求一次系统权限，信任本数据目录的自签名证书、启动 WebClient，并按需将原生 WebDAV 的单文件上限提高到 4GiB−1。上限修改影响这台电脑的原生 WebDAV 连接，应用时会重连正在运行的 WebClient；App 管理的 rclone/WinFsp 挂载不受此参数限制。

「恢复原文件上限」恢复 MusicFS 修改前的值，证书和 HTTPS 入口保持可用。退出 MusicFS 或停用 HTTPS 会保留这项系统设置。本机 HTTPS 地址只供运行后台的电脑使用，局域网播放器使用局域网地址。[Microsoft WebDAV 说明](https://learn.microsoft.com/en-us/iis/publish/using-webdav/using-the-webdav-redirector)

## 数据、构建与验证范围

用户数据由 `env-paths` 选择当前用户目录，包含音乐 SQLite、独立 `auth.sqlite`、插件修订、连接凭据、挂载和启动设置。Windows 使用当前用户目录 ACL；Unix 数据目录为 `0700`，私有配置为 `0600`。rclone 以隐藏窗口运行，日志位于数据目录的 `mounts/rclone.log`；启动问题查看 `startup.log`、`launcher.log`。

原生辅助程序负责托盘、当前用户自启和 Windows 系统浏览器入口，后台仍是 Bun。源码、依赖和各目标工具链见[辅助程序 README](../native/desktop/README.md)，应用构建、独立测试数据及窄测试入口见[开发指南](development.md)。

本轮管理认证已通过 Bun SQLite 和本地 workerd/D1；监听切换、后台恢复和原生桥接使用离线夹具验证。构建结果与目标系统实机验收分别记录；免费 Worker 的真实 CPU 限额尚未实测。既有 Windows/Linux 挂载和客户端结果见[桌面记录](verification/p2-desktop-host.md)、[Windows 记录](verification/p2-windows-mount.md)和[总台账](verification.md)。
